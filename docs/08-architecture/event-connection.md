# 会場ネットワークと接続方式（event-connection.md）

- 文書ID: ARCH-EVENT-CONN
- バージョン: 0.1
- 状態: 草案（会場側への事前確認と実機検証が必要）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（REQ-OPS-02、REQ-NET-01、REQ-SHR-01、NFR-08）
- 関連Issue: #66（本書）、#41、#65、#42〜#47

## 1. 概要

オープンキャンパス当日の会場ネットワークの条件を整理し、親機・参加者PC・スマートフォンをどうつなぐかを決める。あわせて、アプリの配信方法と、QRコードの種類を定める。

## 2. 前提（所有者より確認済み。2026-10-04）

| 項目 | 内容 |
|---|---|
| 親機PC | デスクトップ。1台。LAN とは別のインターネット回線をつなぐことは、現状難しい |
| 参加者PC | 参加者1組（2人）につきデスクトップPC1台。有線LANで親機とつながる |
| キーボード | 各PCに1つ。会場のキーボードは100%（テンキー付き）で、キー数が多い |
| 会場の有線LAN | **インターネットに出られない。** LAN内のWebSocket通信は遮断されていない |
| 会場のWi-Fi | 参加者には提供しない。会場のWi-Fiにつなぐことは、運用上の規則で不可 |
| Wi-Fiルーター | こちらで用意することは、可能と思われる（会場側への事前確認が必要） |
| スマートフォン | 保護者のスマホ。LANに入れない。使えるのは自分のモバイル回線のみ |
| スマホ参加 | 重要（所有者の回答） |

## 3. 要求との関係

| 要求 | 本書での扱い |
|---|---|
| REQ-OPS-02（親機による進行管理、MVP） | 親機のローカルサーバーが、会場LAN内で完結して担当する |
| REQ-NET-01（スマホ参加、目標） | インターネットなしの自前Wi-Fiルーターで実現する（§5） |
| REQ-NET-02（リアルタイム対戦、目標） | 会場LAN内のローカルサーバー経由。クラウドは使わない |
| REQ-SHR-01（持ち帰り、目標） | GitHub Pages の固定URLで実現する。当日の通信とは独立（§6） |
| NFR-01（安定性） | 外部のインターネットに依存しない構成にする |

## 4. 候補の比較

| 案 | 内容 | 判定 | 理由 |
|---|---|---|---|
| クラウドの通信サーバー（Cloudflare Workers など） | PC・スマホがクラウドに接続する | **不可** | 参加者PCがインターネットに出られない |
| 親機PCを Cloudflare Tunnel で公開 | 親機をインターネットに出し、URLで接続する | **不可** | 親機にインターネット回線がない。LAN内のPCにも使えない |
| **親機PCのローカルサーバー（会場LAN内）** | 親機が、アプリの配信・進行管理・ルームの中継を行う | **採用** | LAN 内で完結する。外部に依存しない。`oc26-stage` の親機サーバーと同じ考え方 |
| **自前のWi-Fiルーター（インターネットなし）をLANにつなぐ** | スマホがこのWi-Fiにつなぎ、親機のサーバーにアクセスする | **採用（目標機能）** | スマホがLANに入れる唯一の方法 |
| WebRTC、Bluetooth、QRとカメラの受け渡し | スマホとPCを直接つなぐ | **不可** | 共通のネットワークかインターネットがないと経路が作れない。iPhone の Safari は Web Bluetooth に非対応 |
| スマホ参加なし（キーボード共有のみ） | 1台のキーボードを2人で使う | **採用（MVPの基本）** | 追加の設営なしで成立する。ルーターが使えない場合の代替にもなる |

## 5. 採用する構成

### 5.1 全体図

```text
 [親機PC（デスクトップ）]  ← ローカルサーバー（アプリ配信 + 進行管理 + WebSocket + 管理画面）
        │
   有線LAN（インターネットなし）
        │
        ├── [参加者PC × N]   http://親機のアドレス:ポート を開く
        │
        └── [Wi-Fiルーター（インターネットなし）]
                 │
              [保護者のスマホ]   このWi-Fiにつなぎ、LANのアドレスを開く
```

- 親機のサーバーが、アプリの配信（静的ファイル）、進行管理、ルームの中継を1つのプログラムで担う。
- 参加者PCは、親機が配信するアプリを開く。**GitHub Pages は当日は使わない。** 事前にビルドしたアプリを、親機PCに置いておく。
- スマホは、自分のモバイル回線ではなく、自前のWi-Fiルーターにつなぐ。インターネットにはつながらないため、LANのアドレスだけが開ける。

### 5.2 QRコードは3種類

| QR | 中身 | 用途 | 読み取る人 |
|---|---|---|---|
| ① Wi-Fi接続用 | Wi-Fi名とパスワード（`WIFI:S:…;T:WPA;P:…;;` の形式） | スマホを自前のWi-Fiにつなぐ | 保護者（スマホ） |
| ② ルーム参加用 | 親機のLANアドレスと、ルーム情報（`http://親機のアドレス:ポート/…`） | 当日の対戦に参加する | 保護者（スマホ） |
| ③ 持ち帰り用 | GitHub Pages の固定URLと、ステージ・設定（REQ-SHR-01） | 帰宅後に設定を復元して遊ぶ | 参加者・保護者 |

- **②と③は別のQRにする。** ②はLANのアドレスで、当日にスマホがWi-Fiにつないだ状態でしか開けない。③はインターネット上のURLで、帰宅後に開く。HTTPS の Pages のページから、`http://` の親機へ接続することはできない（混在コンテンツ）ため、1つにまとめられない。
- 以前に決めた「同じQRを持ち帰りにも使う」は、この制約により取り下げる。画面で①②と③を並べて、使う場面を説明する。
- ①と②の順序は、スマホをつなぐ手間を減らすため、画面の案内を①→②の順にする。

### 5.3 PC側の対戦（MVP）

- 1組（2人）が、1台のPCとキーボードを共有してローカル対戦する。
- 100%キーボードの左側を1P、右側（矢印キー・テンキー側）を2Pに割り当てる（キー配置は #15 で決める）。
- 同時押しが多いと、キーボードによっては入力が落ちる（ゴースト入力）。キー配置は、実機のキーボードで確認する（§7）。

### 5.4 スマホ参加（目標機能）

- 参加者のPCで対戦ルームを作り、②のQRを表示する。保護者がスマホで読み取って参加する（REQ-NET-01）。
- 保護者のスマホは、仮想コントローラー（#48）で操作する。
- 同期の方式（入力同期か状態同期か）は #43 で決める。LAN内の通信なので、遅延は小さい見込み。

## 6. 持ち帰り用QR（REQ-SHR-01）との関係

- ③の持ち帰り用QRは、PC上でオフラインのまま生成する（QRの生成はブラウザ内で完結する）。
- 保護者・参加者が帰宅後、自分のスマホやPCのモバイル回線・家庭の回線で、GitHub Pages を開く。会場のネットワークは使わない。
- 学校ロゴを、持ち帰り用QRの発行時に表示する（許可の範囲: オープンキャンパスでの使用。[legacy-assessment.md](./legacy-assessment.md) §3.17）。

## 7. リスクと事前確認

| 項目 | 内容 | 確認方法 | 確認する Issue |
|---|---|---|---|
| 会場側の許可 | 自前のWi-Fiルーターを持ち込んでよいか。会場のWi-Fiではなく、閉じたネットワークである点を説明する | 会場側への事前確認 | #7 |
| スマホの挙動 | インターネットに接続できないWi-Fiにつないだとき、iPhone は警告を出す。Android は、機種によって携帯回線に切り替わることがある | iOS Safari / Android Chrome の実機 | #51、#69 |
| クライアント分離 | ルーターが、端末どうしの通信を遮断していないこと（「AP isolation」「クライアント分離」をオフにする） | ルーター設定の確認 | #69 |
| 親機のアドレス | 親機のアドレスが変わると、QRが無効になる。固定のアドレスにするか、起動時に自動で検出してQRに反映する | 設営手順の確認 | #67、#69 |
| 親機のファイアウォール | 親機OSのファイアウォールが、参加者PCやスマホからの接続を遮断しないこと | 親機で設定を確認 | #67 |
| 親機の処理の限界 | 参加者PCの台数分の接続とルーム中継を、60 FPS の対戦を妨げずに処理できること | 台数を想定した負荷確認 | #51 |
| 非セキュアな接続 | HTTP のページでは、一部のブラウザ機能（Service Worker、クリップボードなど）が使えない | 使う機能を事前に確認 | #17 |
| キーボードの同時押し | 2人が同時に多くのキーを押したとき、入力が落ちないこと | 会場と同じ種類のキーボードで確認 | #15、#21 |
| アプリの配置 | 事前にビルドしたアプリを、親機PCへコピーする手順 | リハーサルで確認 | #52 |

## 8. 縮退動作

| 障害 | 動作 |
|---|---|
| 親機PCが停止・再起動 | 参加者PCは、開いているアプリをそのまま使い続けられる（進行管理だけが止まる）。再起動後に再接続する |
| Wi-Fiルーターの故障、またはスマホが接続できない | スマホ参加をやめ、1台のキーボードを共有するローカル対戦にする |
| 親機とPCの接続が切れた | 直前の状態で体験を続ける。進行の指示はスタッフが口頭で案内する |
| 持ち帰りQRを読み取れない | 参加者がスクリーンショットを撮る、またはスタッフが案内する |
