# 会場ネットワークと接続方式（event-connection.md）

- 文書ID: ARCH-EVENT-CONN
- バージョン: 0.2
- 状態: 草案
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（REQ-OPS-02、REQ-NET-01、REQ-SHR-01、NFR-08）
- 関連Issue: #66（本書）、#41、#65、#67、#68

## 1. 概要

オープンキャンパス当日の会場ネットワークの条件を整理し、親機と参加者PCをどうつなぐか、アプリをどう配信するかを決める。**スマートフォンでの参加は、イベント終了後（持ち帰ったあと）のみとし、当日の会場では行わない。**

## 2. 前提（所有者より確認済み。2026-10-04）

| 項目 | 内容 |
|---|---|
| 親機PC | デスクトップ。1台。LAN とは別のインターネット回線をつなぐことは、現状難しい |
| 参加者PC | 参加者1組（2人）につきデスクトップPC1台。有線LANで親機とつながる |
| キーボード | 各PCに1つ。会場のキーボードは100%（テンキー付き）で、キー数が多い |
| 会場の有線LAN | **インターネットに出られない。** LAN内のWebSocket通信は遮断されていない |
| 会場のWi-Fi | 参加者には提供しない。会場のWi-Fiにつなぐことは、運用上の規則で不可 |
| スマートフォン | **当日は使わない。** 参加できるのは、イベント終了後に持ち帰ったあとのみ（所有者の決定） |

## 3. 要求との関係

| 要求 | 本書での扱い |
|---|---|
| REQ-OPS-02（親機による進行管理、MVP） | 親機のローカルサーバーが、会場LAN内で完結して担当する |
| REQ-NET-01（スマホ参加、目標） | 当日の会場では行わない。持ち帰りのあとに、スマホで参加する（方式は §7 の未確定事項） |
| REQ-SHR-01（持ち帰り、目標） | GitHub Pages の固定URLで実現する。当日の通信とは独立 |

## 4. 候補の比較

| 案 | 内容 | 判定 | 理由 |
|---|---|---|---|
| クラウドの通信サーバー（当日） | PCがクラウドに接続する | **不可** | 参加者PCがインターネットに出られない |
| 親機PCを Cloudflare Tunnel で公開 | 親機をインターネットに出し、URLで接続する | **不可** | 親機にインターネット回線がない |
| **親機PCのローカルサーバー（会場LAN内）** | 親機が、アプリの配信と進行管理を行う | **採用** | LAN 内で完結する。外部に依存しない。`oc26-stage` の親機サーバーと同じ考え方 |
| 自前のWi-Fiルーターで、当日にスマホ参加 | インターネットなしのWi-Fiをつなぎ、スマホから親機に接続する | **不採用** | 当日のスマホ参加を行わないことにしたため、不要 |
| **1台のキーボードを2人で共有するローカル対戦** | 同じPCで2人が対戦する | **採用（当日の参加方法）** | 追加の設営が不要で、安定している |

## 5. 採用する構成

### 5.1 全体図

```text
 [親機PC（デスクトップ）]  ← ローカルサーバー（アプリ配信 + 進行管理 + WebSocket + 管理画面）
        │
   有線LAN（インターネットなし）
        │
        └── [参加者PC × N]   http://親機のアドレス:ポート を開く
                              1台のPCを、2人がキーボードを共有して使う
```

- 親機のサーバーが、アプリの配信（静的ファイル）と進行管理を1つのプログラムで担う。
- 参加者PCは、親機が配信するアプリを開く。**GitHub Pages は当日は使わない。** 事前にビルドしたアプリを、親機PCに置いておく。
- 当日、無線ネットワークは用意しない。

### 5.2 当日の対戦（MVP）

- 1組（2人）が、1台のPCとキーボードを共有してローカル対戦する。
- 100%キーボードの左側を1P、右側（矢印キー・テンキー側）を2Pに割り当てる案とする（キー配置は #15 で決める）。
- 同時押しが多いと、キーボードによっては入力が落ちる（ゴースト入力）。キー配置は、実機のキーボードで確認する（§6）。

### 5.3 QRコード

- 当日に使うQRは、**持ち帰り用QR（GitHub Pages の固定URLと設定）だけ**。
- 持ち帰り用QRは、PC上でオフラインのまま生成する（QRの生成はブラウザ内で完結する）。
- 保護者・参加者が帰宅後、自分のスマホやPCで、家庭の回線またはモバイル回線から GitHub Pages を開く。会場のネットワークは使わない。
- 学校ロゴを、持ち帰り用QRの発行時に表示する（許可の範囲: オープンキャンパスでの使用。[legacy-assessment.md](./legacy-assessment.md) §3.17）。

### 5.4 持ち帰りのあとのスマホ参加

- スマホでの参加は、持ち帰りのあとにのみ行う。会場のネットワークは関係しない。
- 参加の方式（スマホ単体で遊ぶか、PCとスマホで通信して対戦するか）は、通信に使うバックエンドの要否に影響する。**未確定**（§7）。

## 6. リスクと事前確認

| 項目 | 内容 | 確認方法 | 確認する Issue |
|---|---|---|---|
| 親機のアドレス | 親機のアドレスが変わると、参加者PCが開けない。固定のアドレスにするか、起動時に表示して案内する | 設営手順の確認 | #67 |
| 親機のファイアウォール | 親機OSのファイアウォールが、参加者PCからの接続を遮断しないこと | 親機で設定を確認 | #67 |
| 親機の処理の限界 | 参加者PCの台数分の接続を、60 FPS の対戦を妨げずに処理できること | 台数を想定した負荷確認 | #51 |
| 非セキュアな接続 | HTTP のページでは、一部のブラウザ機能（Service Worker、クリップボードなど）が使えない | 使う機能を事前に確認 | #17 |
| キーボードの同時押し | 2人が同時に多くのキーを押したとき、入力が落ちないこと | 会場と同じ種類のキーボードで確認 | #15、#21 |
| アプリの配置 | 事前にビルドしたアプリを、親機PCへコピーする手順 | リハーサルで確認 | #52 |

## 7. 縮退動作

| 障害 | 動作 |
|---|---|
| 親機PCが停止・再起動 | 参加者PCは、開いているアプリをそのまま使い続けられる（進行管理だけが止まる）。再起動後に再接続する |
| 親機とPCの接続が切れた | 直前の状態で体験を続ける。進行の指示はスタッフが口頭で案内する |
| 持ち帰りQRを読み取れない | 参加者がスクリーンショットを撮る、またはスタッフが案内する |
