# バックエンド（リアルタイム通信）の選定（backend.md）

- 文書ID: ARCH-BACKEND
- バージョン: 0.1
- 状態: 草案
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§8 NFR-08、§9）
- 関連: [event-connection.md](./event-connection.md)（会場ネットワークと接続方式）、[frontend.md](./frontend.md) §8、[event-control.md](../01-experience/event-control.md)
- 関連Issue: #41（本書）、#66、#67、#68

## 1. 概要

静的ホスティングと分離した、WebSocket のバックエンド（リアルタイム通信）のホスティング候補を比較した。**結論は「リアルタイム通信のバックエンドは持たない」。** 通信対戦（REQ-NET-02）が 2026-10-04 に取り下げられ、当日の通信は会場LAN内の親機のローカルサーバーだけになったため、クラウドの通信サーバーは不要である。

## 2. 前提

- 会場の有線LANは、インターネットに出られない。会場のWi-Fiは使えない。親機にもインターネット回線がない（event-connection.md §2）。
- 当日の対戦は、1台のPCで、2人がキーボードを共有して行う。PC どうしの通信対戦は行わない（REQ-NET-02 取り下げ）。
- 持ち帰りは、GitHub Pages の固定URLと、URLに埋め込んだ設定で行う。保存する情報がないので、サーバー側のデータは持たない（NFR-08、data-model.md）。

- **当日の通信の方式:** 進行管理は、参加者PCが親機へ **HTTP の GET を定期的に送って**進行状態を取得する方式（既定 1 秒間隔。event-control.md §8.2）に統一する。WebSocket は使わない。

## 3. 要求との関係

| 要求 | 本書での扱い |
|---|---|
| REQ-NET-02（通信対戦） | 取り下げ。リアルタイム通信のバックエンドは作らない |
| NFR-08（外部資源に依存しない配信） | 当日は親機のローカルサーバー、持ち帰り後は GitHub Pages。外部のバックエンドに依存しない |
| NFR-01（当日の安定動作） | 外部のサービスの障害・回線の状態に左右されない構成にする |

## 4. 候補の比較

| 案 | 費用 | 当日の安定性 | 会場ネットワークの制約 | 運用の手間 | 判定 |
|---|---|---|---|---|---|
| クラウドの WebSocket サーバー（PaaS、Cloudflare Workers + Durable Objects など） | 無料枠〜小額。会期だけなら小さい | サービスと回線に依存。会場に回線がなければ動かない | **不可**: 参加者PCがインターネットに出られない | アカウント・デプロイ・監視が必要 | **不採用** |
| 親機PCを公開（Cloudflare Tunnel など） | 無料〜小額 | 回線と外部サービスに依存 | **不可**: 親機にインターネット回線がない | 設定・認証・公開範囲の管理が必要 | **不採用** |
| 自前のWi-Fiルーターと親機で、スマホから接続 | 機材の費用 | 無線の混雑・設定に左右される | 会場のWi-Fiは使えず、自前の構成が必要 | 設営・検証が重い | **不採用**（当日のスマホ参加を行わないため） |
| **親機PCのローカルサーバー（会場LAN内）** | ほぼなし（既存のPC） | LAN 内で完結。外部に依存しない | **適合**: 有線LANのみ。インターネット不要 | 親機でサーバーを起動し、アドレスを案内する（#67） | **採用**（進行管理のみ。通信対戦の同期はしない） |
| GitHub Pages のみ（バックエンドなし） | 無料 | 静的配信なので高い | 持ち帰り後の家庭・モバイル回線で動く | デプロイは GitHub Actions で自動 | **採用**（持ち帰り用） |
| 当日も GitHub Pages だけ | 無料 | 会場からインターネットに出られず不可 | **不可** | — | 不採用 |

## 5. 採用する構成

| 場面 | 配信・通信 | リアルタイム通信 |
|---|---|---|
| 当日（会場） | 親機PCのローカルサーバーが、アプリを配信。進行状態を、参加者PCが定期的に取得 | 対戦のためのリアルタイム通信はしない（1台で2人が遊ぶ） |
| 持ち帰り後 | GitHub Pages（静的ホスティング） | なし。スマホ単体で簡易CPUと遊ぶ（REQ-CPU-01） |

- **参加者に、ネットワーク設定を要求しない。** 参加者PCは、親機のアドレスをブラウザで開くだけでよい。持ち帰り後は、QR の URL を開くだけでよい。
- 親機のサーバーが、参加者のデータ（名前・設定・ステージ・結果）を受け取らない・保存しない（event-control.md §8）。
- 将来、通信対戦の要求が戻った場合は、frontend.md §8.1 の「入力ソースの差し替え口」を使い、本書に候補の再比較を追記する（会場に回線がない制約が変わらない限り、クラウド型は使えない）。その場合も、親機のローカルサーバーに WebSocket を載せる案を、先に検討する。
