## 1. 概要

イベントで作った**ファイターの設定とステージ**を、参加者が家庭に持ち帰り、GitHub Pages で復元して遊べるようにする。持ち帰りの手段は、**URL を QR コードにしたもの**と、**URL の文字**の2つ。この文書は、URL に入れる情報、URL の組み立て、データ量の上限、復元のしかた、失敗したときの扱いを定める。

通信対戦（REQ-NET-02）は取り下げ済みなので、**ルームの情報は含めない**。会期後もバックエンドは動かさない（[backend.md](../08-architecture/backend.md)）。

## 5. 持ち帰りURLの組み立て

```text
https://m0o9l0v3.github.io/oc-battle-sim/#t1.<ペイロード>
└────────────── 公開URL ───────────────┘└┬┘└ Base64URL ┘
                                   フラグメント
```

- **公開URLは、`location` から組み立てない。** 当日の画面は親機のローカルサーバー（`http://192.168.…`）から配信されるため、`location` から作ると、家庭で開けない URL ができる。公開URLは、ソースの定数（`src/share/config.ts` の `PUBLIC_APP_URL`）として持ち、ビルド時の環境変数（`VITE_PUBLIC_URL`）で上書きできる。既定は上の GitHub Pages の URL。
- **データは、フラグメント（`#`）に置く。** クエリ（`?`）には置かない。フラグメントはブラウザからサーバーへ送られないため、名前などが、サーバーのアクセスログや、リファラに残らない。
- `t1` は「持ち帰り（take-home）の形式のバージョン 1」を表す識別子。バージョンが違えば、別の復号を使う（§6.4）。
- 起動時の `?reset`（個別リセット。frontend.md §10）とは、役割が別。持ち帰りURLは `?` を使わない。

## 6. ペイロードの形式（バージョン 1）

### 6.1 ビットの並び

先頭から順に、ビットをつめる（上位ビットから）。末尾の端数のビットは 0 で埋める。**文字や値の区切り記号は使わない**（固定の長さと、長さの欄だけで読む）。

| 順 | 欄 | ビット数 | 内容 |
|---|---|---|---|
| 1 | 予備 | 4 | 0（将来の拡張用。0 以外は失敗） |
| 2 | 能力値（4つ） | 3 × 4 = 12 | `attackPower`、`defense`、`jumpPower`、`speed` の順。各 **値 − 2**（0〜6） |
| 3 | 外観 | 2 + 3 + 3 + 3 = 11 | `body`（b1〜b4 → 0〜3）、`face`（f1〜f6 → 0〜5）、`color`（c1〜c8 → 0〜7）、`accessory`（なし → 0、a1〜a6 → 1〜6） |
| 4 | ファイター名の長さ | 5 | UTF-8 のバイト数（0〜30） |
| 5 | ファイター名 | 8 × 長さ | UTF-8 のバイト列 |
| 6 | ステージの `cells` | 336 | 14 行 × 24 列。row 0 の col 0 から行の順に、1 = ブロック |
| 7 | ステージの `spawns` | 18 | p1 の col（5）・row（4）、p2 の col（5）・row（4） |
| 8 | ステージ名の長さ | 5 | UTF-8 のバイト数（0〜30） |
| 9 | ステージ名 | 8 × 長さ | UTF-8 のバイト列 |
| 10 | チェックサム | 16 | 1〜9 の全バイト（端数の 0 を含む）の **CRC-16/CCITT-FALSE** |

- 能力値の「値 − 2」は、能力値の範囲（2〜8。stat-system.md）に合わせたもの。
- 外観の ID の並び（b1〜b4 など）は、character-design.md §5.1.1 の一覧に従う。**一覧が増減したら、`t1` の復号は使えなくなる**ので、版（`t2`）を上げる（§6.4）。
- 名前は、NFC に正規化・前後の空白を除去・制御文字を除去したあとの文字列（character-config.md §5.5）。
- ステージ名が未入力のとき、長さは 0（復元後に、既定名を付ける）。
- 全体を Base64URL（パディングなし）の文字列にして、`#t1.` のあとに置く。

### 6.2 長さ（最悪の場合）

| 項目 | ビット数 |
|---|---|
| 予備 | 4 |
| 能力値 + 外観 | 12 + 11 = 23 |
| ファイター名（長さ 5 + 最大 30 バイト） | 5 + 240 = 245 |
| `cells` + `spawns` | 336 + 18 = 354 |
| ステージ名（長さ 5 + 最大 30 バイト） | 5 + 240 = 245 |
| チェックサム | 16 |
| **合計（最悪）** | **887 ビット → 端数を詰めて 111 バイト** |

> 4 + 23 + 245 + 354 + 245 + 16 = 887 ビット。バイトにそろえると 111 バイト（888 ビット）。

- Base64URL にすると **148 文字**（111 バイト = 37 組 × 3 バイト → 37 × 4 = 148）。
- 名前が短ければ、短くなる。ステージの `cells` は、どんなステージでも 336 ビットで同じ（RLE は使わない。stage-format.md §9）。
- 名前を最悪（30 バイト）にしても、全体の長さは **148 文字を超えない**。

### 6.3 往復と検証

- 符号化 `encodeTakeHome(character, stage) → string`、復号 `decodeTakeHome(payload) → { ok: true, character, stage } | { ok: false, reason }`。**復号は例外を投げない**（character-config.md §5.4、stage-format.md §10）。
- 復号の手順: ① バージョン識別子（`t1.`）、② Base64URL として正しいか、③ 長さが読める範囲か（欄の途中で切れていないか、余りのビットが 0 か）、④ チェックサム、⑤ 値の範囲（能力値 2〜8、外観の ID の範囲、ステージ名・ファイター名が UTF-8 として正しい）、⑥ **検証**（`validateConfig` の読み込みの検証と、`validateStage` を通す。character-config.md §5.1、validation.md）。
- 一つでも失敗したら、全体を失敗とする（**部分的な復元はしない**。能力値の合計が崩れるため）。
- 往復（符号化 → 復号）で、元の `CharacterConfig`・`StageData` と一致する。テストで確かめる（test-plan.md §5.1 `share`）。

### 6.4 バージョンの扱い

| 状況 | 扱い |
|---|---|
| `t1` | 復号する |
| 知らない識別子（`t2` 以降、または `t` で始まらない） | 失敗（`UNKNOWN_VERSION`）。「あたらしい バージョンの QR だよ」と案内する |
| 将来 `t2` を足したとき | 古い `t1` の復号は残す（過去に配った QR を、会期後も開けるように） |

## 7. QRとして読み取れる長さ

- 持ち帰りURLは、小文字を含むため、QR の**バイトモード**で符号化する。
- 最悪の長さ: 公開URL 41 文字 + `#t1.` 4 文字 + ペイロード 148 文字 = **193 バイト**。
- QR の誤り訂正レベルは **M**（約 15 % の復元）を使う。バイトモードの容量は、バージョン 9 が 180 バイト、**バージョン 10 が 213 バイト**。193 バイトは、**バージョン 10（57 × 57 モジュール）に収まる**（余裕 20 バイト）。
- 公開URLが長くなる（独自ドメインなど）場合の上限: 公開URL + 4 + 148 ≦ **213**（つまり公開URLは 61 文字以内）。超える場合は、誤り訂正を L にする（バージョン 9 で 230 バイト）か、名前の上限を見直す。**ビルド時に、最悪のケースの長さを検査して、213 を超えたら失敗させる**（#61 で実装）。
- 表示の大きさ: 余白（クワイエットゾーン）4 モジュールを含めて 65 モジュール。画面で読み取るので、**1 モジュールを 5 ピクセル以上**にする（QR の一辺は 325 ピクセル以上）。1280 × 720 の S12 で、QR の領域に 360 × 360 ピクセルを確保する（#61、ui-design.md §9）。
- スマホで読み取れるかは、実機で確認する（#61。test-plan.md §5.4 T10）。

| 文書 | 確認した制約 |

## 9. 復元（URL を開いたとき）

### 9.1 起動時の処理

1. 起動時に、`location.hash` が `#t` で始まるか調べる。始まらなければ、通常の起動（S01 から）。
2. `decodeTakeHome` を呼ぶ。
3. 成功: 復元した設定を、持ち帰りの入口の画面（§9.2）に渡す。**入口の画面で復元したデータは、`localStorage` に保存**（GitHub Pages のオリジンの `ocbs.session`。data-model.md §6）して、**URL からフラグメントを取り除く**（`history.replaceState`）。更新（F5）で、復元したデータが戻る。同じ QR は、いつでも開き直せる。
4. 失敗: `IMPORT_FAILED` を表示し（§9.4）、フラグメントは**取り除かない**（URL を直して開き直せるように）。

### 9.2 家庭のPC（持ち帰りの入口）

- 復元できたら、**入口の画面**（S01 の前に置く。画面番号は #61 で付ける）に、復元した 1P の名前・能力値・外観と、ステージの形を表示する。
- 選べる操作:
  - **「ふたりで あそぶ」**: 1P を復元した設定、2P を標準の設定（2P 用の外観）にして、復元したステージで、1台のキーボードを共有するローカル対戦（S06 の キー確認 → 対戦）へ進む。設定は、あとで S03 で変えられる。
  - **「CPUと あそぶ」**: 簡易CPU（REQ-CPU-01、#71・#72）が実装されたら有効にする。それまでは、表示しない。
  - **「はじめから つくる」**: 復元したデータを使わず、S01 から始める。
- 家庭では、親機がない（`HostLink` は何もしない実装。frontend.md §8）。フェーズ・一斉リセット・再戦の受付停止は、働かない。

### 9.3 スマホで開いたとき（MVP）

- スマホ単体のプレイ（REQ-NET-01）は目標機能のため、MVP では遊べない。
- 画面幅が狭い、または操作が主にタッチ（`(pointer: coarse)`）のとき、「スマートフォンでは まだ あそべません。パソコンで ひらいてね」と案内し、**復元した 1P の名前と能力値を表示**する（user-flow.md §5.13）。
- スマホからPCへ、**同じ URL を送れる**よう、「URLを コピー」のボタンを置く。コピーは、ユーザーが押したときだけ行う（Clipboard API が使えない環境では、URL の文字を選択できる状態で見せる）。
- スマホで復元に失敗したときも、同じ画面で失敗を伝える（§9.4）。
- スマホ単体プレイを実装したら、この案内を遊べる画面に置き換える（#48）。

### 9.4 失敗したとき

失敗したことを、**理由と次の操作とともに**画面で伝える（character-config.md §5.4）。復元できたように見せない。標準の設定で続けることもできる。

| 原因 | 表示 | 次の操作 |
|---|---|---|
| `UNKNOWN_VERSION` | 「あたらしい バージョンの QR だよ。アプリを こうしんしてから ひらいてね」 | ページを再読み込み、または標準で始める |
| `TOO_SHORT`・`BAD_ENCODING`・`BAD_CHECKSUM`（切れた・書き換えられた） | 「もちかえった せっていを よみこめなかったよ。QRを もういちど よみとってね」（`IMPORT_FAILED`） | QR を読み取り直す、URL を開き直す |
| `OUT_OF_RANGE`・`INVALID_CONFIG`・`INVALID_STAGE`（値や検証の失敗） | 同上 | 同上 |

- どの場合も、「このまま ひょうじゅんの ファイターで あそぶ」のボタンで、標準の設定から始められる。
- 復号の関数は、標準の設定にしない（呼び出し側が判断する）。
- 設定の一部だけを使うことはしない。

### 9.5 会期後（親機がない）

- 会期後は、バックエンドも親機もない。**エラーを出さず**、静的なページとして動く。通信を必要とする画面はない（フェーズの取得を行わない）。
- 復元に必要なのは、URL のデータだけ。会場のネットワークには、一切つながない。

## 10. 個人情報の扱い

- ファイター名・ステージ名は、URL に入る。**個人情報（本名・学校名・連絡先など）を入れない**よう、名前の入力画面（S02・S04 のエディタ）に注意書きを出す（character-config.md §4。実装済み）。
- S12 の QR の近くにも、「なまえは QRに はいるよ。ほんとうの なまえは いれないでね」と表示する（#61）。
- URL のフラグメントは、サーバーに送られない（§5）。ただし、QR や URL の画像・文字を、人に見せたり、SNS に載せたりすると、名前が見える。この旨を、S12 の注意書きに含める。
- データに、参加者の識別子（`sessionId`、端末の ID、時刻）を入れない。
- 親機は、QR のデータを受け取らない・保存しない（event-control.md §8）。QR の生成は、参加者PC上で完結する。

## 11. 学校ロゴの表示

- 学校ロゴは、持ち帰り用QRの**発行のとき（S12）**に、QR の**横**に表示する（user-flow.md §5.13、legacy-assessment.md §3.17）。
- **QR の中央にロゴを重ねない**（誤り訂正の余裕を、読み取りのために残す）。
- 使用の許可は、**オープンキャンパスでの使用**に限られる。そのため、ロゴは**会場で動かすとき（親機のローカルサーバーから配信されるとき。親機があるとき）だけ**表示する。GitHub Pages（会期後）では表示しない。
- ロゴの画像ファイルと、使用許可の記録は、#50（権利チェック）で確認する。許可が確認できるまで、ロゴは表示しない（QR の機能は、ロゴなしで動く）。

## 12. 家庭で遊べる範囲

| できる | できない |
|---|---|
| PC 1台のキーボードを2人で共有するローカル2人対戦 | 通信対戦（オンライン対戦）。ネットワークをまたいだ対戦は行わない |
| 簡易CPUとの対戦（REQ-CPU-01。実装後。PC・スマホ） | 戦の記録（Battle Report の履歴）の引き継ぎ |
| 復元した設定を、S03・S04 で変えて遊ぶ | 親機による進行管理（会場だけ） |
| ステージの編集 | |
| スマホ: 復元した設定の表示と、PC への URL の受け渡し（MVP） | スマホでの対戦（MVP では不可。目標機能） |

## 13. 実装への指示（#61 ほか）

| 項目 | 内容 |
|---|---|
| モジュール | `src/share/`（core）: `encodeTakeHome`、`decodeTakeHome`、`PUBLIC_APP_URL`、`buildTakeHomeUrl`。DOM・`location` に依存しない（URL の組み立ては、引数で受け取る） |
| QR 生成 | 外部への通信をしない。`qrcodegen`（MIT。ライセンス表記を整理して取り込む。legacy-assessment.md §3.9）を使い、参加者PC上で Canvas に描く |
| 起動時 | `location.hash` の判定は adapter 層（`session/boot`）で行い、core に文字列だけを渡す |
| テスト | 往復（最悪値を含む）、固定の長さ（ステージが全ブロック・交互・空でも `cells` の長さが同じ）、不正入力（切れた・1ビット変えた・知らない版・範囲外・検証を通らない）で例外を投げず `ok: false`、最悪ケースの URL が 213 バイト以内 |
| ビルドの検査 | 最悪の長さが 213 バイトを超えたら、ビルドまたはテストを失敗させる |

## 14. 例外・制約

| 場面 | 扱い |
|---|---|
| 外観の ID の一覧が増減した | 版を上げる（`t2`）。`t1` の復号は残す |
| ステージの寸法・値の種類が変わった | 版を上げる |
| ブラウザが `history.replaceState` を使えない | フラグメントは残す（機能は維持。更新すると、もう一度復元する） |
| `localStorage` が使えない | 復元はできる（メモリ上）。更新すると、URL から復元し直す（フラグメントを残す） |
| 公開URLが変わる（リポジトリ名の変更など） | 以前に配った QR は開けなくなる。URL を変える場合は、旧URLにリダイレクトを置く |
