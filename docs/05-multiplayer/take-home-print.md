# 持ち帰りカードの印刷（take-home-print.md）

- 文書ID: MPL-PRINT
- バージョン: 0.1
- 状態: 草案
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（REQ-SHR-01）
- 関連: [take-home-share.md](./take-home-share.md)、[event-control.md](../01-experience/event-control.md) §11、[event-host.md](../01-experience/event-host.md) §5.4、[legacy-assessment.md](../08-architecture/legacy-assessment.md) §3.16
- 参考: `oc26-stage` の Issue #5（段階A〜C・送信フィードバックUI）

## 1. 概要

S12 の持ち帰り用QR（[take-home-share.md](./take-home-share.md)）を、**紙のカード**にして持ち帰れるようにする。プリンタは親機PC（Windows）にだけつながっているため、参加者PCは親機へ**印刷の依頼**を送り、親機PCの**印刷ステーション**が順番に印刷する。依頼が受け付けられたら、参加者PCは**待機の画面**になり、操作できなくなる。カードは、整理番号の順に、スタッフが手渡す。

## 2. 目的

- スマホを持っていない参加者も、作ったファイターとステージを持ち帰れる。
- 20 台から同時に依頼が来ても、1 枚ずつ、受け付けた順に印刷する。
- 参加者が、依頼できたかどうか・次に何をすればよいか（待つ）を、画面で分かる。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-SHR-01 | 持ち帰り用QRで設定を復元（必須・MVP） | QR をカードに印刷する（§8）。カードの QR は、画面の QR と同じ持ち帰りURL |
| NFR-01 | 安定性を最優先する | 依頼の失敗はエラー画面にせず、もういちど押せる（§7.4）。親機の再起動で、参加者PCをリセットしない |
| NFR-08 | 外部の資源に依存しない | QR は親機で作る。外部への通信をしない。追加のパッケージを入れない |

## 4. 全体の流れ

```text
参加者PC（S12）                     親機サーバー（server/）                    印刷ステーション（親機PCの Chrome）
 「カードを いんさつする」
  POST /api/print/job {url} ─────→  検証 → 整理番号を付けて、印刷待ちへ
                            ←────── 200 {number}
  「おくれたよ！」→ 待機の画面                                     ←── POST /api/print/claim（1.5 秒ごと）
                                     いちばん古い印刷待ちを「印刷中」に ──→ {id, number}
                                                                        GET /print-station/sheet?id=…（iframe）
                                                                        print()（--kiosk-printing なら確認なし）
                                                                    ←── POST /api/print/done {id}
```

- `oc26-stage` は、依頼のたびに親機で既定のブラウザを起動していた（`rundll32`）。本プロジェクトでは、**親機PCで開いておいた 1 つのページ（印刷ステーション）が、印刷待ちを順に取り出す**方式にした。OS のコマンドに依存せず、印刷が 1 件ずつ順番に進み、印刷待ちの件数や刷り直しを画面で扱えるため。
- 「受け付けた」（200）は、**親機が印刷待ちに入れたこと**を表す。紙が出たこと・紙詰まりがないことまでは、参加者PCに伝えない（スタッフが、印刷ステーションとプリンタを目で確認する）。

## 5. データ（親機のメモリだけ）

| 項目 | 内容 |
|---|---|
| 持ち帰りURL | 参加者PCが送ったもの。**公開URL（`--public-url`、なければ環境変数 `VITE_PUBLIC_URL`、なければアプリの既定）と一致し、フラグメントが `decodeTakeHome` で復号できるものだけ**受け付ける（任意の URL の QR を刷らせない） |
| ファイター名・ステージ名 | 受け付けたURLを復号して取り出す（参加者PCが送った文字列は、そのまま使わない）。カードに印刷する |
| 整理番号 | 受け付けた順に 1 から。**親機サーバーの起動のときだけ 1 に戻る**（一斉リセットでは戻さない。1 日を通して重ならない） |
| 状態 | 印刷待ち → 印刷中 → 済み。印刷中のまま 60 秒過ぎたら（印刷ステーションを閉じた・更新した）、印刷待ちへ戻す |

- **ファイルに保存しない。ログに出さない**（ログは「印刷を受け付けました: 整理番号 N」だけ）。親機を止めると消える。
- 済みのものは、刷り直しのために**直近 20 件**だけ残し、それより古いものは捨てる。
- 印刷待ち（＋印刷中）は **60 件まで**。超えたら断る（503）。いたずらで紙を使い切らないため。
- 印刷ステーションの一覧には、整理番号・状態・時刻だけを出す（名前・URL は出さない）。

## 6. API（親機サーバー）

| 経路 | 方法 | 接続元 | 内容 |
|---|---|---|---|
| `/api/print/job` | POST | どこからでも（参加者PC） | 本文 `{ "url": "<持ち帰りURL>" }`（1KB まで）。成功: `200 { number }`。持ち帰りの操作（`share`）が許されないフェーズ: `409`。検証に通らない: `400`。印刷待ちが上限: `503` |
| `/print-station` | GET | 親機PCのみ + トークン（`?token=`） | 印刷ステーションの画面 |
| `/print-station/sheet?id=…` | GET | 親機PCのみ + トークン | 1 枚分の印刷シート（§8） |
| `/print-station/station.js` | GET | 親機PCのみ + トークン | 印刷ステーションの手順（`server/print-station.js`） |
| `/api/print/status` | GET | 親機PCのみ + トークン（Bearer） | 印刷待ち・印刷中の件数、次の整理番号、一覧、ロゴの有無 |
| `/api/print/claim` | POST | 親機PCのみ + トークン | いちばん古い印刷待ちを取り出す。`{ job: { id, number } \| null }` |
| `/api/print/done` | POST | 親機PCのみ + トークン | `{ id }` を済みにする。印刷待ちへ戻っていたものも済みにする（確認の画面を長く開いていたとき、二重に刷らない） |
| `/api/print/reprint` | POST | 親機PCのみ + トークン | 済みの `{ id }` を、同じ整理番号のまま、列の先頭へ戻す |

- 印刷ステーションの認証は、管理画面と同じ（親機PC自身から、起動時のトークン。[event-control.md](../01-experience/event-control.md) §7.4）。
- 依頼の中身は正しいのに公開URLだけが違うときは、親機とアプリのビルドの設定の食い違いとして、**1 回だけ**ログに出す（`#` より前だけ。名前は出さない）。

## 7. 参加者PC（S12）

### 7.1 印刷のボタン

- S12 の QR の説明の下に、「カードを いんさつする」を置く。
- **親機とつながっているときだけ**出す（`HostContext.live` がある）。親機がない（GitHub Pages）・通信できない状態が続いたときは、出さない。
- 持ち帰りの操作（`share`）が止まっているフェーズでは、押せず、理由を出す（[event-control.md](../01-experience/event-control.md) §12）。

### 7.2 状態

| 状態 | 表示 | 操作 |
|---|---|---|
| 送る前 | 「カードを いんさつする」 | 押せる |
| 送信中 | ボタンの中に回る印と「おくっています…」 | 押せない（連打しても 1 回だけ送る）。「つぎの ひとへ（スタッフ）」も出さない（リセットすると、だれも受け取らないカードが刷られる） |
| 送れた | 「おくれたよ！」を 1 秒 | 押せない。「つぎの ひとへ（スタッフ）」も出さない |
| 待機 | §7.3 | なし |
| 送れなかった | 「うまく おくれなかったよ。もういちど おしてね」 | もういちど押せる（待たせない） |

- 送れたら、**すぐに**整理番号をセッション（`SessionData.printNumber`）へ入れて保存する（編集中の値のように待たない）。更新（F5）しても、待機の画面のまま（もう一度は依頼させない）。
- 送信の手順は `src/ui/printRequest.ts`（DOM なしでテストする）。

### 7.3 待機の画面

- S12 の中身を、次だけにする: チェックの印、「いんさつの リクエストが かんりょうしたよ」、「カードが できるまで、すわって まっていてね。スタッフが とどけるよ」、整理番号。
- **ボタンを置かない**（QR・URL・「つぎの ひとへ」も出さない）。S12 からは、ほかの画面へ進めない（「もちかえる」は S12 では出ない）ため、参加者PCでは何も操作できない。
- 待機が解けるのは、**一斉リセット**（`sessionId` が変わる）か、**個別リセット**（`?reset` のブックマーク）のときだけ。
- 見出しに焦点を移し、画面が変わったことを読み上げでも分かるようにする。

### 7.4 送れなかったとき

- 通信の失敗・時間切れ（5 秒）・断られた（409・400・503）は、どれも「送れなかった」として扱う。例外を投げず、技術的な内容は出さない。
- 何度でも押し直せる。

## 8. 印刷シート（A4 縦 1 枚）

- 参考: `oc26-stage` の印刷テンプレート（ロゴのヘッダー、「QRコード」の見出し、大きな QR、URL）。
- 上から: **学校ロゴ**（幅 82mm）、線、「QRコード」、**QR（92mm 四方）**、ファイター名・ステージ名、説明、「QRが よめないときは…」と URL、いちばん下に注意書き（「QRや アドレスを ひとに みせると、なまえが みえるよ」）。右上に**整理番号**の枠。
- `@page { size: A4 portrait; margin: 0 }`。余白を 0 にして、ブラウザが日時・URL のヘッダーとフッターを付けないようにする（余白は本文で取る）。
- QR は親機で作り（`src/share/qr.ts`、誤り訂正 M）、SVG で埋め込む。ロゴは `server/assets/school-logo.jpg` を data URI で埋め込む（1 つの HTML で完結）。ロゴが見つからないときは、ロゴなしで印刷し、印刷ステーションに警告を出す。
- ロゴの使用は、学校から許可を得ている（リポジトリに含めてよい。2026-10-10 所有者確認）。参加者PCの画面・GitHub Pages には出さない（印刷シートだけ）。

## 9. 印刷ステーション（親機PC）

- 起動時に表示される URL（`http://localhost:8080/print-station?token=…`）を、**`--kiosk-printing` を付けた Chrome（または Edge）**で開いておく。管理画面にもリンクがある。
- 1.5 秒ごとに印刷待ちを確かめ、1 件ずつ取り出して、画面の外に置いた iframe に印刷シートを読み込み、`print()` する。**印刷の終わりは `afterprint` で待つ**（`print()` がすぐに戻るブラウザでも、次の 1 枚で上書きしない。来ないときは 2 分で印刷できたとみなす）。1 枚ごとに 1.5 秒あける。手順は `server/print-station.js`（テストあり）。
- 印刷シートを読めない・`print()` が失敗したときは、**済みにしない**。自動印刷を止め、「整理番号 N を印刷できませんでした」と出す。取り出したものは 60 秒で印刷待ちへ戻り、「再開する」で、もう一度印刷する。
- `--kiosk-printing` が効いていれば、確認なしで**既定のプリンタ**へ印刷される。効いていないと確認の画面が出る（「印刷」を押せば続く）。
- 「一時停止／再開する」（用紙の補充など）、「もういちど印刷」（紙詰まりなど。同じ整理番号で先頭へ）。
- 起動の例（Windows）。Chrome をすべて閉じてから実行する（`--user-data-dir` で、ふだんの Chrome と分ける）:

```bat
"C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk-printing --user-data-dir=C:\ocbs-print "http://localhost:8080/print-station?token=…"
```

## 10. 例外・制約

| 場面 | 扱い |
|---|---|
| 親機が止まっている・通信できない | 印刷のボタンを出さない（つながっていた後に止まった場合は、送れなかった扱い） |
| 親機を再起動した | 印刷待ちは消える（メモリだけ）。整理番号は 1 から。待機中の参加者PCは、待機のまま（スタッフが、印刷ステーションの一覧と照らして対応する） |
| 紙詰まり・用紙切れ | 参加者PCには伝えない。スタッフが「一時停止」→ 直す →「もういちど印刷」 |
| 印刷ステーションを閉じた・更新した | 印刷中のものは 60 秒で印刷待ちへ戻り、開き直すと続きから印刷する |
| 確認の画面を 60 秒以上開いたまま | 印刷待ちへ戻るが、閉じたあとの済みの報告で済みになる（二重に刷らない） |
