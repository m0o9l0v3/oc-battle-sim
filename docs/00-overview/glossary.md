# 用語集（glossary.md）

- 文書ID: OVW-GLOSSARY
- バージョン: 0.1
- 状態: 草案
- 上位文書: [system-overview.md](./system-overview.md)

## 1. 概要

本プロジェクトで使う用語を、**参加者に見せる表記**と**実装・仕様書で使う名前**に分けて定義する。画面の文言、コード、仕様書で言葉が食い違わないための基準とする。

## 2. 目的

- 中学生に分かる言葉を、画面表示の基準として固定する（NFR-02）。
- 仕様書とコードで使う識別子を一つに統一する。
- 未確定の用語は、どの仕様書で決めるかを明示する（上位文書 §12 の未確定事項と対応）。

## 3. 表記のルール

| 対象 | 言語 | 例 |
|---|---|---|
| 画面に表示する文言 | 日本語（中学生に分かる表現） | こうげき力 |
| 識別子（変数名、型名、ファイル名） | 英語 | `attackPower` |
| 仕様書・コミット・PR | 日本語。識別子は英語のまま書く | `attackPower` を設定する |

- 画面文言は、コードに直接書かず、設定にまとめる（`oc26-stage` の方針を踏襲。[legacy-assessment.md](../08-architecture/legacy-assessment.md) §3.11）。
- 「スマブラ」は企画上の呼称であり、画面・成果物には使わない（NFR-07）。画面では「対戦」「ファイター」などの一般的な言葉を使う。

## 4. 能力値

system-overview.md §5.1 に基づく。**各能力値は一つの現象にだけ影響させる**（設計原則 2）。

| 識別子 | 画面表示（暫定） | 意味 | 影響する現象 |
|---|---|---|---|
| `attackPower` | こうげき力 | 1回の攻撃で与えるダメージの大きさ | 与えるダメージ |
| `defense` | ふっとばされにくさ | 攻撃を受けたときの、吹き飛ばされにくさ | 吹き飛ばされる量 |
| `jumpPower` | ジャンプ力 | ジャンプで上がる高さ | ジャンプ高度 |
| `speed` | いどうのはやさ | 横方向に動く速さ | 横方向の移動速度 |

- 画面表示は暫定。#27（能力値設定画面）で、参加者向けの最終文言を確定する。
- `defense` は「防御力」という言葉から「ダメージが減る」と誤解されやすい。画面では「ふっとばされにくさ」を使い、ダメージ軽減とは説明しない。

## 5. ポイント制

| 用語 | 定義 | 値 |
|---|---|---|
| ポイント制 | 4つの能力値に、決められた合計ポイントを配分する方式 | — |
| 最小値 / 最大値 | 1つの能力値に配分できる範囲 | 2 / 8 |
| 合計ポイント | 4つの能力値の合計。**対戦開始には全て使い切る** | 20 |
| 標準設定 | 初期状態の配分 | Attack 5 / Defense 5 / Jump 5 / Speed 5 |

- 能力値の追加のペナルティはMVPでは設けない。トレードオフは合計ポイントだけで表す。

## 7. 対戦

| 用語 | 定義 | 決める文書 |
|---|---|---|
| 対戦 | 1対1の2D対戦。「第1戦」「第2戦」と数える | #12 |
| 基本攻撃 | 全員に共通の攻撃方式。MVPでは固有技を持たない | #11 |
| ダメージ蓄積 | 攻撃を受けるたびに増える値。多いほど吹き飛ばされやすい | #11 |
| 吹き飛ばし | 攻撃を受けて飛ばされる動き。量はダメージ蓄積と `defense` で決まる | #11 |
| 場外 | ステージの外側の領域。出ると撃墜される | #12, #13 |
| 撃墜 | 場外に出て倒されること | #12 |
| ストック | 撃墜されても残る機会（残機）。数は未確定 | #12 |
| リスポーン | 撃墜後にステージへ戻ること | #12 |
| 復帰 | 吹き飛ばされた後、ステージに戻ること | #12 |
| 再戦 | 能力値を変更して行う、第2戦以降の対戦。何度でも行える | #6 |
| 対戦相手（2P） | 参加者（1P）の対戦相手。標準設定で始まり、能力値を後から変更できる | #6 |

数値（ストック数、試合時間、ダメージ式など）は、#11 と #12 で定める。本書では決めない。

## 10. 持ち帰り・スマートフォン

| 用語 | 定義 | 決める文書 |
|---|---|---|
| 保護者 | 当日は、参加者と1台のPCのキーボードを共有して対戦する。持ち帰りのあと、スマートフォン単体で遊べる（REQ-NET-01） | #7 |
| 簡易CPU | スマホ単体・PC単体のときの対戦相手。基本的な移動・攻撃・回避・復帰をする。プレイヤーと同じ入力・物理・能力値のルールで動き、特別な能力を持たない（REQ-CPU-01） | #71 |
| 仮想コントローラー | スマートフォンの画面上に表示する操作ボタン。横持ちを基本候補とする。持ち帰り後のスマホ単体プレイで使う | #48 |
| 持ち帰り用QRコード | イベント終了後も、設定を復元して家庭で遊べるようにするQRコード（REQ-SHR-01）。GitHub Pagesの固定URLを指す。当日の会場で使うQRは、これのみ | #60 |

## 11. 体験の流れ

| 用語 | 定義 |
|---|---|
| Design → Test → Evaluate → Improve | 体験の中心となる学習サイクル。設定する→対戦する→評価する→変更する、を繰り返す |
| 親機 | 進行を管理するスタッフ用のPC。再戦の受付停止・終了指示・リセットなどを行う（REQ-OPS-02、MVP）。管理項目は #65、接続方式は #66 で決める | #65、#66 |
| 操作確認・テスト | 対戦の前に、自分のファイターとステージを一人で試すこと |
| スタッフ・学生ヘルパー | オープンキャンパス当日の案内と進行を補助する人 |
