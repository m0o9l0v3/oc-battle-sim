## 1. 概要

持ち帰りのあと、**スマートフォン単体で遊ぶ**ための操作を定義する。対戦相手は**簡易CPU**（REQ-CPU-01、#71・#72）で、通信対戦・ルームへの参加の画面はない（event-connection.md §5.4）。

画面は**横持ち**にし、画面の上に**1人用の仮想コントローラー**（左右・ジャンプ・攻撃）を重ねる。左手の親指で左右、右手の親指でジャンプ・攻撃を押す。

## 2. 目的

- 持ち帰った自分のファイターを、スマホだけで、すぐ動かせる。
- PC のキーボード版と、**同じ能力値・同じルール**で動く（入力の形だけが違う）。
- 2本の親指で、移動とジャンプ・攻撃を、**同時に**押せる。
- ブラウザの動作（ズーム、スクロール、文字の選択、長押しのメニュー）で、操作を邪魔されない。

## 4. 画面の流れ

### 4.1 スマホで持ち帰りURLを開いたとき

```text
持ち帰りURL（QR）を スマホで開く
  ↓
持ち帰りの入口（復元したファイター・ステージの表示）
  ├─ 「スマホで あそぶ」 → スマホの対戦画面（§5）
  └─ アドレスを コピー（パソコンで続けるため。従来どおり）
```

- スマホの判定は、`(pointer: coarse), (max-width: 767px)` に合うかどうか（[TakeHomeEntry](../../src/ui/TakeHomeEntry.tsx) の `isMobileEnvironment`。従来どおり）。
- スマホでは、ファイターの作り直し（S02〜S04）と、Report・比較（S08、S11）は行わない。**持ち帰った設定のまま遊ぶ**。作り直しはパソコンで行う（案内する）。
- 対戦画面の「もどる」で、持ち帰りの入口に戻る。

### 4.2 対戦相手

| 段階 | 相手 | ルール |
|---|---|---|
| 簡易CPU の実装まで（#72 の前。終了） | 動かないダミー（S05 の試し動かしと同じ。`DUMMY_INPUT`、標準の能力値） | 試し動かしのルール（`PRACTICE_RULES`。決着なし） |
| **簡易CPU の実装後（#72。現在）** | **簡易CPU**（`CpuSource`。強さは「ふつう」、能力値は標準。プレイヤーと同じ入力の形・物理・能力値の規則。[cpu-opponent.md](../03-combat/cpu-opponent.md)） | 対戦のルール（`DEFAULT_MATCH_RULES`） |

- 相手の入力は、`InputSource` を差し替えるだけで変わる（frontend.md §5.3）。仮想コントローラー側の変更は、不要。
- 勝敗が決まったら、結果（「きみの かち！」など）と「もういちど」を、画面の中央に出す。「もういちど」で、同じ設定のまま、次の試合を始める（CPU の動きは、試合ごとに変わる）。
- 映す範囲は、ステージと、まわりの少し（左右 2 セル、上 3 セル、下 3 セル。横長の画面では、左右の場外も映る）。

## 5. 仮想コントローラーの配置

### 5.1 配置（横持ち）

```text
 ┌────────────────────────────────────────────────────────────┐
 │ [もどる]                                     ダメージ 12%    │
 │                                                            │
 │                     （対戦の画面。全面）                      │
 │                                                            │
 │                                                  ( ジャンプ )│
 │  [  ◀  ][  ▶  ]                           ( こうげき )       │
 └────────────────────────────────────────────────────────────┘
    左手の親指                                   右手の親指
```

| 操作 | 位置 | 見た目の大きさ（CSS px） | 種類 |
|---|---|---|---|
| 左へ移動（◀） | 左下 | 76 × 76 | 押している間 |
| 右へ移動（▶） | 左下（◀ の右に、すき間なく並べる） | 76 × 76 | 押している間 |
| 攻撃 | 右下 | 直径 84（いちばん大きい） | 押した瞬間 |
| ジャンプ | 右下（攻撃の右上） | 直径 72 | 押した瞬間 |

- **大きさの下限は 56 px**（ui-design.md の `--min-target`。指の幅。Apple の推奨 44 pt、Android の推奨 48 dp より大きい）。画面の高さが 360 px の機種でも、上の大きさで収まる。
- ◀ と ▶ は、**すき間なく並べる**。親指を左右に**すべらせると**、そのまま向きが変わる（指を離して、押し直さなくてよい）。すき間に指が落ちて「何も押していない」ことを防ぐ。
- ジャンプと攻撃も、すべらせて押しかえられる（§6.2）。
- 画面の端から、少し離す（`env(safe-area-inset-*)` と、16 px の余白）。iPhone のホームバー、角の丸み、画面の端のジェスチャー（戻る）と重ならないようにする。
- ボタンは、半透明（対戦の画面が透けて見える）。押している間は、色を濃くし、中の記号・ことばを少し小さく見せる（押したことが分かる）。**ボタンの枠そのものは縮めない**（指の下のボタンを決める範囲が、押している間に変わると、端を押した指のわずかな揺れで、離す・押すが繰り返されるため）。
- 文字だけでなく、**記号**（◀ ▶）と、**ことば**（ジャンプ、こうげき）を、ボタンに書く（ui-design.md：色だけに頼らない）。
- 対戦の画面は、仮想コントローラーの**下に全面**で表示する。ステージは、画面の中央に収まるように縮小する（fitCamera。左右の余白に、ボタンが重なる）。

### 5.2 横持ちへの誘導

- **縦持ちのとき**は、対戦の画面の代わりに、「よこに してね」の案内（スマホを回す絵と、ことば）を、全面に出す。対戦は、**止める**（ループを動かさない。押しているボタンは、すべて離した扱い）。
- 案内の間も、**「もどる」は、案内の上に出し、押せる**ようにする。全画面になったが、回転の固定が効かない（端末の回転ロックなど）とき、ブラウザの操作が隠れていても、ここから出られる。
- 横にすると、案内が消え、対戦を始める（または、続ける）。
- 向きの判定は、CSS の `(orientation: portrait)`（縦の長さ > 横の長さ）で行う。端末の回転ロックが、オンでも、オフでも、判定は同じ。
- Android Chrome では、「スマホで あそぶ」を押したときに、**全画面**（`requestFullscreen`）と**横向きの固定**（`screen.orientation.lock('landscape')`）を、試みる。使えない、または、断られたときは、何もしない（案内だけで進める）。iOS Safari（iPhone）は、どちらも使えないため、案内だけ。

### 5.3 その他の画面要素

| 要素 | 位置 | 内容 |
|---|---|---|
| もどる | 左上 | 持ち帰りの入口へ戻る。56 px 以上 |
| 対戦の状態 | 右上 | 残り時間と、両者（きみ・CPU）のダメージ（%）・のこりのストック |
| 案内 | 最初の数秒、中央の下 | 「◀ ▶ で うごく。ジャンプ と こうげき を おしてね」 |

## 6. 入力の規則

### 6.1 入力の形

- 仮想コントローラーは、**入力の抽象化レイヤ**（pc-ui.md §5）の、1つの入力ソース（`VirtualPadInput`。`src/input/virtualPad.ts`）として実装する。出力は、キーボードと同じ `PlayerInput`（左・右・ジャンプの押した瞬間・攻撃の押した瞬間）。
- 先行入力、やられ中の入力の破棄、向き、左右の打ち消しは、**core（`battle`）が行う**（pc-ui.md §5.2〜§5.4）。キーボードと、同じ規則で動く。
- **エッジのラッチ:** 押した瞬間（`pointerdown`、またはすべらせて別のボタンに入ったとき）を、次のステップまでためる。2つのステップの間に押して離した、短いタップも、1回の押した瞬間として受け取る（pc-ui.md §5.5 と同じ）。

### 6.2 指（ポインター）の扱い

- **Pointer Events** で受ける。指ごとに `pointerId` が違うので、**指ごとに**、いま押しているボタンを1つ覚える（マルチタッチ）。
- 押している操作は、「**どれか1本の指**が、そのボタンを押している」こと。同じボタンを2本の指で押して、1本を離しても、もう1本が押している間は、押している。
- 指を**すべらせて**、別のボタンに入ったら、前のボタンを離し、新しいボタンを押す（新しいボタンのジャンプ・攻撃は、押した瞬間になる）。ボタンの外に出たら、離した扱い。外から、ボタンに入ったら、押した扱い。
- 指の位置のボタンは、`document.elementFromPoint` と、ボタンの `data-action` で決める。
- `pointerup`、`pointercancel` で、その指を離した扱いにする。
- **すべて離した扱いにする場面:** ページが隠れたとき（`visibilitychange`）、ウィンドウのフォーカスが外れたとき（`blur`）、縦持ちになったとき、画面を閉じたとき。ためていた押した瞬間も、捨てる（キーボードの `releaseAll` と同じ）。

### 6.3 マウス・キーボードとの関係

- PC のブラウザで、この画面を開いたときは、マウスでボタンを押せる（Pointer Events はマウスも受ける。確認用）。
- スマホの画面では、キーボードの入力は使わない（つないだキーボードでの操作は、保証しない）。

### 6.4 遅延を増やさない作り（NFR-03）

- ボタンの押した・離したは、イベントの中で、**すぐに入力ソースの状態を書き換える**。React の再描画を待たない。
- ボタンの「押している」見た目は、入力ソースの通知から、ボタンの `data-pressed` 属性を直接切りかえる（画面全体を再描画しない）。
- ゲームの更新は、PC と同じ固定ステップ（60 Hz）。描画が遅れても、入力は、次のステップで読まれる（フレームが落ちても、押した瞬間は失われない）。
- `click` イベントを使わない（モバイルブラウザの、タップの遅延の影響を受けない）。

## 7. 対象ブラウザの制約と対策

対象: **iOS Safari（iOS 15 以降）、Android Chrome（最近の版）**（NFR-04）。

| 起きること | 対象 | 対策 |
|---|---|---|
| ダブルタップで拡大する | iOS Safari、Android Chrome | 対戦の画面の全体に `touch-action: none`。仮想コントローラーで、`touchstart` の既定の動作を止める（`preventDefault`。`passive: false`） |
| 2本指で拡大する（ピンチ） | iOS Safari | `touch-action: none`。iOS の `gesturestart` を、対戦の画面の間だけ止める |
| ページがスクロールする・引っぱって更新する | 両方 | 対戦の画面を `position: fixed` で全面にする。`overscroll-behavior: none`。`touch-action: none` |
| 長押しで、文字の選択・拡大鏡・メニューが出る | iOS Safari、Android Chrome | `user-select: none`、`-webkit-user-select: none`、`-webkit-touch-callout: none`。`contextmenu` を止める |
| タップした所が、灰色に光る | iOS Safari、Android Chrome | `-webkit-tap-highlight-color: transparent` |
| 画面の向きの固定 | iOS Safari では使えない | §5.2（案内）。Android Chrome は、全画面のときだけ固定を試みる |
| 全画面 | iPhone の Safari では使えない | 使えるときだけ試みる。使えなくても遊べる |
| アドレスバーの出し入れで、画面の高さが変わる | 両方 | 高さは `100dvh`（使えない版は `100vh`）。キャンバスは、大きさの変化に追従する（ResizeObserver。既存） |
| ノッチ・ホームバー | iPhone | `env(safe-area-inset-*)` の余白（§5.1） |
| 画面の端からのスワイプ（戻る） | iOS Safari、Android のジェスチャー | ボタンを、端から離す（§5.1）。止められないため、戻ったときは、持ち帰りURLから開き直せる |

- `<meta name="viewport">` に `user-scalable=no` は**加えない**。iOS Safari は無視し、ほかの画面（持ち帰りの入口など）の拡大を、不必要に妨げるため。拡大の抑止は、対戦の画面の `touch-action` で行う。

## 8. 例外・制約

| 場面 | 扱い |
|---|---|
| 縦持ち | 対戦を止め、「よこに してね」を出す（§5.2） |
| 3本以上の指 | それぞれ、指の下のボタンを押す。ボタンの外の指は、無視する |
| 着信・ほかのアプリに移った | すべて離した扱い（§6.2）。戻ったら、続きから |
| 画面が狭い（高さ 320 px 未満） | ボタンの大きさは保ち、対戦の画面は、より小さく縮む。保証は、高さ 360 px 以上 |
