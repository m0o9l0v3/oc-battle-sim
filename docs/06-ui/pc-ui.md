## 1. 概要

PC（デスクトップブラウザ）での操作を定義する。**1台のPC、1つの100%キーボード（テンキー付き）を、2人で共有する**対戦のキー配置（1P / 2P）、入力の規則、キーの確認画面、マウス操作の共通ルールを決める。

## 2. 目的

- 2人が、1つのキーボードで、同時に、迷わず操作できる（左右移動・ジャンプ・攻撃）。
- 同時押しで、キーボードが入力を落とさない配置にする（ゴースト入力への備え）。
- 会場のキーボード（100%）の、キー数の多さを活かす。

## 4. キー配置

### 4.1 標準の配置（100%キーボード）

| 操作 | 1P（左手。キーボードの左側） | 2P（右手。キーボードの右側のテンキー） |
|---|---|---|
| 左へ移動 | **A** | **テンキーの 4** |
| 右へ移動 | **D** | **テンキーの 6** |
| ジャンプ | **W** | **テンキーの 8** |
| 攻撃 | **F** | **テンキーの 5** |

```text
 キーボード（100%）
 ┌──────────────────────────────┬────────────┬───────────────┐
 │  ... W ...                    │            │   [7] [8] [9]  │
 │  ... A  S  D  F ...           │  矢印キー   │   [4] [5] [6]  │
 │       （1P は ここ）           │            │   [1] [2] [3]  │
 └──────────────────────────────┴────────────┴───────────────┘
        1P: W / A D / F                          2P: 8 / 4 6 / 5
```

- **1P は、キーボードの左側（A・D・W・F）、2P は、右側のテンキー（4・6・8・5）**。2人が、並んで座ったとき、それぞれの手の位置に近い。
- 1P: 左右は A と D、ジャンプは W、攻撃は F（D の隣）。左手だけで、4つのキーに届く。
- 2P: 4・5・6 が横に並び、8 が上にある、十字の形。右手だけで、4つのキーに届く。
- キーは、`KeyboardEvent.code`（物理的な位置）で判定する。`code` は、キーボードの言語配列や、NumLock の状態に影響されにくい（テンキーの `Numpad4` など）。

### 4.2 テンキーがない場合の配置（家庭のPCなど）

持ち帰ったあとの、家庭のPC（テンキーのないキーボード）のために、**2P は、次の配置も同時に使える**。標準の配置（§4.1）と、**どちらでも操作できる**（切り替えの設定は不要）。

| 操作 | 2P（矢印キーの配置） |
|---|---|
| 左へ移動 | **←** |
| 右へ移動 | **→** |
| ジャンプ | **↑** |
| 攻撃 | **/（スラッシュ）** |

- **Shift、Ctrl、Alt は使わない。** Shift を連続して押すと、Windows の「固定キー機能」の案内が出て、操作が中断される。Ctrl・Alt は、ブラウザや OS のショートカットとぶつかる。

### 4.3 覚えやすさ

- 画面に、キー配置の図を、いつでも見られる形で出す（S06 の対戦準備の画面、対戦前の READY の間）。
- 参加者への案内は、「左の手は A D W F、右の手は テンキーの 4 6 8 5」の1行。
- 色だけでなく、**文字**（「1P」「2P」）で、持ち主を示す（[character-design.md](../02-fighter/character-design.md) §5.4）。

### 4.4 使わないキー

| キー | 扱い |
|---|---|
| 操作に使うキー以外の文字キー | 無視する（何も起こらない） |
| Esc | 対戦中は何も起こらない（対戦を途中で終えさせない。[battle-rules.md](../03-combat/battle-rules.md) §4） |
| F5（更新）、Ctrl+R など、ブラウザの機能 | 禁止しない（更新は「再開」。[user-flow.md](../01-experience/user-flow.md) §6.1.1） |
| F11（全画面） | 禁止しない（運営の判断で使ってよい） |

- 対戦に使うキーは、ブラウザの動作（スクロール、検索、戻る）を起こさないよう、既定の動作を止める（`preventDefault`）。矢印・スペースなどでページがスクロールしない。

## 5. 入力の規則

操作の入力は、**入力の抽象化レイヤ**（#21）で、プレイヤーごとの `左`・`右`・`ジャンプ`・`攻撃` に変換する。キーボード、仮想パッド（スマホ）、簡易CPU（#72）は、同じ形で、このレイヤにつながる。

### 5.1 入力の種類

| 操作 | 種類 | 規則 |
|---|---|---|
| 左・右 | 押している間 | 左右を同時に押したときは、**打ち消して、止まる**（どちらにも動かない） |
| ジャンプ | **押した瞬間**（エッジ） | 押しっぱなしでは、繰り返さない。空中ジャンプは、新しく押し直す（[recovery.md](../03-combat/recovery.md) §3） |
| 攻撃 | **押した瞬間**（エッジ） | 押しっぱなしでは、連続で出ない。次の攻撃は、押し直す |

- キーリピート（長押しで、OS が繰り返す入力）は、無視する（`event.repeat` が true のものは、押した瞬間として数えない）。

### 5.2 先行入力

- ジャンプ・攻撃を、**できるようになる、4ステップ（約67 ms）前**から、押していれば、できるようになった瞬間に、実行する（**攻撃の硬直の終わり**や、**着地の直前**の操作を、取りこぼさないため）。
- **先行入力の対象にしないもの:** やられ中（hitstun）、撃墜中、リスポーン待ち、READY、END の間に押した、ジャンプ・攻撃は、**捨てる**（先行入力として、ためない）。やられ中が終わる直前の4ステップに押しても、同じ。これは、[combat-system.md](../03-combat/combat-system.md) §7.2 と [recovery.md](../03-combat/recovery.md) §3.1 の「やられ中は、操作が効かない」と一致する。
- 先行入力は、**操作ごとに1つ**（ジャンプ用に1つ、攻撃用に1つ）。同じ操作を、続けて押しても、ためない（最後の1つだけ）。各入力は、押してから **4ステップ**を過ぎると、消える。
- **同じステップに、両方が実行できるとき**（ジャンプと攻撃の先行入力が、同時に有効になったとき）は、**ジャンプ → 攻撃**の順で、**1ステップに1つ**ずつ実行する。ジャンプを先に実行し、攻撃は次のステップ（まだ4ステップ以内なら）に実行する。順序は、キーの押された順や、イベントの処理順に、よらない（決定的）。

### 5.3 向き

- ファイターの向きは、**最後に押した、左右の入力**で決まる。入力が一度もないときは、**相手の方向**を向く（開始時は、ステージの中央を向く）。
- **決め方（決定的）:** 各ステップで、左右の押している状態を見る。
  - **どちらか1つだけ**を押しているとき: その向きに、向く。
  - **両方**を押しているとき: **押した時刻（ステップ）が、あとのほう**の向きに、向く（左右を、別のステップで押したとき）。
  - 両方を、**同じステップ**に、初めて押したとき（押した順が決められないとき）: **直前の向きを、保つ**。イベントの処理順や、キーの種類で、決めない。
  - どちらも押していないとき: **直前の向きを、保つ**。
- 左右の同時押しは、移動としては打ち消す（止まる。§5.1）が、向きは、上の規則で決まる。
- 攻撃は、攻撃を始めたときの向きに、出る。

### 5.4 入力を受け付けない間

| 状態 | 扱い |
|---|---|
| READY、END | 受け付けない |
| やられ中（hitstun）、撃墜中、リスポーン待ち | 受け付けない。**ジャンプ・攻撃の押した瞬間は、捨てる**（先行入力にしない。§5.2）。ただし、**押しているキーの状態（左右）は、追う**（やられ中が終わった瞬間に、押し続けている方向へ、動き出せる） |
| 親機のフェーズで、操作が許可されていない | 受け付けない（[event-control.md](../01-experience/event-control.md) §6） |

### 5.5 タイミング

- 入力は、**ゲームのステップ（60 Hz）ごと**に、その時点の押している状態を読む。画面の更新や、イベントの順序に依存しない（決定的）。
- 同じ入力の列から、同じ結果になる（リプレイ・テストが可能）。

## 6. マウス操作の共通ルール

画面（S01〜S06、S08〜S12）は、**マウスだけ**で操作できる。

| ルール | 内容 |
|---|---|
| クリック | ボタン、選択肢は、クリックで操作する |
| ドラッグ | ステージエディタのブロックの配置だけ（[stage-editor.md](../04-stage/stage-editor.md) §6） |
| ホバー | 押せる要素は、マウスを乗せると、枠・色が変わる（押せることが分かる） |
| 押せない要素 | **理由を、近くに表示する**（「ポイントを つかいきろう」など）。無反応にしない |
| ダブルクリック | 特別な動作を、割り当てない（1回のクリックと同じ） |
| 右クリック | 特別な動作を、割り当てない（ブラウザのメニューは、止めない） |
| 確認のダイアログ | 通常の操作では、出さない（待たせない）。取り消しが必要な操作は、「もどす」で対応する |

- キーボードの操作（Tab で移動、Enter で押す）は、必須としない。ただし、ボタンは、フォーカスで押せる標準の部品を使う。

## 7. キーの確認画面（S06）

- S06（対戦準備）に、**1P と 2P のキーの確認**を表示する。キーを押すと、画面上の該当のキーが、光る（押している間）。
- 目的:
  - 2人が、自分のキーを、確認できる。
  - 押しても反応しないキー（ゴースト入力、NumLock の状態、故障）を、**対戦の前に、見つけられる**（スタッフの確認にも使う。[event-checklist](../09-testing/) #52）。
- **同時押しの確認:** 同時押しの入力の落ち方は、**押す物理キーの組み合わせ**で変わる（キーボードの回路の都合）。そのため、**左へ動く組み合わせと、右へ動く組み合わせの、両方**を確認する。次の **4 通り**を、それぞれ、同時に押して、**6 つのキーが光る**ことを確認する。
  1. 1P の W + D + F と、2P の 8 + 6 + 5（右へ動く）
  2. 1P の W + A + F と、2P の 8 + 4 + 5（左へ動く）
  3. 1P の W + D + F と、2P の 8 + 4 + 5（1P は右、2P は左）
  4. 1P の W + A + F と、2P の 8 + 6 + 5（1P は左、2P は右）
- 2P の矢印の配置（← → ↑ /。§4.2）を使うキーボードでは、同じ 4 通りを、矢印の配置でも確認する（← → ↑ / の組み合わせ）。
- 光らないキーがあるとき、画面に、「ひかる キーが ないよ。スタッフに きいてね」と出す。

### 7.1 ゴースト入力への備え

| 確認 | 内容 | 担当 |
|---|---|---|
| 同時押しの最大 | 1P: W + D + F または W + A + F（3 キー）、2P: 8 + 6 + 5 または 8 + 4 + 5（3 キー）= 6 キー。**左右の向きの組み合わせ 4 通り**を、すべて確認する（§7） | #51（会場と同じ種類のキーボード） |
| 左右の同時押し | 1P の A + D、2P の 4 + 6 は、「止まる」の動作（打ち消し）で、問題にならない | ユニットテスト（#21） |
| 代替の配置 | 6 キーを同時に受け付けないキーボードがあるとき、**スタッフが、別のキーボードに替える**（[event-operation.md](../01-experience/event-operation.md) §9）。キー配置は、設定ファイルで変えられる | 設営 |

- 入力が落ちるキーボードでは、**配置の変更ではなく**、キーボードの交換で対応する（配置を、現場で変えない）。

## 8. ブラウザと画面

| 項目 | 内容 |
|---|---|
| 対象ブラウザ | デスクトップの Chrome / Edge を主対象とする（会場PCの標準。#51 で確認） |
| 画面の大きさ | 最小 **1280 × 720**（16:9）を想定。それより大きくても、拡大して表示する。小さいと、スクロールを出さず、縮小する |
| フォーカス | 対戦中は、ゲームの画面が、キーボードのフォーカスを持つ。ボタンなどにフォーカスが移っていても、対戦のキーが効く |
| ウィンドウが非アクティブ | ほかのウィンドウに移ったとき、押しているキーの状態を、**すべて離した扱い**にする（キーが押されっぱなしにならない） |
| 全画面 | 運営の判断で、F11 を使ってよい |

## 9. キー配置のデータ

```ts
type KeyBinding = Record<'left' | 'right' | 'jump' | 'attack', string[]> // KeyboardEvent.code のリスト

type KeyBindings = { p1: KeyBinding; p2: KeyBinding }
```

標準の値:

```ts
const DEFAULT_BINDINGS: KeyBindings = {
  p1: { left: ['KeyA'], right: ['KeyD'], jump: ['KeyW'], attack: ['KeyF'] },
  p2: {
    left: ['Numpad4', 'ArrowLeft'],
    right: ['Numpad6', 'ArrowRight'],
    jump: ['Numpad8', 'ArrowUp'],
    attack: ['Numpad5', 'Slash'],
  },
}
```

- 配置は、設定ファイルにまとめる（キーの変更を、コードの変更なしに行える）。
- 同じキーが、複数のプレイヤー・操作に重ならないことを、起動時に検証する。

## 10. 例外・制約

| 場面 | 扱い |
|---|---|
| NumLock がオフ | `KeyboardEvent.code` で判定するため、テンキーの 4・6・8・5 は、効く。矢印の配置も使える |
| テンキーがないキーボード | §4.2 の矢印の配置を使う |
| 左右の同時押し | 止まる（打ち消す） |
| IME（日本語入力）がオン | `KeyboardEvent.code` で判定するため、影響を受けにくい。対戦中は、文字入力の欄にフォーカスを置かない |
| 名前の入力欄（S02、S04）にフォーカス | 文字を入力できる。入力欄にフォーカスがあるときは、ゲームの操作として扱わない |
| 長押しの繰り返し | 無視する（§5.1） |

## 11. Acceptance Criteria

- [ ] 左右移動・ジャンプ・攻撃のキー配置（1P / 2P）が決まっている（§4）
- [ ] 同時押しで入力が落ちないことを確認する方法が、定義されている（§7）
- [ ] 入力の規則（エッジ、同時押し、先行入力、向き）が定義されている（§5）
- [ ] マウス操作の共通ルールが定義されている（§6）
- [ ] 配置が、設定で変更でき、重なりを検証する（§9）
- [ ] 会場のキーボード（100%）と、テンキーなしのキーボードの両方に対応している（§4.1、§4.2）
