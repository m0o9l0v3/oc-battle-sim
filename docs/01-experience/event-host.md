- 関連: [event-control.md](./event-control.md)、[event-operation.md](./event-operation.md)、[event-connection.md](../08-architecture/event-connection.md)
- 関連Issue: #67（本書）、#68、#52

## 1. 概要

当日、親機PCで動かすローカルサーバー（`server/`）の、準備・起動・設営・障害時の手順を定める。サーバーは、アプリの静的配信と、進行管理（進行状態の配信・管理画面）を、1つのプログラムで担う（[event-connection.md](../08-architecture/event-connection.md) §5.1）。`oc26-stage` の `tools/event-server.mjs` を、本プロジェクトのフェーズに合わせて TypeScript に移植した（[legacy-assessment.md](../08-architecture/legacy-assessment.md) §3.13）。

## 2. 目的

- 親機PCを、インターネットなしで、短時間に起動できる。
- 親機が止まっても、再起動で、参加者PCの体験を止めない（NFR-01）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-OPS-02 | 親機から、再戦の受付停止・終了の指示・リセットを管理できる | §5（管理画面）、[event-control.md](./event-control.md) §7 |
| NFR-01 | 安定性を最優先する | §6（再起動しても、同じ `sessionId` で続ける） |
| NFR-08 | 外部の資源に依存しない | Node.js の標準機能だけで動く。追加のパッケージを入れない |

## 4. 準備（前日まで。インターネットにつながる場所で）

| 手順 | コマンド・内容 |
|---|---|
| 1. Node.js を入れる | 22.13 以上（`node -v` で確認） |
| 2. リポジトリを親機PCに置く | `git clone` または、フォルダごとコピー |
| 3. 依存を入れる | `npm ci` |
| 4. アプリをビルドする | `npm run build`（`dist/` ができる。**`BASE_PATH` は指定しない**。GitHub Pages 用のビルドとは別） |
| 5. 起動を確かめる | `npm run host` → 表示された URL を、親機のブラウザで開く |
| 6. 親機のアドレスを固定する | 会場の LAN で、親機PCの IPv4 アドレスを、OS の設定で固定する（推奨）。固定できない場合は、起動のたびに表示されるアドレスを使う（§5.1） |
| 7. ファイアウォール | 親機OSのファイアウォールで、Node.js の受信（TCP 8080）を許可する。Windows は、初回起動時の確認で「プライベート ネットワーク」を許可する |

- 当日は、インターネットに出られない（[event-connection.md](../08-architecture/event-connection.md) §2）。**`npm ci` と `npm run build` は、必ず前日までに済ませる。**

## 5. 当日の起動

### 5.1 起動

```bash
npm run host
```

起動すると、次の4つを表示する。

| 表示 | 使い方 |
|---|---|
| 参加者PCで開く URL（`http://<親機のアドレス>:8080/`） | 各参加者PCのブラウザで開く。ブックマークに登録する |
| 個別リセット用のブックマーク（`…/?reset`） | 各参加者PCに登録する（[event-control.md](./event-control.md) §9.1.1） |
| 管理画面（`http://localhost:8080/admin?token=…`） | 親機PCのブラウザで開く。**トークンは起動のたびに変わる** |
| 印刷ステーション（`http://localhost:8080/print-station?token=…`） | 持ち帰りカードを印刷するとき、`--kiosk-printing` を付けた Chrome で開いておく（§5.4） |

オプション:

| オプション | 既定 | 内容 |
|---|---|---|
| `--port` | `8080`（環境変数 `PORT` でも可） | 待ち受けるポート |
| `--dist` | `dist` | 配信するアプリ |
| `--state` | `.host/progress.json` | 進行状態の保存先（§6） |
| `--logo` | `server/assets/school-logo.jpg` | 持ち帰りカードに載せる学校ロゴ。見つからないときは、ロゴなしで印刷する |
| `--public-url` | 環境変数 `VITE_PUBLIC_URL`、なければアプリの既定 | 印刷の依頼を検証する公開URL。アプリのビルドと同じ値にする（起動時に表示する。食い違うと、ログに出る） |

例: `npm run host -- --port 8081`

### 5.2 管理画面

| 表示・ボタン | 内容 |
|---|---|
| フェーズ・残り時間 | ターンの残り（既定は `制作開始` から19分）と、いまのフェーズ（制作・対戦・持ち帰り）の残り。過ぎると、マイナス（橙色）で超過を表示する |
| 時間の調整 | −5分・−1分・＋1分・＋5分 で、いまのフェーズの終了予定をずらす（ターンの終了予定も同じだけ動く） |
| 予定の変更 | 制作・対戦・持ち帰りの予定の長さ（分）を変える。いまのフェーズにもすぐ反映し、次のターン以降も使う（[event-control.md](./event-control.md) §7.5） |
| 次の操作 | 次に押すボタンを、枠で強調する。押せないボタンは、薄く表示する |
| 再戦の受付 | 受付中・停止中 |
| 接続中の参加者PC | **目安の台数**。進行状態の取得の回数を匿名で数えて見積もる（参加者PCを識別しない。[event-control.md](./event-control.md) §11）。台ごとの一覧は出さない |
| サーバー | 稼働中・応答なし |
| 一斉リセット | 確認のあと、全台を S01 に戻す（[event-control.md](./event-control.md) §9） |

- 通常の進行ボタンには、確認を出さない（[event-control.md](./event-control.md) §7.2）。
- 管理画面と管理操作は、**親機PC自身（`localhost`）から、起動時のトークンでだけ**使える。参加者PCからは、URL を知っていても開けない（§7.4）。

### 5.3 1ターンの操作

1. ターンの最初は、`準備中`。必要なら **一斉リセット**（前のターンのデータを消す）。
2. 説明が終わったら **制作開始**（タイマーが始まる）。
3. **対戦開始** → **持ち帰り開始** → （遅れた組がいれば **予備時間へ**）→ **終了**。
4. 時間が押したら、**再戦を止める**（進行中の対戦は止まらない）。延長・短縮は **±1分・±5分**、予定そのものを変えるときは **予定の変更**。
   - 制作が予定までに終わらないときは、制作中のまま **持ち帰り開始（対戦を飛ばす）** を押せる（確認が出る）。ターンの時間を過ぎると、「次の操作」が「持ち帰り開始」になる。
5. 次の組の前に、**一斉リセット**。

- その日の最初のターンの前にも、**一斉リセット**を押す（リハーサルのデータを、参加者PCに残さない。§6）。

### 5.4 持ち帰りカードの印刷

仕様: [take-home-print.md](../05-multiplayer/take-home-print.md)

1. **前日まで:** 親機PC（Windows）にプリンタを登録し、**既定のプリンタ**にする。用紙は A4。テストページを印刷して確かめる。
2. **当日、親機サーバーを起動したら:** Chrome をすべて閉じてから、次のコマンドで印刷ステーションを開く（トークンは、起動時に表示されたものに置き換える）。

   ```bat
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk-printing --user-data-dir=C:\ocbs-print "http://localhost:8080/print-station?token=…"
   ```

   同じコマンドは、印刷ステーションの画面にも表示される。Edge の場合は `msedge.exe`。
3. 参加者が S12 で「カードを いんさつする」を押すと、整理番号の順に印刷される。参加者PCは待機の画面になる。**カードの右上の整理番号**を見て、手渡す。
4. 紙詰まり・用紙切れ: 「一時停止」→ 直す →「もういちど印刷」（同じ整理番号で、先頭に入る）→「再開する」。
5. 次の組の前の **一斉リセット** で、参加者PCの待機の画面は解ける。整理番号は 1 に戻らない（親機サーバーを起動し直したときだけ戻る）。

- 確認の画面が出るときは、`--kiosk-printing` が効いていない（ほかの Chrome が開いていた、など）。そのまま「印刷」を押しても続けられる。

## 6. 再起動と障害

| 状況 | 動作・手順 |
|---|---|
| 親機サーバーを止めた・落ちた | 参加者PCは、開いている画面のまま体験を続ける（[event-control.md](./event-control.md) §10）。`npm run host` で起動し直す |
| 再起動したとき | **保存した進行状態（`--state`）から再開する。** フェーズ・`sessionId`・タイマー・再戦の受付は、止める前のまま。参加者PCはリセットされない。管理画面のトークンは変わるため、表示された新しい URL を開き直す |
| 保存が壊れている・ない | 新しい状態（`準備中`、新しい `sessionId`）で始める。参加者PCは、通信が回復すると S01 に戻る |
| ポートが使われている | 起動時にメッセージを出して止まる。`--port` で別の番号を使い、参加者PCのブックマークも合わせる |
| アプリがビルドされていない | 参加者PCに「ビルドされていません」と表示する。`npm run build` のあと、起動し直す |
| 印刷待ちがあるときに再起動した | 印刷待ちは消える（メモリだけ）。整理番号は 1 から。待機の画面の参加者PCには、スタッフが対応する |

- 保存するのは進行状態だけ（フェーズ・`sessionId`・`revision`・タイマー・再戦の受付）。参加者のデータは、保存しない（印刷の依頼の持ち帰りURLも、メモリにだけ置く）。
- サーバーのログには、起動・管理操作・印刷の受付（整理番号だけ）・異常だけを出す。進行状態の取得のたびには出さない。参加者のデータ（名前・URL）は、ログに出さない。

## 7. 配信するもの・受け付けるもの

| 経路 | 方法 | 接続元 | 内容 |
|---|---|---|---|
| `/`、`/assets/*` など | GET | どこからでも | `dist/` の静的ファイル。`/?reset` も `index.html` |
| `/api/progress` | GET | どこからでも | 進行状態（[event-control.md](./event-control.md) §8.1 の7項目）だけ |
| `/admin` | GET | 親機PCのみ + トークン | 管理画面 |
| `/api/admin/status` | GET | 親機PCのみ + トークン | 管理画面の表示用の値 |
| `/api/admin/command` | POST | 親機PCのみ + トークン | 管理操作（本文は 1KB まで） |
| `/api/print/job` | POST | どこからでも | 持ち帰りカードの印刷の依頼（本文は持ち帰りURLだけ、1KB まで。[take-home-print.md](../05-multiplayer/take-home-print.md) §6） |
| `/print-station`、`/print-station/sheet` | GET | 親機PCのみ + トークン | 印刷ステーションと、1 枚分の印刷シート |
| `/api/print/status`・`claim`・`done`・`reprint` | GET・POST | 親機PCのみ + トークン | 印刷ステーションの操作 |

- 上記以外の POST・PUT などは、**本文を読まずに** 405 を返す（参加者のデータを受信しない）。
