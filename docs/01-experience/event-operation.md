# イベント運営仕様（event-operation.md）

- 文書ID: EXP-EVENT-OP
- バージョン: 0.1
- 状態: 草案
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§2.2、§8、REQ-OPS-01、REQ-OPS-02、NFR-01）
- 関連: [user-flow.md](./user-flow.md)、[event-connection.md](../08-architecture/event-connection.md)

## 1. 概要

オープンキャンパス当日の、進行・スタッフの役割・会場の構成・途中参加・トラブル時の代替進行を定義する。**1ターン約20分**で、参加者が「作る → 対戦 → 振り返る → 設計し直す → 再戦」の学習サイクルを体験できる運営にする。

本書は人の運営を定める。親機（進行管理画面）の機能は `event-control.md`（#65）、当日チェックリストは `09-testing/event-checklist.md`（#52）で定める。

## 2. 目的

- スタッフ・学生ヘルパーが、短い準備で当日を回せるようにする（REQ-OPS-01）。
- 通信不可・機器不調・時間超過でも、体験を止めない代替進行を決めておく（NFR-01）。
- 参加者に唯一の正解を押しつけず、自分で判断して改善する体験にする（設計原則 3）。

## 3. 前提

| 項目 | 内容 |
|---|---|
| 参加者 | 中学生。保護者と2人1組で、1台のデスクトップPCを使う（1ターン最大20組、約40人） |
| 参加者PCの台数 | **20台**（所有者の回答。2026-10-04） |
| ターン数 | **最大3〜4ターン**。ターン間は3〜5分程度 |
| 体験時間 | 1ターンあたり約20分（[user-flow.md](./user-flow.md) §7） |
| 会場の構成 | 親機PC（デスクトップ）1台と参加者PC（有線LAN）。インターネットには出られない。無線ネットワークは使わない |
| 入力 | 1台のPCの100%キーボードを2人で共有する（1P: 左側、2P: 右側） |
| スマートフォン | 当日は使わない。持ち帰りのあと、各自のスマホで遊ぶ |
| アプリの配信 | 親機PCのローカルサーバーから配信する |

## 4. 役割

| 役割 | 人数（案） | 主な仕事 |
|---|---|---|
| 進行役 | 1名 | 全体への説明、親機の操作（再戦の受付停止・終了の指示・リセットなど）、時間の管理 |
| ヘルパー（学生・スタッフ） | 最大3名 | 参加者の個別の補助。担当の列を巡回して、詰まっている組に声をかける（§4.4） |
| 機器担当（兼任可） | 1名 | 親機PCの起動、参加者PCの接続確認、トラブル時の対応 |

### 4.1 進行役

- 導入の説明を行う（§6.1）。
- 親機の管理画面で、進行を時刻どおりに操作する（§6.2）。
- 参加者の画面を一斉に止めて説明し続けない。説明は短くし、操作の時間を守る。
- 時間が押したときの判断を行う（§8）。

### 4.2 ヘルパー

- 巡回し、詰まっている組を見つけて、**次の1操作だけ**を促す。参加者のキーボードやマウスを奪わない。
- 答えを教えない。「どの数字を変えると、動きがどう変わった？」と問いかける。
- 保護者がいない、または参加を希望しない組では、2Pを担当する（§7）。
- 持ち帰りQRの読み取りで詰まった組を補助する。

### 4.3 してはいけないこと

- 特定の能力値の配分を「正解」として勧めない。
- 参加者の操作を代わりに行わない。
- 勝敗だけを評価しない。「何を変えて、何が変わったか」を聞く。

### 4.4 ヘルパーの担当列

PCは横一列4台を1列とし、5列を前から後ろへ並べる（§5）。20台を、ヘルパー3名で分担する。

| 担当 | 列 | 台数 |
|---|---|---|
| ヘルパーA | 前から1〜2列 | 8台 |
| ヘルパーB | 前から3〜4列 | 8台 |
| ヘルパーC | 5列目（最後列）と、全体の補助（持ち帰りQRの読み取りなど） | 4台 |

- 進行役は前方（親機PCの近く）にいる。1〜2列目は、進行役の目も届く。
- 機器担当は、進行役またはヘルパーCが兼任してよい。

## 5. 会場の構成

```text
                  [全体表示（モニター等）]
 [親機PC] ← 進行役の席。管理画面とローカルサーバー（最前方）

   1列目   [PC] [PC] [PC] [PC]      ← ヘルパーA
   2列目   [PC] [PC] [PC] [PC]      ← ヘルパーA
   3列目   [PC] [PC] [PC] [PC]      ← ヘルパーB
   4列目   [PC] [PC] [PC] [PC]      ← ヘルパーB
   5列目   [PC] [PC] [PC] [PC]      ← ヘルパーC

 すべて有線LAN（インターネットなし）で親機とつながる。合計 参加者PC 20台
```

| 項目 | 内容 |
|---|---|
| 親機PC | 進行役の近くに置く。管理画面を表示する。事前にビルドしたアプリを配置し、ローカルサーバーを起動しておく |
| 参加者PC | 親機のアドレスを開く（ブラウザ）。ホーム画面（ブックマーク）を用意しておく |
| 席の配置 | 親機PCを最前方とし、横一列4台を1列として、5列を後ろへ並べる。参加者と保護者が、並んで1台のキーボードを使える間隔にする |
| 全体表示 | あり（所有者の回答）。進行役が全体へ説明する画面（モニター等）。最後列からも文字が読めるかを事前に確認する |
| 電源・LANケーブル | 事前に台数分を確認する |
| スマートフォン | 当日は使わない。持ち帰りQRを読み取るときだけ、各自のスマホを使う（会場のネットワークは使わない） |

## 6. 当日の進行

### 6.1 説明の台本（導入、約1分）

進行役が、全体に向けて話す。専門用語を使わず、短く切る。

> 今日は、自分だけのファイターを作って、対戦します。
>
> ファイターには、「こうげき力」「ふっとばされにくさ」「ジャンプ力」「いどうのはやさ」の4つの数字があります。この数字を決めるのが、みなさんの仕事です。20ポイントを、4つに分けます。
>
> 1回戦をやったら、数字を変えて、もう1回戦います。数字を変えると、動きがどう変わるか、見てみてください。
>
> 「これが正解」という数字はありません。自分で試して、決めてください。
>
> 分からないときは、手を挙げてください。スタッフが行きます。

台本は目安であり、学校の雰囲気に合わせて変えてよい。「スマブラ」などの既存作品の名称は使わない（NFR-07）。

### 6.2 タイムライン（20分）

[user-flow.md](./user-flow.md) §7 の配分に合わせる。親機のフェーズ名は #65 で確定する。ここでは進行の区切りだけを示す。

| 時刻 | 区切り | 画面 | 進行役の操作・声かけ | ヘルパーの重点 |
|---|---|---|---|---|
| 0:00 | 導入 | S01 | 台本（§6.1）を話す。「はじめる」を押してもらう | 全員が S01 を開いているか |
| 1:00 | ファイター作成 | S02、S03 | 「見た目は1分、数字は2分で決めます」 | 4つの数字の意味、20ポイントを使い切ること |
| 4:00 | ステージ | S04 | 「ステージは、選んでも、作ってもOKです」 | プリセットへの誘導（エディタで詰まったら） |
| 6:00 | 試し | S05 | 「1人で動かしてみましょう」 | 操作方法（1P・2Pのキー） |
| 7:00 | 対戦準備 | S06 | 「2人でキーボードを分けます」 | キーの分担、2Pの設定 |
| 8:00 | 第1戦 | S07、S08 | 「対戦スタート。終わったらレポートを見てください」 | 勝敗より、レポートを見ているか |
| 11:00 | 再設計 | S09 | 「数字を変えてみましょう。変えられるのは数字だけです」 | 何を変えたか言えるか |
| 12:00 | 第2戦 | S10、S11 | 「第2戦。終わったら、1回戦との違いを見てください」 | 比較画面の見方 |
| 15:00 | 追加の再戦（予備） | S09〜S11 | 「時間のある組は、もう一度変えて遊べます」 | 遅れた組の補助を優先 |
| 18:00 | 終了・持ち帰り | S12 | 親機の「終了」、または個別に案内。持ち帰りQRの案内 | QRの読み取りの補助 |
| 20:00 | 終了 | — | 親機の「リセット」で次のターンへ | 参加者PCの確認 |

- 時間は目安で、強制しない。画面は、親機の指示がない限り、参加者が自分のペースで進める。
- 進行役の声かけは、時刻の区切りで1回だけ。参加者の手を止めさせない。
- 親機の操作（再戦の受付停止、終了の指示など）の詳細は #65 で定める。

### 6.3 振り返りの声かけ（Battle Report と比較）

参加者に「正解」を示さず、考えるきっかけを作る。

- 「1回戦と2回戦で、何を変えた？」
- 「変えたら、何が変わった？ 動き、ダメージ、ふっとび方は？」
- 「もう1回変えるなら、どの数字をどうする？」

### 6.4 持ち帰り（約2分）

- 持ち帰り用QR（GitHub Pages の固定URL）を、参加者と保護者のスマホで読み取ってもらう（REQ-SHR-01、目標機能）。
- 読み取りには、各自の携帯回線を使う。会場のネットワークは使えない。
- 学校のロゴが、QR発行画面に表示される（許可の範囲: オープンキャンパスでの使用）。
- 読み取れない場合の案内は §9 にある。

### 6.5 ターンの運営

- 1日に**最大3〜4ターン**行う。1ターンは約20分、ターン間は3〜5分（入れ替えと確認の時間）。1ターンあたり、最大20組。
- 1日の所要時間は、おおよそ「(20分 + 3〜5分) × ターン数」。4ターンで約92〜100分。

ターン間の流れ（目安 3〜5分）:

1. 進行役が、親機の**一斉リセット**を行う（20台すべての参加者PCを、初期状態（S01）に戻す）。
2. 参加者と保護者が席を入れ替える。ヘルパーが誘導する。
3. 機器担当（またはヘルパー）が、全台が S01 を表示していることを確認する。表示されていない台は、ブラウザの更新で直す。
4. 進行役が、導入（§6.1）から次のターンを始める。

- 一斉リセットは、親機から1操作で全台に反映できるようにする（`oc26-stage` で実装経験あり。要件は #65 の受入条件に追加）。
- リセット後に、前の参加者の設定やステージが残らないこと（個人情報や作品を、次の参加者に見せない）。
- ターン間の時間は短いので、リセットを人の手で台ごとに行わない。

## 7. 途中参加と人数

| 場面 | 扱い |
|---|---|
| ターン開始後に来た組 | 5分以内なら、S01 から始めてもらう。親機の指示とは独立して進められる（個別のペース）。5分を過ぎた場合は、次のターンの案内、または予備の時間（15:00〜）を使う |
| 保護者がいない、または参加を希望しない | **想定しない**（所有者の回答）。いた場合は、ヘルパーが2Pを担当する。簡易CPU（REQ-CPU-01）が使える場合は、その相手でもよい |
| 参加者が複数名いる組（兄弟など） | 1P と 2P を、本人たちで分担してもよい |
| 途中で帰る | そのまま帰ってよい。親機またはスタッフが、次のターンの前にリセットする |

## 8. 時間が押した場合の削り方

削る順番を、あらかじめ決めておく。

1. S02（見た目）を簡単に済ませる（デフォルトのまま進める）。
2. S04 のエディタを使わず、プリセットステージを選ぶ。
3. S05（試し）を飛ばす。
4. 追加の再戦（予備）をなくす。

**省かないもの:** 第1戦 → 能力値の変更 → 第2戦と、比較の振り返り。ここが学習サイクルの核（設計原則 4）。

## 9. トラブル時の判断

| 場面 | 対応 |
|---|---|
| 親機と通信できない | 参加者PCは、直前の状態のまま続けられる。進行は口頭で案内する。作品や設定は消さない |
| 親機PCが停止した | 機器担当が再起動する。参加者PCは、そのまま使い続けられる。再起動後に再接続する |
| 参加者PCの画面が固まった | ブラウザを更新する。設定が残っていることを確認する（保存方式は #18）。残っていなければ、標準設定から再開する |
| キーボードの入力が効かない・落ちる | 1P と 2P のキー配置を変える、または同時押しが少なくなるように操作を案内する。改善しなければ、別のキーボードに替える |
| ステージが作れない・検証を通らない | プリセットステージを選んでもらう |
| 能力値の合計が20にならない | 画面の残りポイントを見るよう案内する。「全部使い切る」ことを伝える |
| 対戦が終わらない・止まらない | 親機から、その組を終了、またはリセットする（#65） |
| 持ち帰りQRが読み取れない | スマホのカメラを近づける、画面の明るさを上げる。それでも読めなければ、画面のスクリーンショットを撮ってもらう。**会場LANのアドレスを持ち帰り先として案内しない** |
| 時間内に終わらない | 「完成」を求めず、現時点の設定で遊ぶことを優先する。持ち帰りの案内は省かない |
| 一斉リセットが一部の台に届かない | その台のブラウザを更新する（アドレスは親機から配信されるので、更新で初期状態に戻る）。台数が多い場合は、機器担当が確認して回る |
| 全体が停止した | 進行役が声をかけ、アプリを使わずに、体験の振り返り（「数字を変えると何が変わった？」）を口頭で行う |

## 10. 当日前の準備（概要）

詳細な手順とチェックリストは `09-testing/event-checklist.md`（#52）で定める。ここでは、運営上の要点だけを挙げる。

- 親機PCに、事前にビルドしたアプリを配置し、ローカルサーバーを起動できること。
- 参加者PCが、親機のアドレスを開けること（ブックマーク）。
- 親機OSのファイアウォールが、参加者PCからの接続を遮断しないこと。
- キーボードの同時押しで、入力が落ちないこと（会場と同じ種類のキーボードで確認）。
- 親機との通信を切っても、参加者PCで続けられること。
- 持ち帰りQRを、実機のスマホで読み取れること。
- 20台すべてで、親機の一斉リセットが反映されること（#65、#67、#68）。
- スタッフの役割分担と、台本の読み合わせ。リハーサル（#52）。
