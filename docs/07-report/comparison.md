# 戦の比較（comparison.md）

- 文書ID: RPT-COMPARISON
- バージョン: 0.1
- 状態: 草案（文言・見た目は #39 で確定）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.3、REQ-EXP-05、REQ-RPT-02）
- 関連: [battle-report.md](./battle-report.md)、[user-flow.md](../01-experience/user-flow.md)（S11）、[ui-design.md](../06-ui/ui-design.md) §7.10

## 1. 概要

2つの戦（第 N 戦と第 M 戦）を、**設定の違い（能力値）と、結果の違い**を並べて見られる画面（S11）の、表示内容と、計算、表現のルールを定義する。**数字を変えたときに、何が変わったかを、自分で確かめる**ための画面にする。

## 2. 目的

- 設定値の変更点と、結果の変化を、並べて示す（REQ-EXP-05）。
- 「**変えた数字 → 決まって変わる動き**」と、「**結果（運や相手の動きにも左右される）**」を、**区別して**見せる。1回の試合の結果だけで、原因を決めつけさせない。
- 改善の方法を、1つの正解として指示しない（[battle-report.md](./battle-report.md) §8）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-EXP-05 | 第1戦と第2戦の、設定・結果を比較できる | §4、§5 |
| REQ-RPT-02 | 各戦の設定を保存し、比較に使う | §3.1（`MatchResult` を使う） |
| 設計原則 2 | 一つの設定変更と一つの観察可能な現象を結び付ける | §5.2（すうじの ききめ） |
| 設計原則 3 | 唯一の正解を押しつけない | §7 |

### 3.1 入力

- 比較は、[battle-report.md](./battle-report.md) §6 の **`MatchResult` 2 つ**だけから作る（ほかのデータを、読まない）。
- 計算は、描画から独立した純粋な関数にして、ユニットテストできる（#39）。

```ts
compare(a: MatchResult, b: MatchResult): ComparisonView
```

## 4. 比べる戦の選び方

| 項目 | 規則 |
|---|---|
| 既定 | **直前の戦（左）と、いま終わった戦（右、「いま」）**。第2戦が終わったときは、第1戦と第2戦 |
| 選び直し | 「くらべる」の選択で、保存されている戦のうちから、**2つ**を選べる（第 N 戦 と 第 M 戦）。同じ戦を、2つに選べない |
| 並び | 戦の番号の**小さいほうが左**（前）、大きいほうが右（あと） |
| 戦が1つしかない | 比較できない。S11 に進めない（第2戦のあとから） |
| 保持する戦の数 | 暫定で 20 戦まで（[battle-report.md](./battle-report.md) §6）。超えた分は、古い戦から、選べなくなる |

## 5. 表示の構成

```text
┌ くらべてみよう ─────────────────────────────┐
│ くらべる:  [ 第 ▮ 戦 ▼ ] と [ 第 ▮ 戦 ▼ ]   （えらべるよ） │
│ ─ ① すうじ ─    1P         第 ▮ 戦    第 ▮ 戦（いま） かわった│
│   こうげき力                  5           7         ◆ ＋2 │
│   ふっとばされにくさ              5           3         ◆ −2 │
│   ジャンプ力                   5           5            0 │
│   いどうのはやさ                5           5            0 │
│   （2P の すうじ ▼ ひらく）  ※ 2P も かわっていたら ◆ が つくよ │
│ ─ ② すうじの ききめ ─（かえた すうじと、すうじから きまる うごき） │
│   こうげき力 ＋2   →  1かいの ダメージ   12.0 → 13.2（＋1.2） │
│   ふっとばされにくさ −2 → 60%の とき ふっとぶ きょり ▮ → ▮（＋▮）│
│ ─ ③ けっか と しあいで みた うごき ─（うんや あいての うごきでも かわるよ）│
│   しょうはい                 1P の かち →  ひきわけ           │
│   のこり ストック  1P / 2P     ●●○ / ●○○ → ●○○ / ●○○        │
│   あたえた ダメージ           ▮     →    ▮       ＋▮       │
│   うけた ダメージ             ▮     →    ▮       −▮       │
│   たおした / たおされた         ▮ / ▮  →  ▮ / ▮               │
│   いちばん ダメージが たまった とき ▮   →    ▮        ＋▮       │
│   もどれた / もどれなかった       ▮ / ▮ →  ▮ / ▮               │
│   ─ しあいで みた うごき ─                                  │
│   あてた かいすう              ▮     →    ▮       ＋▮       │
│   ふっとんだ きょり（へいきん）    ▮     →    ▮       ＋▮       │
│   ジャンプ / もどれた かいすう   ▮ / ▮ →  ▮ / ▮               │
│   うごかした きょり             ▮     →    ▮       ＋▮       │
│   しあいの ながさ              ▮びょう →  ▮びょう              │
│  「かえた すうじは、どの うごきに あらわれたかな？」              │
│  [ もう一度 すうじを かえる ]                  [ おわる ]       │
└──────────────────────────────────────────────┘
```

### 5.1 ① すうじ（設定の差分）

- **1P の能力値 4 つすべて**を、「左の戦」「右の戦」「かわった」の3列で並べる。変わった行は、**「◆」と、強調**（色だけに頼らない）。差は、「＋2」「−2」（右 − 左）。変わらない行は、「0」。
- 2P の能力値は、「2P の すうじ」を開くと、同じ形で見られる（変わっていれば「◆」を、見出しにも付ける）。
- 外観（見た目）とステージは、**再戦で変えない**（[user-flow.md](../01-experience/user-flow.md) §5.9）ので、比較の対象にしない。**2つの戦で、ステージと、1P・2P の外観・名前が、すべて同じときだけ**、画面の隅に、「みためと ステージは おなじ」と添える。**どれかが違うとき**（`stageDiffers` または `appearanceDiffers` が true）は、この文を出さず、**かわりに、違うものの警告**（「ステージが ちがうよ」「みためが ちがうよ」。§9）を出す。

### 5.2 ② すうじの ききめ（変えた数字と、すうじから きまる うごき）

**確定の値**（[battle-report.md](./battle-report.md) §4.2 の左の列。能力値だけから、**計算で決まる**値）を、並べる。運・相手・操作に、**左右されない**ので、**変えた数字に応じて、必ず変わる**。

| 変えた能力値 | 並べる数字（確定） | 求め方 |
|---|---|---|
| `attackPower` | 1かいの ダメージ | `12 × (1 + 0.10 × (attackPower − 5))`（%） |
| `defense` | ダメージが 60 % たまった ときに ふっとぶ きょり | 速さ `(8 + 0.15 × 60) × (1 − 0.10 × (defense − 5))` から、固定ステップの計算で求めた距離（セル） |
| `jumpPower` | ジャンプの たかさ | `1.6875 × (1 + 0.10 × (jumpPower − 5))`（セル） |
| `speed` | いどうの はやさ | `3.75 × (1 + 0.10 × (speed − 5))`（セル/秒） |

- **変えていない能力値の分は、表示しない**。能力値は、合計が 20 ポイントなので、**1つだけが変わることはない**（ふやした分、どこかが、へる）。必ず、**2つ以上**の能力値が変わり、その分の確定の値が並ぶ。
- 各行は、「**変えた数字（◆ ＋2）→ 確定の値（左 → 右、差）**」の形。数字の下に、一言の説明を添える。
- ここが、**原因と結果が、直接つながっている**部分（体験の中心。[system-overview.md](../00-overview/system-overview.md) §1）。確定の値は、**必ず、変えた数字に応じて変わる**（数字が増えれば、値も、決まった向きに変わる）。
- 試合中に測った値（あてた かいすう、ふっとんだ きょり、ジャンプ・もどれた かいすう、うごいた きょり）は、ここに**入れない**。③に、「しあいで みた うごき」として並べる（§5.3）。

### 5.3 ③ けっか（結果の差分）

- **勝敗（勝者と理由）と、残りのストック**を、いちばん上に、並べる（「第 N 戦: 1P の かち（ストックで かった）」→「第 M 戦: ひきわけ」のように、**それぞれの結果を文で示す**。差の符号は付けない。[battle-report.md](./battle-report.md) §4.1）。
- [battle-report.md](./battle-report.md) §4.1 の6つ（勝敗を除く）に加えて、**「しあいで みた うごき」**（[battle-report.md](./battle-report.md) §4.2 の右の列。あてた かいすう、ふっとんだ きょり、ジャンプ・もどれた かいすう、うごいた きょり）を、「左の戦」「右の戦」「差」で並べる。
- 差は、「＋」（ふえた）「−」（へった）「0」（おなじ）。**よい・わるいの価値づけをしない**（§7）。
- 見出しに、「うんや あいての うごきでも かわるよ」と添える。**②（すうじから きまる）と③（しあいで みた・けっか）を、区別して**見せる。観察の値は、**変えた数字と、同じ向きに変わるとは限らない**（相手の動き、操作、試合の長さにも、左右される）。
- 試合の長さ（秒）を、並べて表示する。長さが違うと、ダメージの合計なども変わるため。

### 5.4 差の計算

| 項目 | 規則 |
|---|---|
| 差 | **右（あと）− 左（前）**。符号は「＋」「−」。0 は「0」 |
| 数 | 回数は整数、ダメージは小数 1 桁（切り捨てでなく、四捨五入）、距離は小数 1 桁 |
| 片方が「—」 | 差は「—」（計算しない） |
| 能力値 | 差の符号つきの整数 |
| 比べる値の向き | 差は、数値の差だけ。**「よくなった」「わるくなった」を、判定しない** |

## 6. 注意の表示（誤解を防ぐ）

| 場面 | 表示 |
|---|---|
| 結果（③）を見るとき | 「けっかは、1かいの しあいごとに ちがうよ。あいての うごきでも かわるよ」 |
| 2P の能力値も変わっているとき | 「あいての すうじも かわっているよ」（比較の注意として、①の近くに出す） |
| 試合の長さが違う（30 秒以上の差） | 「しあいの ながさが ちがうよ（○びょう と △びょう）」 |
| 1P の能力値が、2つの戦で、同じ（変えて、戻した場合など） | 「1P の すうじは おなじ だよ」と示す（②は表示しない）。**原因は、決めつけない**。2P の能力値が違うときは、「あいての すうじも かわっているよ」（上の行）も、あわせて出す。結果（③）に、違いがないときも、「けっかは おなじ くらい だったよ」と、事実だけを示す |
| 能力値を変えた直後の、比べるのが 1 戦ずつ | 1回ずつの結果から、「かんけい するかも」と言える範囲に、とどめる（§7） |

## 7. 表現のルール（正解を押しつけない）

[battle-report.md](./battle-report.md) §8 のルールに従う。比較では、特に次を守る。

- **原因を、決めつけない:** 「こうげき力を あげたから、かった」とは、書かない。②は「**きまって かわる うごき**」、③は「**けっか**」と、区別して書く。
- **よい・わるいの価値づけをしない:** 「ふえた」「へった」「おなじ」だけ。矢印（▲▼）や、緑・赤の色分けを、よい・わるいに対応させない（中立の色にする）。
- **おすすめを、出さない:** 「つぎは ○○を かえよう」と、書かない。問いかけにとどめる。
- 点数・順位・総合評価を、出さない。

### 7.1 問いかけの選び方（決定的）

問いかけは、固定のひな形から、次の順の**最初に当てはまる行を、1つだけ**選ぶ（乱数なし。**1画面に、問いかけは1つ**）。

**前提（ポイントの制約）:** 能力値は、合計が **20 ポイント**。したがって、**1つの能力値だけが変わることはない**。2つの戦で、1P の能力値が違うとき、**必ず2つ以上**が変わり、**ふえた数字と、へった数字の両方**がある。

| 順 | 条件 | 問いかけ（文言は、設定ファイル） |
|---|---|---|
| 1 | 1P の能力値が、2つの戦で同じ | 「すうじは おなじ だったね。けっかを くらべて、なにに きづいたかな？（あいての すうじや うごきも みてみよう）」 |
| 2 | 1P の能力値が違う | **いちばん おおきく かわった すうじ**（差の絶対値が最大。同じ大きさなら、`attackPower`、`defense`、`jumpPower`、`speed` の順）の、ひな形（下の表） |

能力値ごとのひな形（順 2）:

| いちばん おおきく かわった すうじ | 問いかけ |
|---|---|
| `attackPower` | 「こうげき力を かえたら、1かいの ダメージは どう かわった？ ふやした すうじと、へらした すうじで、うごきは どう ちがった？」 |
| `defense` | 「ふっとばされにくさを かえたら、ふっとぶ きょりは どう かわった？ ふやした すうじと、へらした すうじで、うごきは どう ちがった？」 |
| `jumpPower` | 「ジャンプ力を かえたら、ジャンプの たかさは どう かわった？ ふやした すうじと、へらした すうじで、うごきは どう ちがった？」 |
| `speed` | 「いどうのはやさを かえたら、いどうの はやさは どう かわった？ ふやした すうじと、へらした すうじで、うごきは どう ちがった？」 |

- **「1つずつ変える」ことを、提案しない**（ポイントの制約で、できないため）。「ふやした すうじと、へらした すうじ」の**組**として、問いかける。
- 2つの問いは、**1つの文**として、1つの問いかけにまとめる（上の表の文）。答えを決めず、「どう」で終える。

## 8. データ

```ts
type StatChange = { key: 'attackPower' | 'defense' | 'jumpPower' | 'speed'; before: number; after: number; delta: number }

type MetricDiff = { before: number | null; after: number | null; delta: number | null }

type ComparisonView = {
  left: { matchNo: number; outcome: MatchOutcome; stocksLeft: { p1: number; p2: number } }
  right: { matchNo: number; outcome: MatchOutcome; stocksLeft: { p1: number; p2: number } }
  p1StatChanges: StatChange[] // 4 つすべて（変わっていないものは delta 0）
  p2StatChanges: StatChange[]
  p1Unchanged: boolean // 1P の能力値が、すべて同じ
  p2Changed: boolean // 2P の能力値が、1つでも違う
  effects: { key: StatChange['key']; derived: MetricDiff }[] // ②。変えた能力値の分だけ。確定の値（能力値から計算）
  observed: Record<
    'hitsLanded' | 'avgKnockbackDistance' | 'jumps' | 'moveDistance',
    { p1: MetricDiff; p2: MetricDiff }
  > // ③の「しあいで みた うごき」（観察の値）
  results: Record<
    'damageDealt' | 'damageTaken' | 'kos' | 'deaths' | 'maxDamageEndured' | 'recoverySuccess' | 'recoveryFailure',
    { p1: MetricDiff; p2: MetricDiff }
  >
  durationSec: { before: number; after: number }
  largestChange: StatChange['key'] | null // 問いかけの選択に使う（§7.1）
  notes: (
    | 'p2_changed'
    | 'p1_unchanged'
    | 'duration_differs'
    | 'stage_differs' // 2つの戦の StageData が違う
    | 'appearance_differs' // 1P または 2P の外観・名前が違う
  )[] // §6、§9 の注意
  stageDiffers: boolean
  appearanceDiffers: { p1: boolean; p2: boolean }
}
```

- 型の最終定義は、データモデル（#18）で、他のデータとそろえる。

## 9. 例外・制約

| 場面 | 扱い |
|---|---|
| 選んだ2つの戦の、外観・ステージが違う | 起こらない（再戦では変えないため）。万一違っても、①②③の比較は、そのまま行い、**警告を出す**。`compare` は、2つの `MatchResult` の `stage` と、1P・2P の外観・名前を比べ、違えば、`notes` に `stage_differs` / `appearance_differs` を入れ、`stageDiffers`・`appearanceDiffers` を true にする（画面は、「ステージが ちがうよ」「みためが ちがうよ」と表示する） |
| 引き分けの戦 | 結果の1つとして、同じ扱いで比べる |
| 戦が、保持の上限を超えて消えた | その戦は、選べない |
| 一斉リセット | 比較の記録も、すべて破棄される（[user-flow.md](../01-experience/user-flow.md) §6.1.1） |

## 10. Acceptance Criteria

- [ ] 比較画面で、設定値の差分と、結果の差分を、並べて示す形式が決まっている（§5）
- [ ] 能力値の変更と、決まって変わる動きが、結果と区別して示されている（§5.2、§5.3）
- [ ] 比べる戦の選び方（既定、選び直し）が決まっている（§4）
- [ ] 改善方法を、1つの正解として指示しない、ことばの規則と、問いかけの選び方がある（§7）
- [ ] 誤解を防ぐ注意（結果のばらつき、2P の変更、試合の長さ）が示されている（§6）
- [ ] 比較の計算が、2つの `MatchResult` だけから、決定的に作れる（§3.1、§8）
