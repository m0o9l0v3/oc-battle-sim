# Battle Report（battle-report.md）

- 文書ID: RPT-REPORT
- バージョン: 0.1
- 状態: 草案（文言・見た目は #38 で確定）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.3、REQ-RPT-01、REQ-RPT-02）
- 関連: [comparison.md](./comparison.md)、[battle-rules.md](../03-combat/battle-rules.md)、[stat-system.md](../02-fighter/stat-system.md)、[ui-design.md](../06-ui/ui-design.md)

## 1. 概要

1試合のあとに表示する **Battle Report** の、指標の絞り込み、計測のタイミング、データ（`MatchResult`）、表示、表現のルールを定義する。**勝敗だけを示すのではなく、対戦内容を振り返り、「数字を変えると、動きが変わった」ことに、気づかせる**画面にする。

## 2. 目的

- 勝敗に加えて、振り返るための指標を示す（REQ-RPT-01）。
- 各戦の設定と結果を保存し、比較できるようにする（REQ-RPT-02）。
- **システムは、結果と判断材料を示し、改善方法を、1つの正解として指示しない**（上位文書 §6.3、設計原則 3）。
- 能力値の違いが、**どの数字に、どう現れたか**が見える（設計原則 2）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-RPT-01 | 勝敗だけでなく、振り返りの指標を表示する | §4（指標）、§7（表示） |
| REQ-RPT-02 | 各戦の設定を保存し、比較に使う | §6（データ） |
| REQ-EXP-03 | 勝敗と結果を確認できる | §7 |

| 設計原則 3 | 唯一の正解を押しつけない | §8（表現のルール） |

## 4. 採用する指標

候補（[system-overview.md](../00-overview/system-overview.md) §6.3）から、**中学生が、1回の試合で、意味を読み取れる数**に絞った。

### 4.1 たいせんの けっか（6つ + 勝敗）

| 指標 | 表示名（暫定） | 定義 | 候補との対応 |
|---|---|---|---|
| 勝敗 | 「1P の かち」など | [battle-rules.md](../03-combat/battle-rules.md) §7 の結果と理由 | （採用） |
| 与ダメージ | あたえた ダメージ | 相手に与えたダメージの合計（%） | 採用 |
| 被ダメージ | うけた ダメージ | 相手から受けたダメージの合計（%） | 採用 |
| 撃墜数 | たおした かいすう | 相手のストックを奪った回数（§4.3） | 採用 |
| 被撃墜数 | たおされた かいすう | 自分が撃墜された回数（自滅を含む） | 採用 |
| 耐えた最大ダメージ | いちばん ダメージが たまった とき | 試合中に、自分の蓄積ダメージが、最も大きくなった値（%） | 採用 |
| 復帰の成否 | もどれた / もどれなかった | 場外から、足場に戻れた回数と、戻れずに撃墜された回数 | 採用 |

- 残りのストック、試合の時間も、画面に添える（指標としては数えない）。

### 4.2 すうじと うごき（能力値に1つずつ対応する4つ）

**4つの能力値に、それぞれ1つずつ、その能力値の効果が現れる数字**を並べる（設計原則 2）。「どの数字が、どの動きに、どう効いたか」を、見られるようにする。

| 能力値 | 見せる数字（暫定の表示名） | 定義 | 能力値との関係 |
|---|---|---|---|
| `attackPower` | **1かいの ダメージ**（へいきん） | 当てた攻撃1回あたりの、ダメージの平均（%） | 能力値で決まる値そのもの（[damage.md](../03-combat/damage.md) §3） |
| `defense` | **ふっとんだ きょり**（へいきん） | 受けた攻撃1回あたりの、吹き飛ぶ距離の平均（セル。[knockback.md](../03-combat/knockback.md) §7 の固定ステップの計算） | 能力値と、受けたときの蓄積ダメージで決まる |
| `jumpPower` | **ジャンプの かいすう** と **もどれた かいすう** | ジャンプ（空中ジャンプを含む）の回数。場外から戻れた回数（§4.1） | 高さは能力値で決まり、復帰の成否に現れる |
| `speed` | **うごいた きょり** | 自分の操作で、横に動いた距離の合計（セル）。やられ中の、吹き飛ばされた移動は、含めない | 能力値が高いほど、同じ時間で、遠くまで動ける |

- 上の4つは、**自分（1P）のファイター**について、主に示す。2P の分も、並べて見られる（§7）。
- **1かいの ダメージ**は、運や上手さではなく、能力値だけで決まる。数字を変えたときに、**変化が、はっきり見える**（比較。[comparison.md](./comparison.md) §5）。

### 4.3 数え方の規則

| 項目 | 規則 |
|---|---|
| **撃墜数**（たおした） | 相手が撃墜されたとき、その**直前の 5 秒（300 ステップ）以内**に、**自分の攻撃を、相手に当てていた**場合に、自分の撃墜数に数える。そうでなければ、**自滅**（相手の攻撃と関係なく落ちた）として、**撃墜数には数えない** |
| **被撃墜数**（たおされた） | 自分が撃墜された回数。**自滅も含む**（ストックを失った数と一致する） |
| 自滅 | 別に数える（`selfKos`）。画面には、「じぶんで おちた かいすう」として、0 でないときだけ、補足で表示する |
| 与ダメージ・被ダメージ | ヒットしたときの `damageDealt`（[damage.md](../03-combat/damage.md) §3）を、足し上げる。蓄積の上限（999 %）で止まったあとの増加は、含めない |
| 耐えた最大ダメージ | 試合中の、自分の蓄積ダメージの**最大値**。撃墜で 0 に戻る前の値を含む。撃墜されなかった場合は、試合の終わりの値 |
| 復帰の成否 | [recovery.md](../03-combat/recovery.md) §5 のとおり（場外にいた期間ごとに、成功または失敗。0.3 秒未満は数えない） |
| 動いた距離 | 自分の操作による横の移動の合計。やられ中（hitstun）の、吹き飛びによる移動は、含めない。単位はセル |
| 1かいの ダメージ | 与ダメージ ÷ 当てた回数。当てた回数が 0 のときは、「—」（表示しない） |
| ふっとんだ きょり | 受けたヒットごとの、吹き飛ぶ距離（[knockback.md](../03-combat/knockback.md) §7 の固定ステップの計算に、吹き飛ばしの速さを入れた値）の平均。受けたヒットが 0 のときは、「—」 |

## 5. 計測のタイミング

指標は、**試合中のイベント**（[battle-rules.md](../03-combat/battle-rules.md) §9）から、**その場で積み上げて**作る。試合のあとに、記録を読み直さない。

| イベント | 更新する数字 |
|---|---|
| `hit` | 攻撃側の与ダメージ・当てた回数、受けた側の被ダメージ、受けた側の「最後に当てられた時刻と相手」、受けた側の、ふっとび距離の合計・受けた回数 |
| `ko` | 撃墜された側の被撃墜数、撃墜数（相手側。§4.3）、自滅、耐えた最大ダメージ（その時点の蓄積ダメージで更新）。蓄積ダメージは、リスポーンで 0 に戻る |
| `recovery_success` / `recovery_failure` | 復帰の成否 |
| 毎ステップ | 蓄積ダメージの最大値の更新、動いた距離（やられ中でないとき）、ジャンプの回数（ジャンプを実行した瞬間） |
| 攻撃を出した瞬間 | 攻撃を出した回数（`attacksThrown`。画面には出さないが、記録する） |
| `match_end` | 結果、残りのストック、経過時間を、確定する |

- 集計の処理は、描画から独立した純粋な関数にして、ユニットテストできる（#37）。
- 同じ入力から、同じ結果になる（決定的）。

## 6. データ

```ts
type PlayerMetrics = {
  stocksLeft: number
  damageDealt: number // %
  damageTaken: number // %
  hitsLanded: number
  attacksThrown: number // 画面には出さない
  kos: number // たおした
  selfKos: number // じぶんで おちた
  deaths: number // たおされた（自滅を含む）
  maxDamageEndured: number // %
  recoverySuccess: number
  recoveryFailure: number
  jumps: number
  moveDistance: number // セル
  avgDamagePerHit: number | null // %
  avgKnockbackDistance: number | null // セル
}

type MatchResult = {
  schemaVersion: 1
  matchNo: number // 第 N 戦（1 から）
  p1Config: CharacterConfig
  p2Config: CharacterConfig
  stage: StageData
  outcome: MatchOutcome // battle-rules.md §10
  durationSec: number
  p1: PlayerMetrics
  p2: PlayerMetrics
}
```

- **各戦の設定（`p1Config`、`p2Config`）と結果を、1つにして保存**する（REQ-RPT-02）。比較（[comparison.md](./comparison.md)）は、この `MatchResult` だけから作る。
- 保存するのは、**集計した指標**。1つ1つのイベントは、保存しない（容量と、個人情報を持たないため）。
- 保持する数の上限、保存の方法は、#18 で決める（暫定: 試合のあいだ、最大 20 戦分）。体験の終わり（リセット）で、すべて破棄する（[user-flow.md](../01-experience/user-flow.md) §6.2）。

## 7. 表示（S08 / S11 の左の結果）

```text
┌ けっか ─────────────────────────────────────┐
│  1P の かち！（ストックで かった）    のこり ストック 1P ●●○  2P ●○○ │
│  ─ たいせんの けっか ─              1P        2P          │
│   あたえた ダメージ                  ▮         ▮           │
│   うけた ダメージ                    ▮         ▮           │
│   たおした かいすう                  ▮         ▮           │
│   たおされた かいすう                ▮         ▮           │
│   いちばん ダメージが たまった とき     ▮         ▮           │
│   もどれた / もどれなかった          ▮ / ▮     ▮ / ▮       │
│  ─ すうじと うごき ─（あなたの すうじ）                       │
│   こうげき力 5   → 1かいの ダメージ ▮                      │
│   ふっとばされにくさ 5 → ふっとんだ きょり ▮                 │
│   ジャンプ力 5   → ジャンプ ▮かい・もどれた ▮かい           │
│   いどうのはやさ 5 → うごいた きょり ▮                      │
│   「どの すうじが、どの うごきに きいたと おもう？」          │
│              [ すうじを かえて もういちど ]                  │
└──────────────────────────────────────────────┘
```

| 項目 | 内容 |
|---|---|
| 並べ方 | 1P と 2P を、左右に並べる。同じ行は、同じ指標 |
| 上の段 | 勝敗、残りのストック、時間 |
| 中の段 | 「たいせんの けっか」（§4.1 の6つ） |
| 下の段 | 「すうじと うごき」（§4.2 の4つ。**あなた（1P）の能力値**と、対応する数字を、矢印でつなぐ）。2P の分は、折りたたみ、または並べて見られる |
| 数字 | 大きく表示する。単位（%、回、セル）を添える |
| 当てはまらない値 | 「—」（0 回で、平均が計算できない場合） |
| 最後の問いかけ | §8.3 の規則で選んだ、1〜2 つの問いかけ |
| ボタン | 「すうじを かえて もういちど」（S09 へ。[user-flow.md](../01-experience/user-flow.md) §5.8） |

- 1画面に収める（スクロールしない）。指標が多すぎて、読めない画面にしない。

## 8. 表現のルール（正解を押しつけない）

### 8.1 方針

- 画面は、**結果と、判断材料（数字）を示す**。**「こうすべき」「これが正解」と、改善の方法を指示しない**（設計原則 3、[system-overview.md](../00-overview/system-overview.md) §6.3）。
- 評価（「よい」「わるい」「つよい」「よわい」）を、数字に付けない。数字は、**事実として**示す。
- 参加者が、**自分で考える**きっかけとして、**問いかけ**を出す。

### 8.2 ことばの規則

| 区分 | 規則 | 例 |
|---|---|---|
| **使わない言葉** | 「〜すべき」「〜しないと」「正解」「ベスト」「おすすめ」「だめ」「よわい」「つよい」「ざんねん」「しっぱい（人に対して）」「スコア」「ランク」 | 「ジャンプ力を あげるべき」 |
| **使う形** | 事実の文（「〜だったよ」）と、問いかけ（「〜かな？」「〜と おもう？」）。数字と、その数字の元になった設定を、並べる | 「ジャンプ力は 5。もどれた かいすうは 2かい だったよ」 |
| **勝敗** | 勝敗は、事実として示す。勝ち・負けの価値づけ（「すごい」「だめ」）をしない。**引き分け**も、結果の1つとして、同じ扱い | 「ひきわけ（ストックも ダメージも おなじ）」 |
| **数字の大小** | 大きい・小さいを、「よい・わるい」に対応させない（与ダメージは大きいほうがよく、被ダメージは小さいほうがよい、など、読み取るのは、参加者） | 色分けは、よい・わるいに使わず、中立にする |
| **点数・順位** | 総合点、ランキング、星の数を、出さない | （出さない） |

### 8.3 問いかけの選び方（決定的）

最後の問いかけは、**固定のひな形**から、次の順の**最初に当てはまるもの**を、1つ（または、最大 2 つ）選ぶ。同じ結果から、同じ問いかけになる（乱数なし）。

| 順 | 条件 | 問いかけ（文言は、設定ファイル） |
|---|---|---|
| 1 | 2 戦目以降（直前の戦がある） | 「かえた すうじは、どの うごきに あらわれたかな？」 |
| 2 | 自滅がある（`selfKos` ≥ 1） | 「じぶんで おちた ことが あったね。どんな ばめんだった？」 |
| 3 | 復帰に失敗した回数が、成功より多い | 「ステージに もどれなかった ことが あったよ。ジャンプ力や はやさは どう かんけい するかな？」 |
| 4 | 被ダメージが、与ダメージより、かなり大きい（2倍以上） | 「うけた ダメージが おおかったよ。ふっとばされにくさは どう かんけい するかな？」 |
| 5 | 与ダメージが、被ダメージより、かなり大きい（2倍以上） | 「たくさん あたえられたね。こうげき力の ほかに、なにが かんけい したかな？」 |
| 6 | 上のどれにも当てはまらない | 「どの すうじを かえると、うごきが かわるかな？ ひとつ えらんで ためそう」 |

- 問いかけは、**答えを決めない**（「どの」「どう」「なにが」で終える）。**1つの能力値を、勧めない**（「こうげき力を かえよう」とは書かない）。
- 4・5 の「かなり大きい」は、2倍以上（暫定。設定で調整）。1回の試合は、運や相手の動きの影響も受けるため、**断定しない**（「かんけい するかな？」）。

## 9. 例外・制約

| 場面 | 扱い |
|---|---|
| 当てた回数が 0 | 「1かいの ダメージ」は「—」。「あたえた ダメージ」は 0 |
| 受けたヒットが 0 | 「ふっとんだ きょり」は「—」 |
| 引き分け | 結果の1つとして表示する（`draw_*`。[battle-rules.md](../03-combat/battle-rules.md) §7） |
| 一斉リセットで、試合が中断された | 結果を残さない。Report も出ない（[battle-rules.md](../03-combat/battle-rules.md) §11） |
| 自滅だけで決着した | 「たおした かいすう」は 0 で、「じぶんで おちた かいすう」を補足する |
| 2P の能力値を変えていた | 2P の数字の近くに、その能力値も表示する（比較。[comparison.md](./comparison.md) §6） |

## 10. Acceptance Criteria

- [ ] 採用する指標と、計測のタイミング、数え方が定義されている（§4、§5）
- [ ] 能力値ごとに、その効果が現れる数字が、1つずつ対応づけられている（§4.2）
- [ ] 各戦の設定と結果を、まとめて保存するデータが定義されている（§6）
- [ ] 改善方法を、1つの正解として指示しない、ことばの規則と、問いかけの選び方がある（§8）
- [ ] 画面が、勝敗だけでなく、振り返りの指標を示す形で、1画面に収まる（§7）
- [ ] 集計が、決定的で、ユニットテストできる形で書かれている（§5）
