## 1. 概要

1試合のあとに表示する **Battle Report** の、指標の絞り込み、計測のタイミング、データ（`MatchResult`）、表示、表現のルールを定義する。**勝敗だけを示すのではなく、対戦内容を振り返り、「数字を変えると、動きが変わった」ことに、気づかせる**画面にする。

## 2. 目的

- 勝敗に加えて、振り返るための指標を示す（REQ-RPT-01）。
- 各戦の設定と結果を保存し、比較できるようにする（REQ-RPT-02）。
- **システムは、結果と判断材料を示し、改善方法を、1つの正解として指示しない**（上位文書 §6.3、設計原則 3）。
- 能力値の違いが、**どの数字に、どう現れたか**が見える（設計原則 2）。

## 4. 採用する指標

候補（[system-overview.md](../00-overview/system-overview.md) §6.3）から、**中学生が、1回の試合で、意味を読み取れる数**に絞った。

### 4.1 たいせんの けっか（6つ + 勝敗）

| 指標 | 表示名（暫定） | 定義 | 候補との対応 |
|---|---|---|---|
| 勝敗 | 「1P の かち」など | [battle-rules.md](../03-combat/battle-rules.md) §7 の結果と理由 | （採用） |
| 与ダメージ | あたえた ダメージ | 相手に与えたダメージの合計（%） | 採用 |
| 被ダメージ | うけた ダメージ | 相手から受けたダメージの合計（%） | 採用 |
| 撃墜数 | たおした かいすう | 相手のストックを奪った回数（§4.3） | 採用 |
| 被撃墜数 | たおされた かいすう | 自分が撃墜された回数（自滅を含む） | 採用 |
| 耐えた最大ダメージ | いちばん ダメージが たまった とき | 試合中に、自分の蓄積ダメージが、最も大きくなった値（%） | 採用 |
| 復帰の成否 | もどれた / もどれなかった | 場外から、足場に戻れた回数と、戻れずに撃墜された回数 | 採用 |

- 残りのストック、試合の時間も、画面に添える（指標としては数えない）。

### 4.2 すうじと うごき（能力値に1つずつ対応する4つ）

**4つの能力値に、それぞれ1つずつ、その能力値の効果が現れる数字**を並べる（設計原則 2）。数字は、**2種類**に分ける。

- **すうじから きまる うごき（確定）:** 能力値だけから**計算で決まる**値。試合の運・相手・操作に、左右されない。**数字を変えると、必ず、この値が変わる**。
- **しあいで みた うごき（観察）:** 試合の中で**実際に測った**値。能力値の効果が現れるが、**相手の動き・操作・試合の長さにも左右される**（変えた数字と、同じ向きに、変わるとは限らない）。

| 能力値 | **すうじから きまる うごき**（確定） | **しあいで みた うごき**（観察） |
|---|---|---|
| `attackPower` | **1かいの ダメージ**: `12 × (1 + 0.03 × (attackPower − 5))`（%。[damage.md](../03-combat/damage.md) §3） | あてた かいすう（`hitsLanded`） |
| `defense` | **ダメージが 60 % たまった ときに ふっとぶ きょり**: 速さ `(8 + 0.15 × 60) × (1 − 0.03 × (defense − 5))` から、固定ステップの計算で求めた距離（セル。[knockback.md](../03-combat/knockback.md) §6、§7。基準の 60 % は、設定で変えられる） | ふっとんだ きょり（受けたヒットごとの、平均。§4.3） |
| `jumpPower` | **ジャンプの たかさ**: `1.6875 × (1 + 0.10 × (jumpPower − 5))`（セル。[stat-system.md](../02-fighter/stat-system.md) §6.2） | ジャンプの かいすう、もどれた かいすう |
| `speed` | **いどうの はやさ**: `3.75 × (1 + 0.075 × (speed − 5))`（セル/秒。[stat-system.md](../02-fighter/stat-system.md) §6.2） | うごいた きょり（§4.3） |

- 「すうじから きまる うごき」は、**`MatchResult` に入れた能力値から、画面で計算する**（保存しない）。
- 上の4つは、**自分（1P）のファイター**について、主に示す。2P の分も、並べて見られる（§7）。
- **確定の値**は、運や上手さではなく、能力値だけで決まるため、数字を変えたときの**変化が、はっきり見える**（比較。[comparison.md](./comparison.md) §5.2）。**観察の値**は、結果（③）と同じように、ばらつくものとして示す。

### 4.3 数え方の規則

| 項目 | 規則 |
|---|---|
| **撃墜数**（たおした） | 相手が撃墜されたとき、その**直前の 5 秒（300 ステップ）以内**に、**自分の攻撃を、相手に当てていた**場合に、自分の撃墜数に数える。そうでなければ、**自滅**（相手の攻撃と関係なく落ちた）として、**撃墜数には数えない** **撃墜が確定したとき、および、リスポーンしたとき**に、撃墜された側の「最後に当てられた時刻と相手」を、**消去する**（前のストックのときの記録が、次のストックの撃墜の判定に、残らないようにする） |
| **被撃墜数**（たおされた） | 自分が撃墜された回数。**自滅も含む**（ストックを失った数と一致する） |
| 自滅 | 別に数える（`selfKos`）。画面には、「じぶんで おちた かいすう」として、0 でないときだけ、補足で表示する |
| 与ダメージ・被ダメージ | ヒットしたときの `damageDealt`（[damage.md](../03-combat/damage.md) §3）を、足し上げる。蓄積の上限（999 %）で止まったあとの増加は、含めない |
| 耐えた最大ダメージ | 試合中の、自分の蓄積ダメージの**最大値**。撃墜で 0 に戻る前の値を含む。撃墜されなかった場合は、試合の終わりの値 |
| 復帰の成否 | [recovery.md](../03-combat/recovery.md) §5 のとおり（場外にいた期間ごとに、成功または失敗。0.3 秒未満は数えない） |
| 動いた距離（うごかした きょり） | **自分の操作で、動かそうとした距離**。**左右の入力があるステップごとに、`moveSpeed × dt`**（移動速度 × 1/60 秒。[stat-system.md](../02-fighter/stat-system.md) §6.2）を足す。入力がないステップと、やられ中（hitstun）のステップは、**足さない**。**実際に動いた距離（位置の変化）は、使わない**ため、吹き飛ばされた勢いや、空中の惰性、反対向きの入力による押し戻しは、**混ざらない**。壁に押しつけていても、入力があれば、足す（操作した量として数える）。単位はセル。**能力値の `speed` が高いほど、同じ入力の時間で、数字が大きくなる** |
| 1かいの ダメージ | **能力値から計算する確定の値**（[damage.md](../03-combat/damage.md) §3。§4.2）。**当てた回数が 0 のときも、表示する**（試合の結果に、よらないため）。測った平均は、持たない |
| ふっとんだ きょり | 受けたヒットごとに、**実際に吹き飛ばされた横の距離**を測る。**そのヒットを受けた位置から、やられ中（hitstun）が終わる（または撃墜される）位置までの、横の位置の差の絶対値**（セル）。壁・足場に当たって止まった場合は、**止まるまでの実際の距離**になる（自由に飛んだ場合の計算上の距離ではない）。その平均を表示する。受けたヒットが 0 のときは、「—」 |

## 5. 計測のタイミング

指標は、**試合中のイベント**（[battle-rules.md](../03-combat/battle-rules.md) §9）から、**その場で積み上げて**作る。試合のあとに、記録を読み直さない。

| イベント | 更新する数字 |
|---|---|
| `hit` | 攻撃側の与ダメージ・当てた回数、受けた側の被ダメージ、受けた側の「最後に当てられた時刻と相手」、受けた側の、**吹き飛び始めの位置**（ふっとんだ きょりの測定の開始） |
| やられ中（hitstun）の終わり、または撃墜 | 受けた側の「ふっとんだ きょり」を確定する（吹き飛び始めの位置と、終わりの位置の、横の差）。受けたヒットの数と、距離の合計を更新する |
| `ko` | 撃墜された側の被撃墜数、撃墜数（相手側。§4.3）、自滅、耐えた最大ダメージ（その時点の蓄積ダメージで更新）。蓄積ダメージは、リスポーンで 0 に戻る 撃墜された側の「最後に当てられた時刻と相手」を消去する。 |
| `recovery_success` / `recovery_failure` | 復帰の成否 |
| 毎ステップ | 蓄積ダメージの最大値の更新、動いた距離（左右の入力があり、やられ中でないステップに、`moveSpeed × dt` を足す。§4.3）、ジャンプの回数（ジャンプを実行した瞬間） |
| 攻撃を出した瞬間 | 攻撃を出した回数（`attacksThrown`。画面には出さないが、記録する） |
| `match_end` | 結果、残りのストック、経過時間を、確定する。**吹き飛ばされている最中（やられ中）の受けた側がいれば、その時点の位置で、「ふっとんだ きょり」の測定を終え、そのヒットの距離を、足して確定する**（最後のヒットが、距離に入らない、または、受けたヒットがあるのに「—」になる、ことを防ぐ） |

- 集計の処理は、描画から独立した純粋な関数にして、ユニットテストできる（#37）。
- 実装（#37）: `src/report/metrics.ts` の `MetricsRecorder`。ステップごとに `record(前の状態, 後の状態, イベント)` を呼び、試合が終わったら `result(終わりの状態)` で、1P・2P の `PlayerMetrics` を取り出す。`buildMatchResult` が、使った設定・ステージと指標を、`MatchResult` にまとめる。画面（`ui/MatchCanvas`）が、対戦中に記録し、終了時に、戦の記録（セッション）へ渡す。
- 実装で定めた扱い（仕様に書いていなかった部分）:
  - **攻撃を出した回数**は、攻撃が始まったときに出る `attack` イベント（`stepMatch`。#37 で追加）で数える。同じステップで、相手の攻撃を受けて、すぐ打ち消されたものも、出した 1 回に入る。
  - **復帰の失敗**は、成功と同じく、場外にいた時間が 0.3 秒（18 ステップ）以上のものだけ数える（`recovery_failure` のイベントは、短いものも出すので、集計側で絞る）。
  - **与ダメージ・被ダメージ**は、ヒットのイベントの `damageDealt` と、「上限（999 %）までの残り」の、小さいほうを足す（上限で止まったあとの増加を含めない）。
  - **ふっとんだ きょり**は、ヒットの瞬間の、受けた側の横の位置から、やられ中が終わる（または、撃墜・試合の終わり）時点の位置までの差。やられ中は、ヒットを受けない（combat-system.md）ので、測定は、重ならない。
  - 記録係は、数字を、**自分の中で、書き換えながら**積み上げる（ステップごとに、新しい配列・オブジェクトを作らない）。1 ステップの記録は、約 0.04 ms 未満（テストで確認。フレーム予算 16.7 ms に対して、ごく小さい）。同じ入力の列から、同じ結果になる。
  - 保存の読み込みで、指標の形（すべて 0 以上の有限の数。平均の距離は、数または null）を確かめる。指標のない戦の記録も、読み込める。
- 同じ入力から、同じ結果になる（決定的）。

## 6. データ

```ts
type PlayerMetrics = {
  stocksLeft: number
  damageDealt: number // %
  damageTaken: number // %
  hitsLanded: number
  attacksThrown: number // 画面には出さない
  kos: number // たおした
  selfKos: number // じぶんで おちた
  deaths: number // たおされた（自滅を含む）
  maxDamageEndured: number // %
  recoverySuccess: number
  recoveryFailure: number
  jumps: number
  moveDistance: number // セル
  avgKnockbackDistance: number | null // セル
}

type MatchResult = {
  schemaVersion: 1
  matchNo: number // 第 N 戦（1 から）
  p1Config: CharacterConfig
  p2Config: CharacterConfig
  stage: StageData
  outcome: MatchOutcome // battle-rules.md §10
  durationSec: number
  p1: PlayerMetrics
  p2: PlayerMetrics
}
```

- **各戦の設定（`p1Config`、`p2Config`）と結果を、1つにして保存**する（REQ-RPT-02）。比較（[comparison.md](./comparison.md)）は、この `MatchResult` だけから作る。
- 保存するのは、**集計した指標**。1つ1つのイベントは、保存しない（容量と、個人情報を持たないため）。
- 保持する数の上限、保存の方法は、#18 で決める（暫定: 試合のあいだ、最大 20 戦分）。体験の終わり（リセット）で、すべて破棄する（[user-flow.md](../01-experience/user-flow.md) §6.2）。

## 8. 表現のルール（正解を押しつけない）

### 8.1 方針

- 画面は、**結果と、判断材料（数字）を示す**。**「こうすべき」「これが正解」と、改善の方法を指示しない**（設計原則 3、[system-overview.md](../00-overview/system-overview.md) §6.3）。
- 評価（「よい」「わるい」「つよい」「よわい」）を、数字に付けない。数字は、**事実として**示す。
- 参加者が、**自分で考える**きっかけとして、**問いかけ**を出す。

### 8.2 ことばの規則

| 区分 | 規則 | 例 |
|---|---|---|
| **使わない言葉** | 「〜すべき」「〜しないと」「正解」「ベスト」「おすすめ」「だめ」「よわい」「つよい」「ざんねん」「しっぱい（人に対して）」「スコア」「ランク」 | 「ジャンプ力を あげるべき」 |
| **使う形** | 事実の文（「〜だったよ」）と、問いかけ（「〜かな？」「〜と おもう？」）。数字と、その数字の元になった設定を、並べる | 「ジャンプ力は 5。もどれた かいすうは 2かい だったよ」 |
| **勝敗** | 勝敗は、事実として示す。勝ち・負けの価値づけ（「すごい」「だめ」）をしない。**引き分け**も、結果の1つとして、同じ扱い | 「ひきわけ（ストックも ダメージも おなじ）」 |
| **数字の大小** | 大きい・小さいを、「よい・わるい」に対応させない（与ダメージは大きいほうがよく、被ダメージは小さいほうがよい、など、読み取るのは、参加者） | 色分けは、よい・わるいに使わず、中立にする |
| **点数・順位** | 総合点、ランキング、星の数を、出さない | （出さない） |

### 8.3 問いかけの選び方（決定的）

最後の問いかけは、固定のひな形から、次の順の**最初に当てはまる行を、1つだけ**選ぶ（**1画面に、問いかけは、1つ**。2つめは選ばない）。同じ結果から、同じ問いかけになる（乱数なし）。

| 順 | 条件 | 問いかけ（文言は、設定ファイル） |
|---|---|---|
| 1 | 2 戦目以降（直前の戦がある） | 「かえた すうじは、どの うごきに あらわれたかな？」 |
| 2 | **1P の**自滅がある（`p1.selfKos` ≥ 1） | 「じぶんで おちた ことが あったね。どんな ばめんだった？」 |
| 3 | **1P の**復帰に失敗した回数が、成功より多い（`p1.recoveryFailure` > `p1.recoverySuccess`） | 「ステージに もどれなかった ことが あったよ。ジャンプ力や はやさは どう かんけい するかな？」 |
| 4 | **1P の与ダメージと被ダメージが、どちらも 0 より大きく**（`p1.damageDealt` > 0 かつ `p1.damageTaken` > 0）、かつ、`p1.damageTaken` ≥ 2 × `p1.damageDealt` | 「うけた ダメージが おおかったよ。どんな ばめんで うけたかな？ ふっとんだ きょりは どうだった？」 |
| 5 | **1P の与ダメージと被ダメージが、どちらも 0 より大きく**（`p1.damageDealt` > 0 かつ `p1.damageTaken` > 0）、かつ、`p1.damageDealt` ≥ 2 × `p1.damageTaken` | 「たくさん あたえられたね。こうげき力の ほかに、なにが かんけい したかな？」 |
| 6 | 上のどれにも当てはまらない | 「どの すうじを かえると、うごきが かわるかな？ ひとつ えらんで ためそう」 |

- **条件は、すべて「1P（あなた）」の数字で判定する**（1P と 2P を分けて保存しているため。問いかけは、参加者（1P）に向けた文）。2P の数字は、問いかけの選択に使わない（2P だけが自滅した、など）。
- 問いかけは、**答えを決めない**（「どの」「どう」「なにが」で終える）。**1つの能力値を、勧めない**。
- 4・5 は、**1P の与ダメージと被ダメージが、どちらも 0 より大きいときだけ**、2倍の比べを行う。**片方が 0 のとき**（例: 1回だけ当てて、1回も当てられていない）は、「おおい」「たくさん」と言えるほどの比べにならないため、4・5 には当てはまらず、次の行（順 6）へ進む（両方が 0 のとき、「ダメージが おおかった」とは、言わない）。2倍以上は、暫定（設定で調整）。1回の試合は、運や相手の動きの影響も受けるため、断定しない。
- 順 6 の「ひとつ えらんで」は、**能力値は、合計 20 ポイントなので、1つだけを変えることはできない**（ふやした分、どこかを、へらす）ことと、矛盾しない言い方にする（「ひとつ えらんで ためそう」は、「ふやす すうじを ひとつ えらぶ」の意味。文言は #38 で、言い換える。例: 「どの すうじを ふやして、どの すうじを へらすと、うごきが かわるかな？」）。

## 9. 例外・制約

| 場面 | 扱い |
|---|---|
| 当てた回数が 0 | 「あたえた ダメージ」は 0。「1かいの ダメージ」は、確定の値として、そのまま表示する（§4.3） |
| 受けたヒットが 0 | 「ふっとんだ きょり」は「—」 |
| 引き分け | 結果の1つとして表示する（`draw_*`。[battle-rules.md](../03-combat/battle-rules.md) §7） |
| 一斉リセットで、試合が中断された | 結果を残さない。Report も出ない（[battle-rules.md](../03-combat/battle-rules.md) §11） |
| 自滅だけで決着した | 「たおした かいすう」は 0 で、「じぶんで おちた かいすう」を補足する |
| 2P の能力値を変えていた | 2P の数字の近くに、その能力値も表示する（比較。[comparison.md](./comparison.md) §6） |

## 10. Acceptance Criteria

- [ ] 採用する指標と、計測のタイミング、数え方が定義されている（§4、§5）
- [ ] 能力値ごとに、その効果が現れる数字が、1つずつ対応づけられている（§4.2）
- [ ] 各戦の設定と結果を、まとめて保存するデータが定義されている（§6）
- [ ] 改善方法を、1つの正解として指示しない、ことばの規則と、問いかけの選び方がある（§8）
- [ ] 画面が、勝敗だけでなく、振り返りの指標を示す形で、1画面に収まる（§7）
- [ ] 集計が、決定的で、ユニットテストできる形で書かれている（§5）
