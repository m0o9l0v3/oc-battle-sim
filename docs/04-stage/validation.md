# ステージの検証（validation.md）

- 文書ID: STG-VALIDATION
- バージョン: 0.1
- 状態: 草案（数値は暫定。調整は #25）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.2、REQ-STG-01）
- 関連: [stage-format.md](./stage-format.md)、[stat-system.md](../02-fighter/stat-system.md)、[recovery.md](../03-combat/recovery.md)

## 1. 概要

作ったステージ、読み込んだステージが、**対戦として成立する**かを調べる規則を定義する。各規則に、数値の基準と、違反したときの参加者向けのメッセージ（コード、場所、直し方）を持たせる。**最小のジャンプ力・移動速度のファイターでも、すべての足場に到達できる**ことの検証方針（§5）を含む。

## 2. 目的

- 対戦が始まらない、続かない、片方だけが不利になる、ステージを作らせない。
- 中学生が、理由を読んで、自分で直せる（NFR-02）。
- 検証は、**決定的な関数**で、エディタ（#33）、プリセット（#32）、持ち帰りの復元（#60）のどこでも同じ結果になる。

## 4. 規則の一覧

| コード | 規則 | 数値の基準 | 検証の場面 |
|---|---|---|---|
| `MALFORMED` | 形式が正しい（型が合う。14 行 × 24 列の配列、すべての値が 0 または 1、スポーンが 2 つあり、**スポーンの列・行が有限の整数**、名前が文字列） | 14 行 × 24 列 | 読み込み |
| `SCHEMA_UNSUPPORTED` | `schemaVersion` が、読み込める版 | `schemaVersion` が **1**（現在）。それ以外は拒否する | 読み込み |
| `BLOCKS_TOO_FEW` | ブロックの数が少なすぎない | **30 個以上** | 編集・対戦開始・読み込み |
| `BLOCKS_TOO_MANY` | ブロックの数が多すぎない | **150 個以下**（全 336 個の約 45 %） | 同上 |
| `MAIN_PLATFORM_NARROW` | ひろい足場がある（床の面積） | メイン足場の幅が **10 セル以上** | 同上 |
| `PLATFORM_TOO_NARROW` | せまい足場がない | すべての足場の幅が **2 セル以上** | 同上 |
| `STAGE_TOO_HIGH` | 上の空間が空いている（高度） | **上の 4 行（行 0〜3）に、ブロックがない** | 同上 |
| `SPAWN_MISSING` | スポーンが 2 つある | P1、P2 の両方 | 同上 |
| `SPAWN_OUT_OF_RANGE` | スポーンが、グリッドの中 | 列 0〜23、行 0〜13（整数。整数でない値は `MALFORMED`） | 同上 |
| `SPAWN_BLOCKED` | スポーンの場所が空で、上が空いている（スポーン領域） | スポーンのセルと、その上の **3 セル**が空 | 同上 |
| `SPAWN_NO_GROUND` | スポーンの真下が、立てるセル | スポーンの 1 つ下が、立てるセル | 同上 |
| `SPAWN_TOO_CLOSE` | 2人のスポーンが離れている | 列の差が **8 以上** | 同上 |
| `UNREACHABLE` | **全ての足場に、行き来できる**（§5） | 強連結 | 同上 |
| `NAME_TOO_LONG` | 名前の長さ | 10 コードポイント以内、かつ UTF-8 で 30 バイト以内 | 同上 |

- 「場外領域」（[battle-rules.md](../03-combat/battle-rules.md) §5.2）は、ステージの範囲の外側に、決まった余白で付く。ステージの形では、変えられない。場外までの距離は、[stage-format.md](./stage-format.md) §7。
- 上の数値は、設定にまとめる（調整のために、コードを変えない）。

### 4.1 規則の理由

| 規則 | 理由 |
|---|---|
| ブロックの数 | 少なすぎると立つ場所がない。多すぎると、動ける空間がなく、対戦にならない |
| メイン足場の幅 10 | 両者が離れて立てる（スポーンの間隔 8 以上）。接近・距離を取る動きができる |
| 足場の幅 2 | 1マスの柱の上は、立ちにくく、遠くからの復帰の目標にもならない |
| 上の 4 行 | ジャンプ・空中ジャンプ（最大 3 段）の上の空間。復帰の動き（[recovery.md](../03-combat/recovery.md)）を妨げない |
| スポーンの上の 3 セル | リスポーンの直後に、頭がぶつからない。ジャンプの最小の高さ 1.18 セルを超える |
| スポーンの間隔 8 | 開始の直後に、攻撃が届かない（攻撃の届く距離は約 0.85 セル） |

## 5. 到達可能性（最小の能力値でも、全ての足場に行ける）

### 5.1 方針

**最小のジャンプ力（`jumpPower` 2）と、最小の移動速度（`speed` 2）のファイターが、すべての足場の間を、行き来できる**ことを調べる。能力値の配分によって、ステージの一部に行けなくなる、または、そこから出られなくなる、ことを防ぐ（[stat-system.md](../02-fighter/stat-system.md) §8）。

| 前提 | 値 |
|---|---|
| 最小のジャンプ高さ | 約 1.18 セル |
| 最小の移動速度 | 約 2.91 セル/秒（`speed` 2。#25 の係数の調整で、2.63 から上がった） |
| 使うジャンプ | 地上のジャンプ 1 回 + 空中ジャンプ 1 回（空中ジャンプは最大 2 回あるが、**1回までしか、頼らない**。余裕を持たせるため） |
| 余裕 | 数値シミュレーションで求めた、飛べる距離の **70 %** まで |

### 5.2 飛び移りの規則（セルの単位）

2つの立てるセル（出発 `a`、到着 `b`）の間の、**飛び移り**が成立する条件。

| 項目 | 規則 |
|---|---|
| 高さの差（rise） | **+2 以下**（上へ、2 セルまで）。+3 以上は、飛び移れない |
| 隙間（gap） | rise が **−1 以上**（同じ高さ、または 1 セル低い、上へ）のとき **1 セル以下**。rise が **−2 以下**（2 セル以上、低い）のとき **2 セル以下** |
| 通り道 | 次のセルがすべて空（§5.3） |

飛べる距離の元の値（最小の能力値、地上 + 空中 1 回、シミュレーション。1/60 秒の刻み）:

| rise | +2 | +1 | 0 | −1 | −2 | −3 | −4 |
|---|---|---|---|---|---|---|---|
| 飛べる距離（セル） | 1.74 | 2.37 | 2.85 | 3.14 | 3.38 | 3.58 | 3.77 |
| 余裕（70 %）の距離 | 1.2 | 1.7 | 2.0 | 2.2 | 2.4 | 2.5 | 2.6 |
| **許す隙間（セル）** | **1** | **1** | **1** | **1** | **2** | **2** | **2** |

- rise が +3 のとき、最小のジャンプ力では、空中ジャンプを2回使っても、余裕がほとんどないため、飛び移りを認めない（足場の高さの差は、+2 まで）。
- 横に隣り合う立てるセル（同じ行）は、歩いて移れる（隙間 0）。

### 5.3 通り道（飛び移りの途中に、ブロックがない）

出発のセルの列 `ca`、到着のセルの列 `cb`、出発の行 `ra`、到着の行 `rb`、低いほうの行 `lo = min(ra, rb) − 3` とする。次の範囲が、**すべて空**であること。

| 範囲 | 列 | 行 |
|---|---|---|
| 出発の列 | `ca` | `lo` 〜 `ra − 1` |
| 隙間の列（あれば） | `ca` と `cb` の間のすべての列 | `lo` 〜 `max(ra, rb) − 1` |
| 到着の列 | `cb` | `rb − 3` 〜 `rb − 1` |

- 足場の下からは、すり抜けられない（ブロックは固体）。足場に乗るには、**横から**（隣の列から）飛び移る。
- グリッドの上の外は、空として扱う。

### 5.4 判定

1. グリッドの、すべての**立てるセル**を、頂点にする。
2. 次のとき、頂点どうしに、**辺**（行き来できる向き）を引く。
   - 同じ行で、横に隣り合う（歩ける）
   - 飛び移りが成立する（§5.2、§5.3）。**向きごとに、別々に判定する**（上へ飛べても、下へ戻れない、またはその逆がある）
3. **強連結**（どの頂点からも、どの頂点へも、辺をたどって行ける）なら合格。

- 足場の1つにだけ入れて、出られない（落ちるしかない）場所、どこからも行けない足場があると、`UNREACHABLE`。
- 計算量は、頂点が最大 336 個、1つの頂点から飛び移れる先が約 100 個以下で、一瞬で終わる。
- この判定は、**ステージの形だけ**で決まる。ファイターの実際の能力値には、依存しない（最小の能力値で通れば、すべての配分で通る。能力値が高いほど、飛べる距離は大きい）。

## 6. メッセージ

違反ごとに、**何が問題か**、**どこか**、**どう直すか**を示す。やさしい日本語で、短く。数値は、規則の数値から作る。

| コード | メッセージ | 示す場所 | 直し方（案内） |
|---|---|---|---|
| `BLOCKS_TOO_FEW` | 「ブロックが すくないよ。あと ○こ おこう」 | （なし） | ブロックを置く |
| `BLOCKS_TOO_MANY` | 「ブロックが おおすぎるよ。○こ へらそう」 | （なし） | ブロックを消す |
| `MAIN_PLATFORM_NARROW` | 「ひろい ゆかが ないよ。10マス いじょうの ゆかを つくろう」 | 最も広い足場 | 床を広げる |
| `PLATFORM_TOO_NARROW` | 「せまい あしばが あるよ。2マス いじょうに しよう」 | その足場 | 足場を広げる、または消す |
| `STAGE_TOO_HIGH` | 「たかすぎる ブロックが あるよ。うえの 4れつは あけておこう」 | 行 0〜3 のブロック | ブロックを下げる、または消す |
| `SPAWN_MISSING` | 「スタートの いちが きまっていないよ」 | （なし） | スポーンを置く |
| `SPAWN_OUT_OF_RANGE` | 「スタートの いちが はみだしているよ」 | スポーン | スポーンを動かす |
| `SPAWN_BLOCKED` | 「スタートの うえに ブロックが あるよ。うえを あけよう」 | スポーンの上の3セル | ブロックを消す |
| `SPAWN_NO_GROUND` | 「スタートの したに ゆかが ないよ」 | スポーン | 床を置く、またはスポーンを動かす |
| `SPAWN_TOO_CLOSE` | 「ふたりの スタートが ちかすぎるよ。もっと はなそう」 | 2つのスポーン | スポーンを離す |
| `UNREACHABLE` | 「いけない あしばが あるよ。ジャンプで とどく ように しよう」 | 行き来できない足場（強調） | 足場を近づける、高さを下げる |
| `NAME_TOO_LONG` | 「なまえが ながすぎるよ」 | （名前の入力） | 短くする |
| `MALFORMED`（読み込み） | 「ステージを よみこめなかったよ。もういちど よみとってね」 | （なし） | [stage-format.md](./stage-format.md) §10 |
| `SCHEMA_UNSUPPORTED` | 「このステージは、いまの アプリでは よみこめないよ。あたらしい ばんの アプリで ひらいてね」 | （なし） | アプリを更新する、または標準のステージで始める |

- メッセージの文言は、設定ファイルにまとめる（コードに直接書かない）。
- 複数の違反があるときは、**すべて**返す。画面では、最初の1〜3件を、重要な順（`MALFORMED` > スポーン > 足場 > 数）に示し、残りは「ほかにも ○こ あるよ」とまとめる。
- 「示す場所」は、エディタで、該当のセルを強調するためのデータ（`cells`）として返す。

## 7. 関数

```ts
type StageViolation = {
  code: string
  cells?: { col: number; row: number }[] // 強調するセル
  detail?: number // 数値（あと何個、など）
}

validateStage(
  stage: unknown,
  mode: 'editing' | 'match' | 'import'
): { ok: true; stage: StageData } | { ok: false; violations: StageViolation[] }
```

| 場面 | 検証の範囲 |
|---|---|
| `editing` | 編集の途中。全規則を調べ、結果を**案内**として示す（保存や、画面の移動は止めない）。`MALFORMED` は起こらない |
| `match` | **対戦を始める前**（S04 → S05、S06 → S07）。すべての規則に通らなければ、進めない |
| `import` | 持ち帰りの復元、プリセットの読み込み。形式（`MALFORMED`）と版（`SCHEMA_UNSUPPORTED`）を含めて、すべて調べる。失敗は、失敗として返す |

- **例外を投げない。** 不正な入力でも、`ok: false` を返す。**型・値の検査（`MALFORMED`、`SCHEMA_UNSUPPORTED`）を、先に行い**、通ったものだけを、ほかの規則（セルの参照を含む）で調べる。`cells[row + 1][col]` のような参照は、スポーンが整数で、範囲内であることを確認したあとにだけ行う。
- 同じ入力から、同じ結果になる（決定的。乱数なし）。
- 検証は、描画から独立した純粋な関数で、ユニットテストできる（#31）。
- 実装（#31）: `src/stage/`（`validate.ts` = `validateStage`、`analysis.ts` = 立てるセル・足場・飛び移り・到達可能性、`rules.ts` = 数値、`rows.ts` = 文字の並びからステージを作る補助）。参加者向けのメッセージは `src/assets/stageMessages.ts`（`describeViolation`、`summarizeViolations`）と `messages.ts`（`stageRules`）。core 層は assets を読めないため、関数は違反のコード・セル・数値だけを返し、文に直すのは assets 側。
- 実装で定めた扱い（仕様に書いていなかった部分）:
  - 型・値の検査（`MALFORMED`）は、3 つの場面すべてで先に行う。`schemaVersion` の比較（`SCHEMA_UNSUPPORTED`）は `import` だけ（`validateConfig` と同じ）。それ以外の規則は、3 つの場面で同じ。
  - `SPAWN_MISSING`: スポーンが `null`・`undefined`（片方または両方）。形が違う、整数でない値は `MALFORMED`。
  - 最上段（行 0）のブロックは、上がグリッドの外で、体が収まらないため、「立てるセル」に数えない（§9 の「全面がブロック → 立てるセルがない」と合わせる）。行 0 のブロックは `STAGE_TOO_HIGH` になる。
  - `SPAWN_NO_GROUND`: スポーンの 1 つ下が、ブロックでない（または最下行）。スポーン自身がブロックのときは `SPAWN_BLOCKED` だけを返す。
  - `UNREACHABLE` で示すセル: メイン足場から、行って戻れる立てるセル以外すべて。
  - 名前が未入力（空・空白だけ）のときは、成功した stage の名前を、デフォルト名（`DEFAULT_STAGE_NAME`）にする。
  - 違反は、重要な順（スポーン > 到達・足場 > 高さ・数 > 名前）に返す。

## 8. テストの観点（#31）

| ステージ | 期待する結果 |
|---|---|
| 標準のステージ（[stage-format.md](./stage-format.md) §8） | 合格 |
| 足場の高さの差が +3 の足場がある | `UNREACHABLE` |
| 足場の隙間が 2（rise 0）、またはメイン足場の途中に 4 セルの穴 | `UNREACHABLE`、またはメイン足場が狭い（`MAIN_PLATFORM_NARROW`） |
| 一方向にしか行けない足場（高い足場に登れるが、降りられない向きの飛び移りが成立しない） | `UNREACHABLE` |
| 1マスの幅の柱 | `PLATFORM_TOO_NARROW` |
| 行 0〜3 にブロックがある | `STAGE_TOO_HIGH` |
| スポーンの上にブロック | `SPAWN_BLOCKED` |
| 2つのスポーンの列の差が 7 | `SPAWN_TOO_CLOSE` |
| 全面が地面の、床だけのステージ（隙間なし） | 合格（平らな床は、許す） |
| ブロックが 29 個 / 151 個 | `BLOCKS_TOO_FEW` / `BLOCKS_TOO_MANY` |
| スポーンが `{ col: 4.5, row: 9 }`（小数） | `MALFORMED`（例外を投げない） |
| `schemaVersion` が 2 | `SCHEMA_UNSUPPORTED` |

- 上の標準のステージと、一部の違反は、試作の検証で、期待どおりの結果になることを確認した（足場の高さの差 +3 は強連結にならない、など）。

## 9. 例外・制約

| 場面 | 扱い |
|---|---|
| 複数の違反 | すべて返す（§6） |
| グリッドの上の外 | 空として扱う（通り道、頭上の空間の判定） |
| ブロックが全面 | `BLOCKS_TOO_MANY` と、立てるセルがないことによる `MAIN_PLATFORM_NARROW` |
| 能力値の係数を調整した（#25） | 最小のジャンプ高さ・移動速度が変わるため、§5.2 の表を、再計算する |
| ステージの寸法を変えた | §4 の数値と、スポーンの間隔を、見直す |

## 10. Acceptance Criteria

- [ ] 各制約に、数値の基準と、違反時のメッセージがある（§4、§6）
- [ ] ジャンプ力・移動速度が最小でも、全足場に到達できることの検証方針が、数値と判定の手順で示されている（§5）
- [ ] 検証の関数が、例外を投げず、決定的で、場面ごとの範囲が決まっている（§7）
- [ ] ユニットテストで確認すべきステージが挙げられている（§8）
- [ ] 標準のステージが、すべての規則を満たしている（[stage-format.md](./stage-format.md) §8）
