# ステージエディタ仕様（stage-editor.md）

- 文書ID: STG-EDITOR
- バージョン: 0.1
- 状態: 草案（画面の細部は #36 のデザインで確定）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.2、REQ-STG-01、NFR-02）
- 関連: [stage-format.md](./stage-format.md)、[validation.md](./validation.md)、[user-flow.md](../01-experience/user-flow.md)（S04）

## 1. 概要

S04（ステージを決める）の画面の仕様を定義する。**プリセットから選ぶだけで先に進める導線**を既定とし、**グリッドエディタ**で、自分でステージを作る・直すこともできる。配置・削除・やり直し・リセット、プリセットの選択、検証結果の見せ方を決める。

## 2. 目的

- 数分で、対戦に使えるステージを用意できる（S04 の目安は 2 分。[user-flow.md](../01-experience/user-flow.md) §7）。
- 作る時間がない、作りたくない参加者も、**プリセットを選ぶだけ**で進める（安定した運用。NFR-01）。
- 検証エラーを、中学生が読んで、自分で直せる表現にする（NFR-02）。
- ステージの作成は、体験の主役にしない。キャラクターの作成（[character-design.md](../02-fighter/character-design.md)）と同じく、短時間で終わる。

| 領域 | 内容 |
|---|---|
| プリセット | 検証済みのステージの一覧（見本の絵つき）。選ぶと、エディタに読み込まれる |

| どうぐ | ブロック、けしごむ、1Pスタート、2Pスタート |
| ボタン | 「ひとつ もどす」「ぜんぶ けす」 |
| 結果の欄 | 検証の結果（§8）。使える（✓）か、直す点が何件あるか |
| 次へ | 検証を通ると押せる。押すと、S05（試しに動かす）へ進む |
| 名前 | ステージの名前（任意）。10文字以内 |

## 5. 進み方（導線）

```text
S04 に入る
  ↓ プリセットの1つ目が、初期選択されている（すでに「つかえるよ！」）
  ├─ そのまま「つぎへ」→ S05（最短。約10秒）
  ├─ 別のプリセットを選ぶ → 「つぎへ」
  └─ 選んだステージを、エディタで直す → 検証を通ったら「つぎへ」
```

- **作らずに進める:** S04 に入った時点で、**標準のプリセットが選ばれ、検証を通った状態**にする。何も操作しなくても、「つぎへ」を押せる。
- エディタで直すのは、**任意**。プリセットの内容は、直しても、元のプリセットは変わらない（コピーで編集する）。
- 「S03（能力値）→ S04 → S05」の順（[user-flow.md](../01-experience/user-flow.md) §5）。S05 から S04 に戻ったとき、**直前に編集していたステージが、そのまま残っている**。

## 6. 操作

### 6.1 道具

| 道具 | 内容 |
|---|---|
| **ブロック** | クリックして、ブロックを置く。ドラッグすると、通った場所に、続けて置く |
| **けしごむ** | クリック、またはドラッグで、通った場所のブロックを消す |
| **1Pスタート** | クリックしたマスを、1P のスタート位置にする（前の位置は、動く） |
| **2Pスタート** | 同じく、2P のスタート位置 |

- すべて、**マウスのクリックとドラッグだけ**で操作できる（キー操作を必要としない。NFR-02）。
- 選んでいる道具が、画面で分かる（強調する）。初期の道具は「ブロック」。

### 6.2 ドラッグの規則（`oc26-stage` から引き継ぐ）

[legacy-assessment.md](../08-architecture/legacy-assessment.md) §3.7 のとおり、`oc26-stage` のドラッグの規則を使う。置いたそばから消える往復を防ぐ。

- 「ブロック」の道具で、ドラッグを始めたとき、**始めたマスにすでにブロックがあれば、そのドラッグは「消す」**、なければ「置く」と決める（ドラッグの間、変わらない）。
- 1回のドラッグで、**同じマスは1回だけ**処理する。
- 「けしごむ」は、常に「消す」。

### 6.3 置けない場所

| 場所 | 扱い |
|---|---|
| **上の 4 行**（行 0〜3） | 置けない。薄く色をつけ、「うえの 4れつは あけておこう」と表示する（[validation.md](./validation.md) の `STAGE_TOO_HIGH` を、置く前に防ぐ） |
| スタート位置のセルに、ブロック | 置けない（スタート位置は空）。スタートを動かしてから置く |
| グリッドの外 | 反応しない |

- スタート位置は、**空のセルに置く**。ブロックのセルをクリックしても、置けない。
- 置けない場所をクリックしたとき、理由を短く表示する（画面の隅に、数秒）。

### 6.4 もどす・リセット

| 操作 | 内容 |
|---|---|
| **ひとつ もどす** | 直前の1回の操作（クリック、または1回のドラッグ）を取り消す。**最大 20 回前まで**。やり直し（進む）は設けない |
| **ぜんぶ けす** | ブロックをすべて消す（スタート位置は残す）。1回の操作として、**「もどす」で戻せる**（確認の画面は出さない） |
| **プリセットから やりなおす** | いま選んでいるプリセットの、元の状態に戻す。1回の操作として、「もどす」で戻せる |

- 確認のダイアログは、出さない（待たせない）。間違えても、「ひとつ もどす」で戻せる。
- 「もどす」の履歴は、プリセットを選び直したときに、リセットされる（別のステージになるため）。S04 を離れても、保持する（S05 から戻ったとき）。

### 6.5 プリセットの選択

- 一覧から、1つをクリックして選ぶ。選ぶと、**そのステージが、エディタに読み込まれる**（編集内容は置き換わる）。
- **編集中のステージがあるとき**（プリセットから変更している）に、別のプリセットを選ぶと、変更が失われる。そのため、**「もどす」で戻せる**ようにする（確認ダイアログは出さない）。
- プリセットの数と内容は #32 で定める。**最低 3 つ**（広さ・足場の高さが違うもの）を、用意する。
- すべてのプリセットが、検証（[validation.md](./validation.md)）を通る。

### 6.6 ステージの名前

- 入力は任意。未入力のときは、デフォルト名（暫定「ステージ」）。
- 10 文字（コードポイント）以内、かつ UTF-8 で 30 バイト以内（[character-config.md](../02-fighter/character-config.md) §5.5 と同じ）。上限を超える入力は受け付けない。
- 名前は、持ち帰り用QRに入る（#60）。個人情報を入れないよう、注意書きを出す。

## 7. 表示

| 要素 | 内容 |
|---|---|
| ブロック | 塗りつぶした四角。色は、見やすいもの（#36） |
| スタート位置 | 1P と 2P の、小さなファイターの絵と、「1P」「2P」の文字（色だけに頼らない。[character-design.md](../02-fighter/character-design.md) §5.4） |
| 上の 4 行 | 薄い色で、置けないことを示す |
| 場外領域 | 薄く、ステージの外側を示す（「ここに でると たおされるよ」と、分かる説明つき。初回だけ、または、情報アイコンから） |
| 格子線 | 薄い線 |
| マウスの位置 | 今のマスを、枠で強調する。選んでいる道具に応じた、見本（置く場所のプレビュー） |
| 検証で違反したセル | 赤い枠と、記号（✕）で強調（§8） |

## 8. 検証の結果の見せ方

### 8.1 いつ検証するか

- **編集のたびに**（ブロックの配置・削除、スタート位置の変更、プリセットの選択、もどす）、検証する（[validation.md](./validation.md) §7 の `editing`）。入力が続いている間は、**200 ミリ秒の待ち**をおいて、まとめて検証する。
- 「つぎへ」を押したとき、`match` で、もう一度検証する。通らなければ、進まず、結果の欄を強調する。

### 8.2 結果の欄

| 状態 | 表示 |
|---|---|
| すべて通った | 「✓ つかえるよ！」（緑の文字だけでなく、✓ の記号つき）。「つぎへ」が押せる |
| 違反がある | 「！」の記号と、**最初の 3 件**のメッセージ（重要な順。[validation.md](./validation.md) §6）。3 件を超える分は、「ほかにも ○こ あるよ」と、まとめる。「つぎへ」は押せない |

- メッセージの文言は、[validation.md](./validation.md) §6 のとおり（ひらがな中心のやさしい日本語）。数値（あと ○こ）も表示する。
- **メッセージをクリック**すると、その違反の**場所を、ステージ上で強調**する（数秒、点滅する）。
- 違反があっても、編集は続けられる（止めない）。画面の移動（S05 へ）だけを止める。
- 「つぎへ」が押せない理由は、押せない状態のボタンの近くに、**短い案内**を表示する（「つかえる ステージに しよう」）。

### 8.3 「プリセットを つかう」の導線（行き詰まったとき）

- 違反が直せないとき、**いつでも**、結果の欄に、**「プリセットから えらびなおす」**のボタンを出す。
- 押すと、プリセットの一覧に注目が移り（強調）、選ぶと、検証済みのステージが入る（§6.5）。
- 違反が **3 件以上**あるときは、このボタンを、目立つ位置に出す（作り直しより、選び直しが早いため）。

### 8.4 例

| 状況 | 表示 |
|---|---|
| プリセットを、そのまま使う | 「✓ つかえるよ！」 |
| ブロックを 25 個に減らした | 「！ ブロックが すくないよ。あと 5こ おこう」 |
| 足場を、高さの差 +3 の位置に置いた | 「！ いけない あしばが あるよ。ジャンプで とどく ように しよう」（その足場が、赤く強調される） |
| スタートの下の足場を消した | 「！ スタートの したに ゆかが ないよ」（スタートが、赤く強調される） |

## 9. 安定運用と例外

| 場面 | 扱い |
|---|---|
| エディタの読み込みに失敗した（例外） | **プリセットの一覧だけ**の画面にする（エディタを隠す）。プリセットを選べば、先に進める |
| プリセットの読み込みに失敗した | 標準のプリセットを、コードに内蔵した形で、必ず使える（最後の拠り所） |
| 時間がなくて、作れない | S04 は、そのまま「つぎへ」で、標準のプリセットで進める。親機の指示（時間が押したとき。[event-operation.md](../01-experience/event-operation.md) §8）で、エディタを使わず、プリセットを選ぶ案内もできる |
| 一斉リセット・個別リセット | S04 の編集内容は、すべて破棄される（[user-flow.md](../01-experience/user-flow.md) §6.1.1）。S01 から、やり直す |
| ブラウザの更新（再開） | 編集内容は保持する（保存方式は #18）。履歴（もどす）は、保持しなくてよい |
| 親機のフェーズが、S04 の操作を許可しない | [event-control.md](../01-experience/event-control.md) §6 のとおり。`stage` の操作が不可のとき、編集・選択はできない（理由を表示する） |
| 再戦（S10）のとき | ステージは**変更しない**（[user-flow.md](../01-experience/user-flow.md) §5.9）。S04 には戻れない |

## 10. データと状態

```ts
type EditorState = {
  stage: StageData // 編集中の、作業用のステージ（プリセットのコピー）
  selectedPresetId: string | null // 選んでいるプリセット
  tool: 'block' | 'eraser' | 'spawn1' | 'spawn2'
  history: StageData[] // 「もどす」の履歴（最大 20）
  validation: { ok: true } | { ok: false; violations: StageViolation[] }
  dirty: boolean // プリセットから変更したか
}
```

- 作業用のステージは、**プリセットとは別の複製**。プリセットは、変更されない。
- 「つぎへ」で確定したステージは、`validateStage(stage, 'match')` を通り、セッション（#35）に保存される。確定したステージは、対戦（S07）で、**開始時に固定**される（[character-config.md](../02-fighter/character-config.md) §6 と同様）。
- 編集のロジック（配置、消去、もどす、スタート位置、ドラッグの規則）は、描画・画面から独立した純粋な関数にして、ユニットテストできる（#33）。

## 11. 時間の目安

| 経路 | 操作 | 目安 |
|---|---|---|
| プリセットをそのまま使う | 「つぎへ」だけ | 約 10 秒 |
| 別のプリセットを選ぶ | 選んで「つぎへ」 | 約 20 秒 |
| 少し直す | プリセットを選び、数か所を直す | 約 1 分 |
| 自分で作る | 「ぜんぶ けす」から作る | 約 2 分（S04 の目安） |

- 時間は画面では管理しない（[user-flow.md](../01-experience/user-flow.md) §7）。

## 12. アクセシビリティと操作

- 色だけに頼らない（記号、枠、文字を併用）。違反の強調は、赤い枠 + ✕。
- すべてのボタンに、文字のラベルがある（アイコンだけにしない）。
- マウスだけで操作できる。キーボードは、フォーカスでボタンを押せる程度（必須としない）。
- 文字は、やさしい日本語（ひらがな中心）。文言は、設定ファイルにまとめる。

## 13. Acceptance Criteria

- [ ] 配置・削除・リセット・プリセット選択の操作が定義されている（§6）
- [ ] 検証エラーの提示方法が、中学生にわかる表現になっている（§8）
- [ ] 作成をスキップして、プリセットを選ぶだけで進める導線がある（§5）
- [ ] 間違えても戻せる（もどす、リセットが戻せる）ことが定義されている（§6.4）
- [ ] 行き詰まったとき、プリセットへ戻れる導線がある（§8.3）
- [ ] エディタが使えない場合でも、先へ進める（§9）
- [ ] 編集のロジックが、ユニットテストできる形になっている（§10）
