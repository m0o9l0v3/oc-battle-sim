# ステージ形式（stage-format.md）

- 文書ID: STG-FORMAT
- バージョン: 0.1
- 状態: 草案（寸法・数値は暫定。調整は #25）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.2、REQ-STG-01）
- 関連: [validation.md](./validation.md)、[stat-system.md](../02-fighter/stat-system.md)、[battle-rules.md](../03-combat/battle-rules.md)、[legacy-assessment.md](../08-architecture/legacy-assessment.md)

## 1. 概要

ステージの寸法、グリッドの単位、データ構造（`StageData`）、座標、場外領域との関係、保存・持ち帰りのときのデータ量を定義する。検証の規則は [validation.md](./validation.md)。

## 2. 目的

- 対戦が成立する、一定の大きさのステージを、グリッドで作れるようにする（REQ-STG-01）。
- ステージ、物理（#22）、試合ルール（#12）、エディタ（#14、#33）、持ち帰りQR（#60）が、同じデータを使う。
- 前回資産 `oc26-stage` の「20列×12行のグリッド」「数値の配列」の考え方を、対戦用に作り直す（[legacy-assessment.md](../08-architecture/legacy-assessment.md) §3.7）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |

| REQ-CMB-01 | 場外で撃墜される | §7（場外領域との関係） |

## 4. 寸法と単位

| 項目 | 値 |
|---|---|
| グリッド | **24 列 × 14 行** |
| 1マス | 1 セル（長さの単位。[stat-system.md](../02-fighter/stat-system.md) §6.1 と同じ） |
| 座標の原点 | グリッドの**左上** |
| 横（x） | 右が正。列 `col`（0〜23）のセルは、`x` が `col` 以上 `col + 1` 未満 |
| 縦（y） | **下が正**（[knockback.md](../03-combat/knockback.md) §4 と同じ）。行 `row`（0〜13）のセルは、`y` が `row` 以上 `row + 1` 未満 |
| ステージの範囲 | `x` が 0〜24、`y` が 0〜14 の長方形（グリッド全体） |
| 表示される範囲 | ステージの範囲 + 場外領域（左右 6、下 6、上 8 セル）= 36 × 28 セル |

- 寸法は固定。参加者は、大きさを変えられない（作業量を抑え、検証を単純にするため）。
- 列・行の数は、設定にまとめる。変える場合は、`schemaVersion` と、検証の数値（[validation.md](./validation.md)）を見直す。
- 24 × 14 にした理由: 両者が離れて立てる広さ（スポーンの間隔 12 セル）、2段の足場が作れる高さ、場外までの余白を含めて 36 × 28 セルが画面に収まること（拡大縮小は #20）。

## 5. データ構造

```ts
type CellValue = 0 | 1 // 0: 空（何もない）、1: ブロック（足場・壁）

type Spawn = { col: number; row: number } // 足が立つセル（足場の1つ上の、空のセル）。col・row は、有限の**整数**（col 0〜23、row 0〜13）

type StageData = {
  schemaVersion: 1
  name: string // ステージの名前
  cols: 24
  rows: 14
  cells: CellValue[][] // cells[row][col]。row 0 が一番上、col 0 が一番左
  spawns: { p1: Spawn; p2: Spawn }
}
```

| 項目 | 内容 |
|---|---|
| `cells` | 14 行 × 24 列の、0 / 1 の配列。**ブロックだけ**を持つ（敵・ゴール・トゲなど、1人用のギミックは使わない。[scope.md](../00-overview/scope.md) §6） |
| ブロック | 上・横・下のすべてが、固体。ファイターは、すり抜けられない。上に乗れる（足場）。横から当たると止まる（壁）。下から当たると、頭がぶつかる（天井） |
| `spawns` | 試合の開始と、リスポーンの位置（[battle-rules.md](../03-combat/battle-rules.md) §6）。足が立つセルを指す。ファイターの足元の中心は、`(col + 0.5, row + 1)` |
| `name` | 0〜10文字（Unicode のコードポイント）かつ UTF-8 で 30 バイト以内（[character-config.md](../02-fighter/character-config.md) §5.5 と同じ規則）。未入力のときは、デフォルト名 |

- 値の種類を 2 つ（空 / ブロック）に絞るのは、物理（#22）と検証を単純にするため。将来、種類を増やす場合は、`schemaVersion` を上げる。
- ブロックの色（見た目）は、データに含めない。表示だけの設定（#36）。

## 6. 足場と空間の用語

[validation.md](./validation.md) で使う用語。

| 用語 | 定義 |
|---|---|
| 立てるセル | ブロックのセルで、**すぐ上のセルが空**のもの。ファイターが、その上に立てる（体の高さは 0.8 セルで、1マスの空きに収まる） |
| 足場 | 同じ行で、横に連続した、立てるセルのまとまり |
| 足場の幅 | 足場を作る、立てるセルの数 |
| メイン足場 | 幅が最も大きい足場 |
| 頭上の空間 | スポーンの位置の上の、3 セル（ジャンプの空間。スポーンだけに課す。[validation.md](./validation.md)） |
| 隙間（gap） | 2つの立てるセルの間にある、空の列の数 |
| 高さの差（rise） | 移る前の足場の上面の行から、移る先の上面の行を引いた値。**上向きが正**。例: 行 10 から行 8 へ移る → +2 |

## 7. 場外領域との関係

[battle-rules.md](../03-combat/battle-rules.md) §5.2 の場外領域は、ステージの範囲（本書 §4）の外側。

```text
        ← 6 →|←─────────── 24 ───────────→|← 6 →
   ┌─ 場外 ─┐        上 8 セル              ┌─ 場外 ─┐
   │         │                              │        │
   │         │      ステージの範囲 24 × 14    │        │
   │         │                              │        │
   └─────────┴──────────  下 6 セル  ────────┴────────┘
```

- ステージの範囲の外に出た体の中心が、場外領域の外に出ると、撃墜。
- グリッドの端に、壁はない。足場の端、グリッドの端を越えて、場外へ出られる。

### 7.1 撃墜までの距離 L（[combat-system.md](../03-combat/combat-system.md) §11 の確定）

このステージ寸法での、横の距離 `L`（飛び始めの位置から、場外領域の外まで）。

| 位置 | L の目安 |
|---|---|
| グリッドの端（足場の端が、グリッドの端のとき） | 6 セル |
| 標準のステージ（§8）の足場の端（列 4、20 の外側） | 10 セル |
| 標準のステージ（§8）のスポーン（列 4 と 19。体の中心は x = 4.5 と 19.5） | **10.5 セル**（左: 4.5 + 6、右: (24 − 19.5) + 6） |
| ステージの中央（x = 12） | 18 セル |

**撃墜までに必要なヒット数**（固定ステップの計算。[knockback.md](../03-combat/knockback.md) §6）:

| 攻撃側 `attackPower` | 防御側 `defense` | L = 6（グリッドの端） | L = 10.5（標準のスポーン） | L = 18（中央） |
|---|---|---|---|---|
| 5 | 5 | 6 回 | 9 回 | 13 回 |
| 8 | 2 | 4 回 | 7 回 | 10 回 |
| 8 | 5 | 5 回 | 8 回 | 11 回 |
| 5 | 2 | 5 回 | 7 回 | 11 回 |
| 2 | 5 | 6 回 | 10 回 | 14 回 |
| 5 | 8 | 7 回 | 10 回 | 15 回 |
| 2 | 8 | 8 回 | 12 回 | 17 回 |
| 8 | 8 | 6 回 | 9 回 | 13 回 |
| 2 | 2 | 5 回 | 8 回 | 12 回 |

- 最も撃墜しやすい（8 vs 2）でも、端で4回、中央で10回。1〜2回で撃墜されることはない。
- 最も撃墜しにくい（2 vs 8）は、中央で17回かかる。ヒットが続かない時間を加えると、撃墜できないことが多い。時間切れの判定（[battle-rules.md](../03-combat/battle-rules.md) §7.2）で、必ず決着する。
- 吹き飛ばされる向きは、攻撃者から離れる向き。ステージの中央付近でも、続けて当てると、端に向かって押される。実際の試合は、端の近くで決着する場面が多い（端での復帰の限界は [recovery.md](../03-combat/recovery.md) §7）。

## 8. 標準のステージの例（暫定。#32 のプリセットの出発点）

`#` はブロック、`.` は空、`1`・`2` は P1・P2 のスポーン（スポーンのセルは空）。

```text
col  000000000011111111112222
     012345678901234567890123
row 0  ........................
row 1  ........................
row 2  ........................
row 3  ........................
row 4  ........................
row 5  ........................
row 6  ..........####..........
row 7  ........................
row 8  ......####....####......
row 9  ....1..............2....
row 10 ....################....
row 11 ....################....
row 12 ....################....
row 13 ........................
```

- メイン足場: 行 10、列 4〜19（幅 16）。足場は、行 8 の左右（幅 4）と、行 6 の中央（幅 4）。
- 足場の間の高さの差は、すべて +2。[validation.md](./validation.md) の規則を満たす（到達可能性を含む）。
- ステージの下（行 13）は空で、落ちると下の場外領域に出る。

## 9. 保存と持ち帰りのデータ量

持ち帰り用QR（#60）で運ぶときの、ステージのデータ量。

| 項目 | 内容 | 長さ（Base64URL の文字数） |
|---|---|---|
| `cells` | 24 × 14 = 336 個の 0 / 1 を、**ビットにつめる**（336 ビット = 42 バイト） | 56 文字（固定） |
| `spawns` | 4 つの数値（列は 5 ビット × 2、行は 4 ビット × 2 = 18 ビット = 3 バイト） | 4 文字（固定） |
| `schemaVersion` | 1 | 1〜2 文字 |
| `name` | UTF-8 で最大 30 バイト | 最大 40 文字 |
| **合計（最悪）** | | **約 100 文字** |

- 行列の長さの圧縮（RLE）は使わない。最悪の場合（0 / 1 が交互）、RLE は 336 文字になり、ビットづめの 56 文字より大きくなる。**ビットづめなら、どんなステージでも、同じ長さ**になる（QRの長さの見積もりが固定できる）。
- ファイター（`CharacterConfig`）の最悪値と合わせた、QR全体の長さの上限は、#60 で確認する。

## 10. 読み込み（外部から）

- 持ち帰り用QRなど、外部から読み込んだステージは、[validation.md](./validation.md) の検証を、すべて通す。
- 形式が壊れている（長さ・値）、検証を通らない場合は、**失敗を画面で伝え**、標準のステージ（§8）で始める（[character-config.md](../02-fighter/character-config.md) §5.4 と同じ方針）。部分的な復元はしない。
- 復号の関数は、例外を投げず、失敗を返す。標準のステージにする判断と、画面への表示は、呼び出し側が行う。

## 11. 例外・制約

| 場面 | 扱い |
|---|---|
| 行・列の数が違う | 無効（`MALFORMED`）。編集では起こらない |
| `cells` に 0・1 以外 | 無効（`MALFORMED`） |
| スポーンが範囲外 | 無効（検証 `SPAWN_OUT_OF_RANGE`。[validation.md](./validation.md)） |
| 空のステージ | 検証で拒否される（足場の量。[validation.md](./validation.md)） |
