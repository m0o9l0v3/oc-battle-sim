# キャラクターデザインとカスタマイズ仕様（character-design.md）

- 文書ID: FTR-DESIGN
- バージョン: 0.1
- 状態: 承認済み（個数・方針。絵柄のラフは #28 で制作）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§5.3、REQ-FTR-03、REQ-FTR-05、REQ-FTR-06、NFR-05、NFR-07）
- 関連: [character-config.md](./character-config.md)、[stat-system.md](./stat-system.md)、`animation.md`（#10）

## 1. 概要

ファイターの見た目（オリジナルの2Dキャラクター）の、パーツ構成、カスタマイズの選択肢、能力値による視覚フィードバック、図形の貼り合わせに見えないための品質基準、カスタマイズ画面（S02）の操作を定義する。

## 2. 目的

- 参加者が、**30〜60秒**で、自分のファイターだと思える見た目を作れるようにする（REQ-FTR-06）。キャラクター作成を、体験の主役にしない。
- 円や四角を貼り合わせただけではない、オリジナルのキャラクターとして認識できる水準にする（REQ-FTR-03、NFR-05）。
- 少数の再利用可能なパーツで、制作の量を抑える（設計原則 7）。
- 既存作品のキャラクター・素材に似せない（NFR-07）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-FTR-03 | オリジナルの2D外観。図形の貼り合わせを避ける | §7（品質基準）、§8（独自性） |
| REQ-FTR-04 | 少数のパーツの移動・回転・拡大縮小でアニメーション | §4（パーツ構成と関節） |

| NFR-05 | オリジナルのキャラクターとして認識できる視覚品質 | §7 |
| NFR-07 | 既存作品の素材・意匠を使わない | §8 |

## 4. パーツ構成

### 4.1 パーツ一覧

ファイターは、次のパーツを重ねて描く。アニメーション（#10）は、パーツの移動・回転・拡大縮小で行う。

| パーツ | 数 | 内容 |
|---|---|---|
| 頭（head） | 1 | 輪郭と髪・耳など。顔（face）を載せる面を持つ |
| 胴体（torso） | 1 | 胴。腕・脚・頭の付け根を持つ |
| 腕（arm） | 左右 | 1つの絵を反転して、左右に使う（奥・手前で影の濃さを変える） |
| 脚（leg） | 左右 | 同上 |
| 顔（face） | 1 | 目・口。表情の切り替えに使う（§4.3） |
| アクセサリー（accessory） | 0〜1 | 帽子・目の周り・首・背中のいずれかに付ける飾り（§5.2） |

### 4.2 重ね順と関節

奥から手前への重ね順:

```text
背中のアクセサリー → 奥の腕 → 奥の脚 → 胴体 → 手前の脚 → 頭 → 顔 → 手前の腕 → 頭・顔・首のアクセサリー
```

- アクセサリーは、付ける場所（**スロット**）ごとに、重ねる位置が違う。
  - **背中（back）**: いちばん奥。胴体の後ろに隠れて、背中に付いているように見える。
  - **頭（head）・顔（face）・首（neck）**: いちばん手前。
- スロットは、アクセサリーのIDごとに決まっている（§5.1.1）。

アニメーション用の回転の中心（関節）を、パーツごとに持つ。

| パーツ | 関節 |
|---|---|
| 頭 | 首の付け根 |
| 腕 | 肩 |
| 脚 | 股の付け根 |
| 胴体 | 腰（全体の基準点。足元の中心を、当たり判定の足元に合わせる） |

- 関節の位置は、体型（§5.1）ごとに持つ。動きの定義は #10。

### 4.3 顔の表情

- 顔は、通常の表情（選択肢ごとに異なる絵）と、**全員共通の表情**（攻撃、やられ、撃墜）を持つ。
- やられ・撃墜などの表情は、全員共通の絵にして、顔の選択肢ごとには描かない（制作量の削減）。通常の顔と同じ位置・大きさに重ねる。

### 4.4 色の適用

- 絵は、**色の枠**（主色、副色、差し色）に分けて描き、色の選択肢（§5.2）で塗り替える。色ごとの絵は用意しない。
- 肌・目・輪郭線など、色の選択で変えない部分は、共通の色にする。

## 5. カスタマイズ

### 5.1 選択肢

| 項目 | 選択肢の数 | `CharacterConfig.appearance` の項目 | 内容 |
|---|---|---|---|
| 体型（Body） | 4 | `body` | 頭・胴体・腕・脚のセット。輪郭が違う |
| 顔（Face） | 6 | `face` | 目・口の組み合わせ |
| 色（Color） | 8 | `color` | 主色・副色・差し色の組。色の枠に当てる |
| アクセサリー（Accessory） | 6（+ なし） | `accessory` | 飾り。付けない選択もできる |
| 名前（Character Name） | 自由入力 | `name` | 10文字以内（[character-config.md](./character-config.md) §5.5） |

- 組み合わせは、4 × 6 × 8 × 7 = 1,344 通り。
- ID は、短い文字列にする。**使ってよいIDは、§5.1.1 の一覧がすべて**（これ以外は、検証で `APPEARANCE_UNKNOWN`）。QRのデータ量を抑えるため（[character-config.md](./character-config.md) §8.1）。
- 組み合わせの数は、各項目の選択肢の数の**積**なので、選択肢を増やすと、必ず増える（例: 体型を5にすると 1,680 通り）。選択肢を増やす場合の規則:
  - **一度に増やす項目は、1つだけ**にする（素材と確認の量を抑えるため）。
  - 追加するIDは、**末尾に追加**する（`b5`、`f7` など）。**既存のIDの意味を変えたり、削除したIDを別の用途に使い回したりしない**（過去のQRを、別の見た目として復元しないため）。
  - 追加・削除したときは、§5.1.1 の一覧と、`schemaVersion`（[character-config.md](./character-config.md)）の扱いを、変更履歴に記録する。

### 5.1.1 IDの一覧（規範）

検証（[character-config.md](./character-config.md) §5.2 の `APPEARANCE_UNKNOWN`）と、持ち帰りの復元は、この一覧だけを、許可するIDとして使う。

| 項目 | 許可するID | 備考 |
|---|---|---|
| `body` | `b1`、`b2`、`b3`、`b4` | 体型。必須（`null` は不可） |
| `face` | `f1`、`f2`、`f3`、`f4`、`f5`、`f6` | 顔。必須 |
| `color` | `c1`、`c2`、`c3`、`c4`、`c5`、`c6`、`c7`、`c8` | 色の組。必須 |
| `accessory` | `a1`、`a2`、`a3`、`a4`、`a5`、`a6`、`null` | `null` は、付けない |

アクセサリーのスロット（§4.2）:

| ID | 付ける場所（スロット） | 例（絵柄は #28） |
|---|---|---|
| `a1` | 頭（head） | 帽子 |
| `a2` | 顔（face） | ゴーグル |
| `a3` | 首（neck） | マフラー |
| `a4` | 頭（head） | リボン |
| `a5` | 頭（head） | ヘッドホン |
| `a6` | 背中（back） | 背中の飾り |

- 名前や絵柄の説明は、#28 で決める。IDとスロットは、ここで固定する。

### 5.2 選択肢の方針

| 項目 | 方針 |
|---|---|
| 体型（4） | シルエットがはっきり違う4種。全体の大きさ（当たり判定）は、同じ。例の方向性: 丸みのある、角のある、細長い、がっしりした。個別の名前と絵は #28 で決める |
| 顔（6） | 表情の印象が違う6種（元気、にやり、きりっ、のんびり、びっくり、ねむそう など） |
| 色（8） | 色相が違う6色と、明暗が違う2色。色だけで1P・2Pを見分けさせない（§5.4） |
| アクセサリー（6） | 帽子・ゴーグル・マフラー・リボン・ヘッドホン・背中の飾り（例）。体型を変えても付く位置を持つ |

- 選択肢の具体的な絵柄・名前は #28（パーツ素材の制作）で決める。本書は、**数と性質**を決める。

### 5.3 初期値

| 項目 | 1P | 2P |
|---|---|---|
| 体型 | `b1` | `b1` |
| 顔 | `f1` | `f2` |
| 色 | `c1` | `c2`（1P と明確に違う色） |
| アクセサリー | なし | なし |

- 初期値のままでも、対戦できる状態にする。選択は、すべて任意。
- 2P の見た目は、**初期値のまま**（対戦相手は標準設定で始まり、変更できるのは能力値のみ。[user-flow.md](../01-experience/user-flow.md) §5.6、§5.9）。**2P 側で、見た目を選べる画面は設けない**（上位の体験フローを変えない限り、固定）。

### 5.4 1P と 2P の見分け

- 画面上で、頭の上に、**「1P」「2P」の目印**を表示する（色だけに頼らない）。
- 初期値の色は、色覚の違いでも見分けられるよう、明るさも変える。

## 6. 能力値と外観の関係

**能力値の違いは、外観には反映しない**（所有者の決定。2026-10-04）。能力値の違いは、**数値と、ゲーム内の動き**だけで示す。

### 6.1 理由

- 本体験の中心は、**数字を入力して値を変えると、動きが変わる**という、プログラミングの体験である（system-overview.md §1）。
- 外観が能力値で変わると、「数字を変えた結果」が、動きではなく見た目の変化として受け取られ、観察の対象がぶれる（設計原則 2）。
- 外観は、参加者が自分で選ぶ（§5）。能力値の大小で、見た目が強そう・弱そうに変わることを避ける。

### 6.2 決めたこと

- 外観（体型・顔・色・アクセサリー）は、**能力値と無関係**。能力値を変えても、外観は変わらない。
- 能力値の違いは、設定画面（S03）の数値と標準比の表示（[stat-system.md](./stat-system.md) §9）、およびゲーム内の動き（移動、ジャンプ、ダメージ、吹き飛び）で観察する。
- **当たり判定は、全員同じ**（[stat-system.md](./stat-system.md) §6.1）。外観によって変わらない（REQ-FTR-05）。
- 将来、能力値の視覚フィードバックを入れる場合は、REQ-FTR-05（視覚のみ、当たり判定を変えない）に従い、この決定を、本書の変更履歴に理由とともに記録して変更する。

## 7. 品質基準（図形の貼り合わせに見えないこと）

### 7.1 絵の基準

| 項目 | 基準 |
|---|---|
| 輪郭 | すべてのパーツに、一貫した輪郭線（太さ・色のルール）がある |
| 形 | 頭・胴体・腕・脚は、**円・四角・三角などの基本図形そのままではなく**、それぞれの特徴を持つ形で描く |
| 陰影 | 少なくとも2段階の陰影（明・暗）をつける |
| 手足 | 腕・脚に、関節の曲がりと、手先・足先の形がある |
| 顔 | 目・口に、表情として読み取れる形と、大きさの差がある |
| 統一 | 全パーツで、線の太さ、陰影のつけ方、角の丸め方が統一されている |
| シルエット | 黒く塗りつぶしても、体型4種を見分けられる |

### 7.2 確認の方法

- **見た目の確認:** 実際の表示の大きさ（画面上のファイターの大きさ）で、2人以上が見て、「図形を貼り合わせたものに見えない」と判断する。
- **全体の確認:** 体型4種 × 顔6種 × 色8種の代表的な組み合わせ（最低でも、体型ごとに2組）を、並べて確認する。
- **アニメーションでの確認:** Idle、Run、Jump、Fall、Attack、Hit、KO（#10）の各状態で、パーツの継ぎ目が目立たない。
- 確認の結果は、#28 の受入条件に記録する。

### 7.3 画面上の大きさ

- ファイターの見た目の大きさは、ステージのマスの大きさ（#13）に対して、**当たり判定の大きさとおおむね一致**させる（差は ±15% 以内）。
- 絵の元データは、画面上の大きさの **2倍以上**の解像度、またはベクター形式（SVG）にする（拡大・高解像度の画面でも崩れないため）。

## 8. 独自性

- 体型・顔・アクセサリー・色・名前に、既存のゲームやアニメのキャラクターを連想させる意匠を使わない（NFR-07）。
- 特定の既存作品のキャラクターに似せた、帽子、服、髪型、配色の組み合わせをしない。
- 制作した素材は、#50（権利チェック）で、出所とライセンスを確認する。
- 名前の例や、デフォルト名にも、既存作品の名前を使わない。

## 9. カスタマイズ画面（S02）

### 9.1 画面

- 1画面に、**4つの選択（体型・顔・色・アクセサリー）と、名前の入力**を並べる。画面を移動しない。
- 選んだ結果を、**大きなプレビュー**に、即時に反映する。プレビューは、Idle のアニメーションで動く（見た目の確認がしやすい）。
- すべての項目に、**初期値が選ばれた状態**で始める（何も選ばなくても進める）。
- 「ランダム」ボタンで、4つの選択をまとめてランダムにできる（時間のない参加者のため）。
- 「つぎへ」で、S03（能力値）へ進む。

### 9.2 時間の目安

目標は 30〜60 秒。

| 操作 | 目安 |
|---|---|
| 体型を選ぶ | 約10秒 |
| 顔を選ぶ | 約10秒 |
| 色を選ぶ | 約10秒 |
| アクセサリーを選ぶ | 約10秒 |
| 名前を入れる（任意） | 約15秒 |

- 合計で、約55秒。ランダム、または初期値のままなら、10秒以内に進める。
- 時間の管理は、画面では行わない（[user-flow.md](../01-experience/user-flow.md) §7）。

### 9.3 操作の制約

- 選択は、クリックのみ（マウス）。ドラッグや、細かい操作を必要としない。
- 名前は、**10文字（Unicode のコードポイント）以内、かつ UTF-8 で30バイト以内**（[character-config.md](./character-config.md) §5.5）。**両方の上限を、この画面で守らせる**: 上限を超える入力は、受け付けない（入力できない）。残りの文字数を表示し、4バイトの絵文字など、バイト数が多い文字を使うと、10文字より少なく入力が止まることを、短く表示する。上限を超えた名前が、対戦開始や持ち帰りで、`NAME_TOO_LONG` になることがないようにする。入力欄に注意書きを出す（「ほんとうの なまえは いれないでね」など。名前は持ち帰り用QRのURLに入る。#60）。
- 名前が未入力のときは、デフォルト名で進める。

## 10. 状態遷移

```text
S02 見た目を選ぶ（編集中）
  ↓ つぎへ
S03 能力値を決める
  ↓（S03 から S02 へ戻れる。入力済みの内容は保持）
```

- 外観は、**対戦の開始時に固定**される（[character-config.md](./character-config.md) §6）。再戦では変更しない。

## 11. 例外・制約

| 場面 | 扱い |
|---|---|
| 選択肢のIDが未知（古いデータ、外部から読み込んだ設定） | **設定全体を破棄**し、失敗を画面で伝えたうえで、標準の設定で始める（[character-config.md](./character-config.md) §5.4）。IDだけを初期値に置き換えて、名前や能力値を残すことはしない（能力値の合計の整合を保つため）。編集中の画面では、未知のIDは選べない |
| 体型を変えたとき、付けていたアクセサリーの位置がずれる | 体型ごとのアクセサリーの付け位置で、自動で合わせる |
| 色の組み合わせが、背景で見えにくい | 色の8種は、ステージの背景に対して、見分けられる明るさ・濃さにする（#28 で確認） |

## 12. 制作する素材の数（#28 の見積もり）

| 区分 | 数 | 内容 |
|---|---|---|
| 体型 | 4 | それぞれ、頭・胴体・腕・脚（腕・脚は左右で反転）= 16 点 |
| 顔 | 6 | 通常の表情 |
| 共通の表情 | 3 | 攻撃・やられ・撃墜（全員共通） |
| アクセサリー | 6 | 体型ごとの付け位置を持つ |
| 色 | 8 | 色の枠（主色・副色・差し色）の組。絵は用意せず、数値で持つ |
| 合計 | 31 点 | 能力値の差し色は作らない（§6） |

## 13. Acceptance Criteria

- [ ] パーツ（頭・胴体・左右の腕と脚・顔・アクセサリー）の構成と、選択肢の数が確定している（§4、§5.1）
- [ ] カスタマイズ操作が、30〜60秒で完了する設計になっている（§9）
- [ ] 能力値による外観の変化を設けないこと、当たり判定が全員同じであることが明記されている（§6）
- [ ] 図形の貼り合わせに見えない品質基準と、確認の方法が示されている（§7）
- [ ] 既存作品に似せないための方針が示されている（§8）
- [ ] 1P と 2P の見分けが、色だけに頼らない（§5.4）
- [ ] 制作する素材の数が見積もられている（§12）
