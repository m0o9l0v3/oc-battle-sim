# バランス調整の記録（balance.md）

- 文書ID: CMB-BALANCE
- バージョン: 0.1
- 状態: 草案（基準ボットのシミュレーションによる。実機の対戦での確認は #51、#52）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（REQ-EXP-02、REQ-FTR-01）
- 関連: [stat-system.md](../02-fighter/stat-system.md)、[damage.md](./damage.md)、[knockback.md](./knockback.md)、[recovery.md](./recovery.md)、[battle-rules.md](./battle-rules.md)、[combat-system.md](./combat-system.md)
- 関連Issue: #25（本書）、#22、#23、#24

## 1. 概要

標準設定と極端な配分で、実装した試合（`src/battle/`）を最後まで進め、**どの配分でも対戦が成立し、特定の配分が常に勝たず、能力値の違いが観察できる**ように、係数を調整した。調整前の結果、調整の理由、調整後の結果を記録する。

## 2. 目的

- 代表的な配分の対戦結果を、記録する。
- 特定の配分が、勝ち続けない（または負け続けない）ようにする（REQ-FTR-01。性能差は、能力値だけから生じ、一つの正解にならない）。
- 能力値の違いが、結果と動きに、観察できる大きさで現れるようにする（REQ-EXP-02）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-EXP-02 | 設定値の違いが、対応する挙動に反映される | §6（違いの大きさ） |
| REQ-FTR-01 | 性能差は、能力値から生じる | §5（配分ごとの勝率） |
| REQ-CMB-01 | ダメージ蓄積 → 吹き飛び → 場外 → 撃墜 | §5（決着の内訳） |

## 4. 方法

### 4.1 シミュレーション

`src/battle/balance.ts`。実装した `stepMatch`（試合の進行、物理、戦闘、撃墜、リスポーン、勝敗）を、そのまま使い、READY から END まで、1試合を進める。

| 項目 | 内容 |
|---|---|
| ステージ | 標準のステージ（[stage-format.md](../04-stage/stage-format.md) §8） |
| 試合のルール | 標準（ストック 3、制限時間 90 秒。[battle-rules.md](./battle-rules.md)） |
| 操作する側 | **基準のボット**。両者が同じ方針で動く（能力値の違いだけが、結果の差になる）。簡易CPU（#72）とは別の、調整専用の部品 |
| 対戦の組み合わせ | 配分 A と B を、**左右（スポーンの位置）を入れ替えて**、20 通りのシードで対戦（1組あたり 40 試合） |
| 乱数 | シードつきの疑似乱数（同じシードから同じ結果。決定的） |
| 勝率 | 勝ち 1、引き分け 0.5、負け 0 として、他のすべての配分との対戦の平均（%） |

### 4.2 基準のボットの方針

| 場面 | 動き |
|---|---|
| 通常 | 相手に近づく。攻撃が届く距離（約 0.95 セル、同じ高さ）で止まり、4 ステップごとに、7割の確率で攻撃する（残りは見送る） |
| 相手が攻撃を出している（発生・持続） | 6割の確率で、届かない距離まで下がる（見切り）。**移動速度が高いほど、有利になる** |
| 相手が高い足場にいる | 近づいて、跳ぶ |
| 高さが違う相手の近くで動けない | 少し離れて、位置を取り直す（足場を回り込む） |
| 場外にいる | ステージの中央へ向かう。落ちている間に、空中ジャンプ（回数が残っているとき） |

### 4.3 限界

- ボットは、人の操作の代わりにはならない。**能力値の価値（特に、速さ・ジャンプの価値）は、操作のしかたで、大きく変わる**。この結果は、「同じ方針で動く場合の、相対的な強さ」の目安。
- ステージは、標準の1つだけ（プリセット #32 が増えたら、再確認する）。
- 勝率の誤差は、1配分あたり約 ±5 ポイント（試合数による）。差が 5 ポイント以下の違いは、意味を持たせない。
- 実機（会場のPC、中学生・保護者の対戦）での確認は、#51、#52 で行う。

## 5. 結果

### 5.1 調整前（係数をすべて 0.10 にした場合）

代表的な 11 の配分の、平均の勝率（%）。

| 配分（攻/防/跳/速） | 調整前 | 調整後 |
|---|---|---|
| 5/5/5/5（標準） | 44（10） | 51（33） |
| 8/2/5/5（攻撃特化） | 46（9） | 48（23） |
| 2/8/5/5（耐久特化） | 46（8） | 45（28） |
| 5/5/8/2（ジャンプ特化） | 48（20） | 48（28） |
| 5/5/2/8（スピード特化） | **73**（39） | 59（40） |
| 8/8/2/2（攻守特化） | **84**（61） | 67（48） |
| 2/2/8/8（機動特化） | **21**（5） | 46（30） |
| 6/6/4/4 | 60（18） | 53（24） |
| 4/4/6/6 | 29（3） | 38（21） |
| 3/3/7/7 | 26（6） | 40（18） |
| 7/7/3/3 | 74（23） | 56（40） |

（括弧の中は、他の 10 の配分のうち、**最も分が悪い相手との勝率**。調整前は、8/8/2/2 が、どの相手にも 61 % 以上で勝ち（無敗）、2/2/8/8 などは、どの相手にも勝ち越せなかった。調整後は、**どの配分も、勝ち越せない相手が、いる**（括弧の値が、すべて 50 % 未満）。）

調整前の問題:

- **攻撃と防御を同時に高める配分（8/8/2/2、7/7/3/3）が、勝ち続けた**（84 %、74 %）。攻撃は与えるダメージを、防御は吹き飛ばされる量を変える。2つが同じ向きに効くため、撃墜までの差が、積み重なる。引き換えの、速さとジャンプの低下（×0.7）は、小さかった。
- **速さを高めた配分（5/5/2/8）が、勝った**（73 %）。基準のボットでも、見切りと差し込みで、移動速度の差が、有利に働いた。
- 逆に、**速さとジャンプを高めて、攻撃と防御を下げた配分（2/2/8/8）は、負け続けた**（21 %）。

### 5.2 調整

| 係数 | 調整前 | 調整後 | 理由 |
|---|---|---|---|
| `K_attack` | 0.10 | **0.04** | 攻撃と防御の効きを小さくして、速さ・ジャンプとの釣り合いを取る |
| `K_defense` | 0.10 | **0.04** | 同上 |
| `K_speed` | 0.10 | **0.075** | 速さの有利を、少し減らす |
| `K_jump` | 0.10 | 0.10（変更なし） | 下げると、最小のジャンプ高さ（約 1.18 セル）が、ステージ検証の基準を下回る。上げると、最小が下がる |

探索した範囲（シミュレーションで、11 配分の平均の勝率の、最大・最小と、無敗の配分の有無を比べた。1組あたりの試合数は、序盤の探索が 16、後半が 40）:

| `K_attack`・`K_defense` | `K_speed` | `K_jump` | 平均の勝率の範囲 | 無敗の配分 | 判断 |
|---|---|---|---|---|---|
| 0.10 | 0.10 | 0.10 | 21〜84 % | 8/8/2/2（最も分が悪い相手にも 61 %） | 調整前。偏りが大きい |
| 0.06 | 0.10 | 0.10 | 34〜70 % | 速さ・攻守の特化が強い | 速さが勝つ |
| 0.06 | 0.05 | 0.10 | 25〜80 % | 8/8/2/2 | 速さが、価値を失い、攻守特化が勝つ |
| 0.05 | 0.075 | 0.10 | 37〜71 % | **8/8/2/2（55 %）** | 攻守特化が、無敗のまま |
| 0.04 | 0.08 | 0.10 | 36〜68 % | **5/5/2/8（61 %）** | 速さが、無敗になる |
| 0.03 | 0.075 | 0.10 | 40〜58 % | なし | 勝率は均等だが、攻撃・防御の差が小さすぎる（±9 %）。違いが観察できない |
| **0.04** | **0.075** | **0.10** | **38〜67 %** | **なし** | **採用**。無敗の配分がなく、差が観察できる（±12 %） |

- 勝率を、さらに平らにするには、攻撃・防御の係数を、さらに下げればよいが、**差が小さくなり、能力値の違いが観察できなくなる**（§6）。観察できることと、偏らないことの、折り合いとして、0.04 を採った。
- `K_speed` を下げると、最小の移動速度は、2.63 から 2.91 セル/秒に上がる。ステージ検証の到達可能性（[validation.md](../04-stage/validation.md) §5）は、**より安全側になる**（飛べる距離が伸びる。許す隙間の規則は変えない）。

読み取り:

- **特定の配分が、常に勝つ・常に負ける状態ではない。** 7 つの配分のすべてが、少なくとも 1 つの配分に負けている（11 配分の総当たりでも、無敗の配分はない。§5.1）。
  - 最も強いのは、攻守特化（8/8/2/2。平均 67 %）。ほとんどの相手に勝つが、**スピード特化には負ける**（19 勝 21 敗）。ジャンプ特化にも、拮抗する（24 勝 15 敗）。
  - 標準は、攻撃特化（13 勝 27 敗）と、攻守特化（13 勝 27 敗）に負けるが、耐久特化・ジャンプ特化・スピード特化には勝つ。
  - **勝ち負けの循環**がある（例: 攻撃特化は、攻守特化に負け、耐久特化に負け、ジャンプ特化に負ける一方、標準とスピード特化・機動特化に勝つ）。
- 能力値の違いは、結果に出ている（耐久特化は、攻撃特化には勝つが、この 7 配分のほかの相手には負けやすい。攻撃特化は、耐久特化に負け、スピード特化・標準には勝つ、など）。
- **ストックを奪い切って決着する試合は、全体で約 26 %（216/840）。** 残りは、時間切れの判定（ストック → 蓄積ダメージ）で決まる。[battle-rules.md](./battle-rules.md) §8 の見込み（多くの試合が、時間切れの前に決着する）は、基準のボットでは、成り立たなかった。人の操作では、攻撃が当たる頻度が違う可能性があるため、会場のリハーサルで確認する（#52）。
- 引き分け（時間切れで、完全に同じ）は、全体の約 1 %（12/840）。

### 5.4 極端な配分でも、対戦が成立する

- 全 231 通りの配分で、**端で 1 回ヒットを受けても、撃墜されない**（復帰できる蓄積ダメージの上限が、最小でも約 41 %。1回のダメージの最大は 13.44 %）。[recovery.md](./recovery.md) §7.3。
- 最も撃墜しにくい組み合わせ（`attackPower` 2 × `defense` 8）でも、**10〜14 回**のヒットで撃墜できる（標準どうしの約 1.3〜1.4 倍。調整前は 2.2〜2.4 倍）。[combat-system.md](./combat-system.md) §11。
- 時間切れでも、必ず勝敗が決まる（同じ場合のみ引き分け。[battle-rules.md](./battle-rules.md) §7.2）。

## 6. 能力値の違いが観察できるか

| 能力値 | 最小（2）〜最大（8） | 標準比 | 観察できる場所 |
|---|---|---|---|
| `attackPower` | 1回のダメージ 10.56 〜 13.44 % | ×0.88 〜 ×1.12 | Battle Report の「1かいの ダメージ」、ヒットのたびに増える数値 |
| `defense` | 吹き飛ぶ速さ ×1.12 〜 ×0.88。60 % のとき 7.4 〜 4.5 セル | ×1.12 〜 ×0.88 | Battle Report の「ふっとぶ きょり」（距離では約 1.6 倍の差）、実際の吹き飛び方 |
| `jumpPower` | ジャンプの高さ 1.18 〜 2.19 セル | ×0.70 〜 ×1.30 | ジャンプの高さ（約 1.9 倍の差。見て分かる） |
| `speed` | 移動速度 2.91 〜 4.59 セル/秒 | ×0.775 〜 ×1.225 | 走る速さ・走りのアニメーションの速さ（約 1.6 倍の差。見て分かる） |

- `jumpPower` と `speed` の差は、画面で見て分かる大きさ。
- `attackPower` と `defense` の差は、標準比で ±12 %。**画面の動きだけでは分かりにくい**が、Battle Report の数値（「1かいの ダメージ 12.0 → 13.0」「ふっとぶ きょり 5.9 → 4.5」）と、撃墜までのヒット数の違い（標準どうし 7〜11 回、攻撃 8 対 防御 2 は 5〜8 回、攻撃 2 対 防御 8 は 10〜14 回）で、観察できる。画面での見え方（数値の見せ方）の確認は、#38、#39、#34 の実装時に行う。

## 7. 今後の確認

| 項目 | 内容 | 担当 |
|---|---|---|
| 人の操作での確認 | 攻守特化（調整後も、最も強い。平均 67 %。スピード特化には、わずかに負ける）が、実際の対戦でも、勝ち続けないか。続くなら、`K_attack`・`K_defense` を、さらに下げる（0.03）か、攻守の両方を高める配分に、別の引き換え（例: 上限の合計）を設ける | #51、#52 |
| ステージを増やしたとき | プリセット（#32）で、同じ総当たりを、再実行する | #32、#31 |
| 決着の割合 | 会場のリハーサルで、ストック決着の割合を確認する（シミュレーションでは約 25 %） | #52 |
| 見え方 | `attackPower`・`defense` の差（±15 %）が、数値と動きで、伝わるか | #34、#38、#39 |

### 7.1 再実行の方法

```bash
# 係数を変えたときの検査（11 配分の総当たり。数十秒〜1 分）
BALANCE_CHECK=1 npx vitest run src/battle/balance.test.ts

# 総当たりの表と、調整前・調整後の平均の勝率を、console に出す（この文書に転記する）
BALANCE_REPORT=1 npx vitest run src/battle/balance.test.ts
```

係数を変えたら、この表と、関連する文書の数値（[stat-system.md](../02-fighter/stat-system.md) §6、damage.md、knockback.md、combat-system.md §11、stage-format.md §7.1、recovery.md §7、validation.md §5）を、合わせて更新する。

- **通常のテスト（`npm test`）では、重い総当たりを実行しない**（CI を遅くしないため）。軽い検査（標準 × 6 つの特化配分、各 4 シード）だけを実行し、すべての試合が決着し、両方に勝ち負けがあることを確かめる。
- `BALANCE_CHECK=1` の検査は、**11 の配分の、平均の勝率が 30 % より大きく 70 % より小さいこと**と、**どの配分にも、勝ち越せない相手がいること（無敗の配分がない）**を確かめる。係数・ルール・ステージを変えたとき、リリースの前に、実行する。
