# 試合ルール（battle-rules.md）

- 文書ID: CMB-RULES
- バージョン: 0.1
- 状態: 草案（数値は暫定。調整は #25）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.1、REQ-CMB-01、REQ-EXP-03）
- 関連: [combat-system.md](./combat-system.md)、[recovery.md](./recovery.md)、[user-flow.md](../01-experience/user-flow.md)

## 1. 概要

1対1の試合の流れ、ストック数、制限時間、場外（撃墜）の判定、リスポーン（無敵時間を含む）、勝敗、引き分け、1試合の想定時間を定義する。復帰（ステージに戻る動き）は [recovery.md](./recovery.md)。

## 2. 目的

- 「ダメージ蓄積 → 吹き飛び → 場外 → 撃墜」で勝敗が決まる試合を、完結した形にする（REQ-CMB-01）。
- 勝敗と結果を確認できる（REQ-EXP-03）。
- **1試合を、体験フローの時間配分（約2分）に収める**（[user-flow.md](../01-experience/user-flow.md) §7）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-CMB-01 | ダメージ蓄積 → 吹き飛び → 場外 → 撃墜 | §5、§6 |

| REQ-OPS-01 | 会場で短時間に運用できる | §8（1試合の時間） |

## 4. 試合の流れ

```text
READY（準備・カウントダウン）
  ↓ 3秒
FIGHT（対戦）  ← 制限時間が進む
  ↓ 決着（全ストック喪失 / 時間切れ）
END（結果の表示）
  ↓ 約3秒
Battle Report（S08）または 結果の比較（S11）へ
```

| 区間 | 内容 | 時間 |
|---|---|---|
| READY | 両者は、スポーン位置に立つ。操作できない。「3・2・1・スタート」を表示 | 3 秒（180 ステップ） |
| FIGHT | 対戦。制限時間が、1ステップごとに減る。ヒットストップ中も、時間は進む | 最大 90 秒 |
| END | 勝敗を表示。両者は操作できない | 約 3 秒 |

- 制限時間は、**FIGHT の間だけ**進む（READY、END では進まない）。
- 一時停止の操作は設けない（MVP）。親機の一斉リセット（`event-control.md`）が来たときは、試合を中断して S01 に戻り、結果は残さない。

## 5. ストックと撃墜

### 5.1 ストック

| 項目 | 値 |
|---|---|
| 初期のストック数 | **3** |
| 撃墜されたとき | ストックが 1 減る |
| ストックが 0 | その試合の負け（相手が勝ち） |

- 画面に、ストック数を、アイコンで表示する。

### 5.2 場外（撃墜）の判定

ステージの範囲（グリッド全体。#13）の外側に、**場外領域**を設ける。ファイターの**体の中心**が、場外領域の外（外側）に出たら、撃墜。

| 方向 | 場外までの余白（ステージの範囲の外側） |
|---|---|
| 左右 | 6 セル |
| 下 | 6 セル |
| 上 | 8 セル |

- 余白は、設定にまとめる。ステージの寸法（#13）が決まったら、[combat-system.md](./combat-system.md) §11 の距離 L を、実際の値で見直す。
- 画面は、場外領域まで表示する（撃墜の瞬間が見える）。表示の拡大縮小は #20。
- 撃墜の原因は、**1つだけ**記録する（`blast_left`、`blast_right`、`blast_top`、`blast_bottom`）。
- **角で、同じステップに、横と縦の境界を同時に越えたとき**の分類（実装によって、記録が変わらないように、次の順で決める）:
  1. 前のステップの位置から今の位置までの**直線の移動**が、場外領域の境界と、**先に交わったほう**を、原因とする。
  2. 同時に交わる（ちょうど角を通る）、または、先後が判定できないときは、**下 → 上 → 左 → 右**の順で、最初に当てはまるものを、原因とする（`blast_bottom` > `blast_top` > `blast_left` > `blast_right`）。
  - 撃墜の判定そのもの（撃墜になること）は、どちらの境界でも同じ。原因だけが、Battle Report の記録に影響する。

### 5.3 同じステップで、2人とも撃墜

- 両方のストックが 1 ずつ減る。
- そのあとの勝敗は §7 に従う。

### 5.4 撃墜の演出

- 撃墜されると、KO のアニメーション（900 ms。[animation.md](../02-fighter/animation.md) §5.7）になる。操作できない。

## 6. リスポーン

### 6.1 流れ

```text
撃墜 ─ 1.5 秒（90 ステップ。KO の演出を含む）─▶ リスポーン（ストックが残っていれば）
```

| 項目 | 規則 |
|---|---|
| 待ち時間 | 撃墜から **1.5 秒**（90 ステップ） |
| 位置 | その参加者の**スポーン位置**（#13）。試合の開始時と同じ場所 |
| 向き | ステージの中央を向く |
| 蓄積ダメージ | **0 %** に戻る |
| 速度 | 0（止まった状態で、スポーン位置に立つ） |
| 空中ジャンプの回数 | 元に戻る（[recovery.md](./recovery.md) §3） |
| ストックが 0 のとき | リスポーンせず、試合が終わる（§7） |

- スポーン位置に、相手がいても、リスポーンできる（ファイターどうしは、体がぶつからない。#22）。

### 6.2 リスポーン後の無敵

| 項目 | 規則 |
|---|---|
| 長さ | リスポーンから **2.0 秒**（120 ステップ） |
| 効果 | **攻撃を受けない**（ダメージも、吹き飛びもない） |
| 表示 | 点滅する（無敵であることが分かる） |
| 解除 | 2.0 秒たつ、**または、自分が攻撃を出したとき**（無敵のまま攻撃し続けることを防ぐ）。移動やジャンプでは解除されない |

- 無敵の間も、相手の攻撃の当たり判定は出るが、当たらない（ヒットとして数えない）。
- 回復後の無敵（やられ中のあとの 12 ステップ。[combat-system.md](./combat-system.md) §7.2）とは別。

## 7. 勝敗

### 7.1 決着の順序

次の順で判定し、最初に当てはまったもので決まる。

| 順 | 条件 | 結果 | 理由コード |
|---|---|---|---|
| 1 | 片方だけ、ストックが 0 | ストックが残っているほうの**勝ち** | `stocks` |
| 2 | 両方、ストックが 0（同じステップで、最後のストックを失った） | **引き分け** | `draw_double_ko` |
| 3 | 制限時間が 0 になった | §7.2 で判定 | §7.2 |

### 7.2 時間切れのとき

上から順に、最初に差がついたもので決める。

| 順 | 比べるもの | 勝ち | 理由コード |
|---|---|---|---|
| 1 | 残りのストック | 多いほう | `timeup_stocks` |
| 2 | 今の蓄積ダメージ（少ないほうが有利） | 少ないほう（表示の整数ではなく、内部の小数の値で比べる） | `timeup_damage` |
| 3 | 上記が、すべて同じ | **引き分け** | `draw_timeup` |

- 引き分けのときは、延長（サドンデス）は行わない（試合の時間を、増やさないため）。
- 引き分けでも、Battle Report に、指標と設定が残り、再戦できる（引き分けは、勝敗の不明ではなく、結果の1つ）。

### 7.3 例

| 状況 | 結果 |
|---|---|
| 1P が 2P のストックを 3 つ奪った | 1P の勝ち（`stocks`） |
| 時間切れ。1P のストック 2、2P のストック 1 | 1P の勝ち（`timeup_stocks`） |
| 時間切れ。ストックが 2 対 2。1P のダメージ 40 %、2P のダメージ 65 % | 1P の勝ち（`timeup_damage`） |
| 時間切れ。ストックもダメージも同じ | 引き分け（`draw_timeup`） |
| 同じステップで、お互いの最後のストックを失う | 引き分け（`draw_double_ko`） |

## 8. 1試合の想定時間

| 区間 | 時間 | 備考 |
|---|---|---|
| READY | 3 秒 | |
| FIGHT | **最大 90 秒** | 全ストックを失えば、早く終わる |
| END | 約 3 秒 | |
| **合計（最大）** | **約 96 秒（1.6 分）** | |

- [user-flow.md](../01-experience/user-flow.md) §7 の配分は、第1戦（S07）が 2 分、Battle Report（S08）が 1 分。**1試合は、最大でも約 96 秒で、S07 の 2 分に収まる**（残り約 24 秒は、画面の切り替えと、対戦準備からの移行）。
- 3 ストックを、制限時間の 90 秒で奪い切れるか: 標準どうしでは、1回の撃墜に、ヒットが 7〜11 回、約 11〜17 秒（[combat-system.md](./combat-system.md) §11）。ヒットが続かない時間（近づく、距離を取る）を加えても、**多くの試合は、時間切れの前に、決着する見込み**。決着しない試合は、§7.2 で決める。
- 最悪の組み合わせ（`attackPower` 2 × `defense` 8）は、1回の撃墜に約 26〜36 秒かかり、3 ストックは奪い切れないことが多い。**時間切れの判定（ストック → ダメージ）で、必ず決着する**。引き分けは、まれ。
- 追加の再戦（予備。[user-flow.md](../01-experience/user-flow.md) §7）でも、1試合の長さは、同じ。

## 9. 記録（Battle Report 用）

試合中のイベントを、時刻（ステップ）とともに記録する（#37）。

| イベント | 記録する内容 |
|---|---|
| `hit` | 攻撃した側、受けた側、`damageDealt`、ヒット後の蓄積ダメージ、吹き飛ぶ速さ |
| `ko` | 撃墜された側、撃墜の原因（§5.2）、撃墜されたときの蓄積ダメージ、撃墜の前に、場外で復帰を試みていたか（[recovery.md](./recovery.md) §5） |
| `respawn` | リスポーンした側 |
| `recovery_success` / `recovery_failure` | 復帰の成功・失敗（[recovery.md](./recovery.md) §5） |
| `match_end` | 結果（勝者、理由コード）、残りのストック、最後の蓄積ダメージ、経過時間 |

- 候補の指標（与ダメージ、被ダメージ、撃墜数、被撃墜数、耐えた最大ダメージ、復帰成功・失敗。[system-overview.md](../00-overview/system-overview.md) §6.3）は、この記録から集計できる。採用する指標は #16。
- 「耐えた最大ダメージ」は、撃墜されるまでに蓄積した、最大の値。

## 10. データモデル

```ts
type MatchRules = {
  stocks: number // 3
  timeLimitSec: number // 90
  readySec: number // 3
  endSec: number // 3
  respawnDelaySec: number // 1.5
  respawnInvincibleSec: number // 2.0
  blastMargin: { left: number; right: number; bottom: number; top: number } // セル
}

type MatchPhase = 'ready' | 'fight' | 'end'

type FighterMatchState = {
  stocks: number
  damage: number // 蓄積ダメージ（%）
  status: 'alive' | 'ko' | 'respawning'
  respawnAtStep: number | null
  invincibleUntilStep: number | null
}

type MatchOutcome = {
  winner: 'p1' | 'p2' | null // null は引き分け
  reason: 'stocks' | 'timeup_stocks' | 'timeup_damage' | 'draw_double_ko' | 'draw_timeup'
}
```

- 数値は、設定ファイルにまとめる（調整のために、コードを変えない）。
- 試合の進行は、描画から独立した純粋な関数にして、ユニットテストできるようにする（#24）。
- 試合は、**決定的**（同じ入力から同じ結果）。乱数を使わない。

## 11. 例外・制約

| 場面 | 扱い |
|---|---|
| FIGHT 中に、親機の一斉リセット | 試合を中断し、S01 へ戻る。結果を残さない |
| ブラウザの更新（再開） | 対戦の途中状態は復元しない。S06 から再開する（[user-flow.md](../01-experience/user-flow.md) §8） |
| 時間切れと撃墜が、同じステップ | 撃墜を先に処理し、そのあと、§7.1 の順で判定する |
| リスポーンの待ち中に、時間切れ | §7.2 の通り（ストックは、すでに減っている） |
| リスポーン位置が、場外 | 起こらない（スポーン位置は、ステージの足場の上。#13 の検証） |

## 12. Acceptance Criteria

- [ ] ストック数・制限時間・時間切れ時の勝敗判定が決まっている（§5.1、§4、§7）
- [ ] 場外判定とリスポーン（無敵時間を含む）が定義されている（§5.2、§6）
- [ ] 1試合の想定時間が、体験フローの時間配分に収まることが示されている（§8）
- [ ] 引き分け（同時撃墜、時間切れの同点）の扱いが定義されている（§7）
- [ ] 試合中に記録するイベントが定義されている（§9）
- [ ] 試合が決定的で、ユニットテストできる形で書かれている（§10）
