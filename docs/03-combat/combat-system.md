# 戦闘システム（combat-system.md）

- 文書ID: CMB-SYSTEM
- バージョン: 0.1
- 状態: 草案（数値は暫定。バランス調整は #25）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（§6.1、REQ-CMB-01、REQ-FTR-01、REQ-EXP-02）
- 関連: [damage.md](./damage.md)、[knockback.md](./knockback.md)、[stat-system.md](../02-fighter/stat-system.md)、[animation.md](../02-fighter/animation.md)、`battle-rules.md`（#12）

## 1. 概要

1対1の対戦で、全員に共通の**基本攻撃**の仕組み（発生・持続・硬直、判定範囲）、攻撃が当たったときの処理の順序、ヒットストップとやられ中の扱い、数値の一覧、極端な能力値でも試合が成立する根拠を定義する。ダメージの式は [damage.md](./damage.md)、吹き飛ばしの式は [knockback.md](./knockback.md)。

## 2. 目的

- 勝敗の流れ「ダメージ蓄積 → 吹き飛び量の増加 → 場外 → 撃墜」（REQ-CMB-01）を、数値と手順にする。
- 全員が同じ攻撃方式を持ち、**差は能力値だけ**で生じる（REQ-FTR-01）。
- 能力値を変えると、結果が変わることが観察できる（REQ-EXP-02）。

## 4. 単位と時間

| 項目 | 規則 |
|---|---|
| 長さ | **セル**（ステージのグリッドの1マス = 1）。[stat-system.md](../02-fighter/stat-system.md) §6.1 と同じ |
| 時間 | 秒、およびステップ（固定の更新。**60 Hz**。1ステップ ≈ 16.7 ms） |
| 速さ | セル/秒 |
| ダメージ | **%**（蓄積する。表示は整数に切り捨て） |
| 重力 | 37.5 セル/秒²（[stat-system.md](../02-fighter/stat-system.md) §6.1） |

- 戦闘の計算は、すべて**ステップ単位**で、決定的に行う。乱数を使わない。

## 5. 共通の基礎

### 5.1 体（やられ判定、hurtbox）

| 項目 | 値 |
|---|---|
| 幅 | 0.50 セル |
| 高さ | 0.80 セル |
| 位置 | 足元の中心を基準にした長方形 |

- 全員同じ。能力値・外観・アニメーションで変えない（REQ-FTR-05、[animation.md](../02-fighter/animation.md) §9）。
- 見た目の大きさとのずれは ±15% 以内（[character-design.md](../02-fighter/character-design.md) §7.3）。見た目の高さは、約 0.8 セル。

### 5.2 操作

| 操作 | 内容 |
|---|---|
| 左右移動 | 能力値 `speed` に応じた速さ |
| ジャンプ | 能力値 `jumpPower` に応じた高さ |
| 攻撃 | 基本攻撃（§6）。地上でも空中でも同じ |

- ガード・回避の操作は設けない（[system-overview.md](../00-overview/system-overview.md) §6.1）。

## 6. 基本攻撃

### 6.1 フレームデータ（全員共通）

| 区間 | ステップ | 時間 | 内容 |
|---|---|---|---|
| 発生（startup） | 6 | 100 ms | 攻撃の準備。当たり判定は、まだ出ない |
| 持続（active） | 4 | 67 ms | **当たり判定が出ている** |
| 硬直（recovery） | 14 | 233 ms | 攻撃後の隙。攻撃も、次の攻撃もできない |
| **合計** | **24** | **400 ms** | |

- **攻撃のフレームの最小値:** 発生 **2 ステップ以上**、持続 **1 ステップ以上**、硬直 **2 ステップ以上**。攻撃のアニメーション（[animation.md](../02-fighter/animation.md) §5.5）の時刻が、常に厳密に増えるための制約。調整（#25）で、フレームを変えるときも守る。
- 攻撃は、1回ごとに、最後まで出し切る。**途中でキャンセルできない**（やられた場合を除く）。
- 硬直が終わると、次の攻撃ができる。連続攻撃の最短間隔は、24ステップ（0.4秒）。
- [animation.md](../02-fighter/animation.md) §5.5 の Attack クリップは、この区間に合わせて再生する。構えは「発生の終わり − 2ステップ」、打撃は「発生の終わり + 1ステップ」。

### 6.2 当たり判定（hitbox）

| 項目 | 値 |
|---|---|
| 形 | 長方形 |
| 幅（前方への長さ） | 0.60 セル。体の前の端から前へ |
| 高さ | 0.40 セル。足元から 0.30〜0.70 セルの高さ（胸のあたり） |
| 出る時間 | 持続の4ステップの間 |
| 向き | 攻撃を始めたときの向き。持続中は、向きを変えても、変わらない |

- 体の前の端から 0.60 セル先まで。体の幅（0.50）と合わせた、攻撃の届く範囲は、体の中心から約 0.85 セル前方。
- 相手の hurtbox（§5.1）と、**長方形どうしが重なる**とヒット。

### 6.3 ヒットの規則

- **1回の攻撃で、同じ相手には1回だけ**当たる（持続の4ステップで、何度も当たらない）。
- 当たり判定が出た最初のステップで、重なっていれば、そのステップでヒット。
- 相打ち（同じステップで、お互いに当たる）は、**両方にヒット**する。どちらかを優先しない。
- 自分には当たらない。1対1のため、味方・第三者もいない。

### 6.4 攻撃中の動き

| 状態 | 横の移動速度 |
|---|---|
| 地上で攻撃中（発生・持続・硬直） | 通常の **0.4 倍** |
| 空中で攻撃中 | 通常のまま |

- 空中の攻撃は、落下や上昇を止めない。
- 攻撃中に、地面から離れる、または着地するのは、自然に起こる。見た目の対応は [animation.md](../02-fighter/animation.md) §6。

## 7. ヒットしたときの処理の順序

1ステップの中で、ヒットしたとき、次の順に処理する。

1. **ダメージを与える**（[damage.md](./damage.md)）。相手の蓄積ダメージが増える。
2. **吹き飛ばしの速度を決める**（[knockback.md](./knockback.md)）。ダメージを足した後の値を使う。
3. 相手を、**やられ中**にして、吹き飛ばす。攻撃中だった場合、その攻撃は打ち切る。
4. **ヒットストップ**を始める（§7.1）。
5. 相手の蓄積ダメージを、画面に反映する。

### 7.1 ヒットストップ

- ヒットしたとき、**攻撃した側と、受けた側の両方**を、**3ステップ（50 ms）止める**。打撃の手応えを出すため（暫定）。
- 止まっている間は、2人とも、位置・速度・アニメーションが進まない。攻撃の発生・持続・硬直の数え方も、止まる。
- ヒットストップは、吹き飛ばしの速度を決めた後に始まる。終わると、相手が吹き飛び始める。

### 7.2 やられ中と、無敵

| 状態 | 規則 |
|---|---|
| やられ中（hitstun） | 操作できない。吹き飛ばされている。**追加の攻撃を受けない**（連続ヒットを防ぐ） |
| やられ中の長さ | [knockback.md](./knockback.md) §5 |
| 回復後の無敵 | やられ中が終わったあと、**12ステップ（200 ms）**は、攻撃を受けない（暫定）。体勢を立て直す時間 |

- これにより、複雑なコンボは起こらない（[system-overview.md](../00-overview/system-overview.md) §7.1）。同じ相手に、続けて何度も当てて、動けないままにすることがない。
- 攻撃を受けた側が、やられ中に、攻撃や移動の入力をしても、効かない。

## 8. 能力値との対応

| 能力値 | 戦闘での役割 | 式 |
|---|---|---|
| `attackPower` | 与えるダメージの量 | [damage.md](./damage.md) §3 |
| `defense` | 吹き飛ばされる量 | [knockback.md](./knockback.md) §4 |
| `jumpPower` | ジャンプの高さ（復帰・回避に影響） | [stat-system.md](../02-fighter/stat-system.md) §6 |
| `speed` | 横の移動速度（接近・距離を取ることに影響） | 同上 |

- **攻撃の発生・持続・硬直・判定範囲は、能力値で変わらない**（共通）。`attackPower` は、ダメージの量だけを変える。

## 10. 実装の方針

- 戦闘の処理（ヒット判定、ダメージ、吹き飛ばしの速度、やられ中、ヒットストップ）は、**描画から独立した純粋な関数**にして、ユニットテストできるようにする（#23）。
- 1ステップの処理は、長方形の重なり判定と、数式の計算だけ。計算量は、2人分で、60 FPS に影響しない（NFR-03）。
- 同じ入力と同じ初期状態から、同じ結果になる（決定的）。

## 11. 試合が成立する根拠（極端な能力値）

「ダメージ蓄積 → 吹き飛び量の増加 → 場外」が、能力値の極端な組み合わせでも、現実的な回数で起こることを、数値で確かめた。前提と結果は次のとおり。

**前提**

- ダメージ、吹き飛ばしの式は [damage.md](./damage.md)、[knockback.md](./knockback.md)。
- 撃墜に必要な吹き飛ばしの速さは、ステージの端からの距離で決まる。ステージの寸法（#13）が未確定なので、仮の距離 **L**（水平に飛んで、場外に出るまでの距離）で見積もる。
  - **L = 8 セル**（ステージの端の近くで受けた場合）: 必要な速さ 約 17.5 セル/秒
  - **L = 14 セル**（ステージの中央寄りで受けた場合）: 必要な速さ 約 23.1 セル/秒
- 吹き飛ばしの水平の距離 = `v² × sin(80°) ÷ 重力`（角度 40°、平らな地面から）。
- 攻撃は、すべて当たったとして、撃墜までに必要なヒットの回数を数えた。

**撃墜までに必要なヒット数（攻撃側 × 防御側の能力値）**

| 攻撃側 `attackPower` | 防御側 `defense` | L = 8 | L = 14 |
|---|---|---|---|
| 5（標準） | 5（標準） | 6 回 | 9 回 |
| **8（最大）** | **2（最小）** | **3 回** | **5 回** |
| 8 | 5 | 5 回 | 7 回 |
| 5 | 2 | 4 回 | 6 回 |
| 2 | 5 | 8 回 | 12 回 |
| 5 | 8 | 10 回 | 14 回 |
| **2（最小）** | **8（最大）** | **14 回** | **20 回** |
| 8 | 8 | 8 回 | 11 回 |
| 2 | 2 | 5 回 | 8 回 |

**読み取り**

- **最も撃墜しやすい組み合わせ**（8 vs 2）でも、**3〜5回**のヒットが必要。1〜2回で撃墜されることはない。逆転や、反撃の余地がある。
- **最も撃墜しにくい組み合わせ**（2 vs 8）でも、**14〜20回**のヒットで撃墜できる。標準どうし（6〜9回）の約 **2.2〜2.3 倍**にとどまり、**試合が終わらなくなる（撃墜できない）ことはない**。
- 1回のヒットを、平均して 1.5 秒に1回当てられるとすると、最悪の組み合わせでも、1回の撃墜に、約 21〜30 秒。標準どうしは、約 9〜14 秒。
- 試合の長さの上限は、#12 で、制限時間と、時間切れの勝敗（蓄積ダメージの少ないほうが勝ち、など）を決めて、撃墜が起きなくても、必ず終わるようにする。
- ステージの寸法（#13）が決まったら、L の値を置き換えて、この表を更新する。

## 12. 例外・制約

| 場面 | 扱い |
|---|---|
| 相打ち | 両方にヒット（§6.3） |
| ヒットストップ中に、別のヒット | やられ中・無敵のため、起こらない（§7.2） |
| 蓄積ダメージが 999 % を超える | 999 % で止める |
| ステージの壁や足場に、吹き飛ばされた体が当たる | [knockback.md](./knockback.md) §6 |
| 場外に出る | 撃墜。判定は #12（`battle-rules.md`） |

## 13. Acceptance Criteria

- [ ] 基本攻撃の発生・持続・硬直・判定範囲が定義されている（§6）
- [ ] attackPower → ダメージ、defense → 吹き飛ばし補正の式と係数が、各文書にある（[damage.md](./damage.md)、[knockback.md](./knockback.md)）
- [ ] 能力値の極端な組み合わせ（2/8 など）でも、試合が成立する根拠が示されている（§11）
- [ ] 全員が同じ攻撃方式で、能力値によって攻撃のフレームが変わらないことが明記されている（§8）
- [ ] 処理の順序と、ヒットストップ・やられ中・無敵が定義されている（§7）
- [ ] 計算が決定的で、ユニットテストできる形で書かれている（§10）
