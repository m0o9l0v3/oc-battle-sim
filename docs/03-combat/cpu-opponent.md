# 簡易CPUの対戦相手（cpu-opponent.md）

- 文書ID: CMB-CPU
- バージョン: 0.1
- 状態: 草案（強さの数値は、シミュレーションで決めた暫定値。実機で遊んで調整する）
- 上位文書: [system-overview.md](../00-overview/system-overview.md)（REQ-CPU-01、REQ-NET-01、§7.1）
- 関連: [battle-rules.md](./battle-rules.md)、[recovery.md](./recovery.md)、[combat-system.md](./combat-system.md)、[frontend.md](../08-architecture/frontend.md) §5・§7.4、[mobile-ui.md](../06-ui/mobile-ui.md) §4.2、[take-home-share.md](../05-multiplayer/take-home-share.md) §9.2
- 実装: `src/cpu/`（#72）

## 1. 概要

持ち帰りのあと、**スマホ単体**と**家庭のPC**で、1人で遊ぶときの対戦相手（簡易CPU）の振る舞いを定義する。CPU は、近づく・攻撃する・回避する（離れる、ジャンプでかわす）・距離を取る・場外から戻る、の基本的な動きだけをする。高度なCPU AI（相手の癖を学ぶ、コンボを狙う など）は対象外（system-overview.md §7.1）。

## 2. 目的

- 1人でも「対戦になる」相手を用意する。持ち帰った自分のファイターの能力値の違いを、家庭でも試せるようにする（REQ-EXP-02 の延長）。
- CPU は、プレイヤーと**同じ入力・同じ物理・同じ能力値の規則**で動く。CPU だけの特別な能力を持たせない（勝ち負けの理由を、能力値と操作に求められるように）。
- 強さを数値で調整でき、テストで動きを確かめられる（入力の出力が決定的）。

## 3. Requirements

| ID | 要求 | 本書での具体化 |
|---|---|---|
| REQ-CPU-01 | 基本的な移動・攻撃・回避・復帰をする簡易CPU。同じ入力・物理・能力値の規則、特別な能力なし | §3.1〜§3.3、§4、§5 |
| REQ-NET-01 | 持ち帰り後、スマホ単体で遊べる | §9（スマホの対戦画面の相手） |
| REQ-FTR-01 | 能力値の配分（4項目・合計20） | §3.3（CPU の能力値） |

### 3.1 同じ入力で動く

- CPU は、入力ソース（`InputSource`。[frontend.md](../08-architecture/frontend.md) §5）の1つ（`CpuSource`）。ステップごとに1回、**プレイヤーと同じ形の入力**（`PlayerInput`: 左・右・ジャンプを押した瞬間・攻撃を押した瞬間）を返すだけ。
- 先行入力、やられ中の入力の破棄、向き、左右同時押しの打ち消しは、キーボード・仮想パッドと同じく、対戦の側（`battle`）が行う。CPU の入力も、同じ規則で処理される。
- CPU は、試合の状態（`MatchState`）を書き換える手段を持たない。

### 3.2 見てよい情報

CPU が判断に使うのは、**プレイヤーが画面から知り得ること**だけ。

| 見てよい（`CpuView`） | 見ない |
|---|---|
| 両者の位置・速さ・地面にいるか・空中ジャンプの残り・向き・蓄積ダメージ | 相手の入力（いま押しているボタン）・先行入力 |
| 攻撃中か（始めてからの時間・向き。構えの見た目から分かる） | やられ中の残りステップ、無敵の残りステップなどの内部のタイマー |
| やられ中か・無敵か（点滅）・撃墜中か | 相手の次の行動 |
| ステージの形（足場）、ルール（攻撃の届く距離・攻撃の時間）、自分の能力値から決まる移動速度・ジャンプの高さ | 乱数の内部状態（相手側の） |

- **相手の情報は、反応時間（§6）の分だけ前のもの**を使う。自分の情報は、そのときのもの。

### 3.3 CPU の能力値

| 場面 | CPU の能力値 | 変えられるか |
|---|---|---|
| PC（「CPUと あそぶ」） | 標準（5 / 5 / 5 / 5） | **変えられる**。2P と同じく、能力値だけ（合計 20。[user-flow.md](../01-experience/user-flow.md) §5.6 の 2P の扱いと同じ） |
| スマホ | 標準（5 / 5 / 5 / 5） | 変えない（スマホでは、設定の作り直しをしない。[mobile-ui.md](../06-ui/mobile-ui.md) §4.1） |

- CPU の外観は、2P の標準の外観。名前は「CPU」。

## 4. 行動

### 4.1 判断の順序

CPU は、ステップごとに、次の順で、最初に当てはまった行動を取る。

| 順 | 行動（`CpuAction`） | 当てはまるとき | すること |
|---|---|---|---|
| 0 | 何もしない（`idle`） | READY・END、自分がやられ中・撃墜中 | 何も押さない |
| 1 | **戻る**（`recover`） | 空中にいて、真下に足場がない（このまま落ちると場外） | §5.2 |
| 2 | （攻撃を出し切る）（`attack`） | 自分が攻撃中 | 何も押さない（その場で出し切る） |
| 3 | **回避**（`evade`） | §4.3 の条件に当てはまり、抽選に当たった | 離れる、またはジャンプでかわす |
| 4 | 続けている動き（`evade`・`retreat`・`wander`） | 前のステップから続く動きがある | 決めた向きに動き続ける。進む先に足場がなくなったら、やめる |
| 5 | **攻撃**（`attack`） | 判断の間隔（`thinkSteps`）ごとに、攻撃が届く距離に相手がいて、抽選に当たった | 相手の方へ向いて、攻撃を押す |
| 6 | 位置の取り直し（`wander`） | 同じ場所（0.3 セル以内）に 1 秒以上いて、攻撃も届かない | ランダムな向き（落ちない側）へ 0.5〜0.8 秒動く。半分の確率で、最初にジャンプ |
| 7 | 待つ（`wait`） | 相手が撃墜中 | 中央の広い足場の中央へ戻って待つ |
| 7 | 待つ（`wait`） | 相手が場外にいる | 自分の足場の、相手に近い端（端から 0.7 セル内側）で待つ。**追って落ちない** |
| 7 | **高い足場へ上がる**（`climb`） | 相手が、0.9 セル以上高い足場に立っている | §5.3 |
| 7 | **近づく**（`approach`） | 上のどれでもない | 相手の方へ動く。攻撃が届く距離の 7 割まで近づいたら止まる |

### 4.2 攻撃

| 項目 | 規則 |
|---|---|
| 届く距離 | 横: 体の幅 + 攻撃の幅 − 0.1 = **1.0 セル**（中心どうしの距離）。縦: 相手の足元が、自分の足元から 0.6 セル上〜0.4 セル下（攻撃の当たり判定の高さから） |
| 攻撃する | 判断の間隔ごとに、届く距離なら `attackChance` の確率で攻撃 |
| ミス | 届く距離の少し外（1.0〜1.7 セル）なら、`missChance` の確率で、攻撃してしまう（空振り） |
| 攻撃しない相手 | やられ中・無敵（点滅）・撃墜中の相手（当たらない） |
| 固まらない | 届く距離に相手がいるのに、1 秒間攻撃していなければ、抽選なしで攻撃する |
| 距離を取る（`retreat`） | 自分の攻撃が終わったら、`retreatChance` の確率で、相手から離れる向きへ 0.25〜0.5 秒動く（後ろに足場があるときだけ） |

### 4.3 回避（「防御」の代わり）

ガード（防御）の操作は設けない（所有者の決定）。**回避行動で代える**。

| 項目 | 規則 |
|---|---|
| 抽選のきっかけ | (a) 相手が攻撃を始めた（相手の攻撃ごとに 1 回）、(b) 相手がこちらを向いて、間合いの外から近づいてきた（近づくごとに 1 回。確率は半分） |
| 抽選 | (a) は `evadeChance`、(b) は `evadeChance` × 0.5 の確率で、回避する |
| 発動する場所 | 相手との横の距離が 1.8 セル未満、高さの差が攻撃の届く範囲。相手が場外・撃墜中のときは発動しない |
| 回避のしかた | 地上で、40 % の確率で**ジャンプでかわす**（離れる向きへ動きながら跳ぶ）。それ以外は、**離れる**（0.3 秒、相手から離れる向きへ）。後ろに足場がないとき（ステージの端）は、離れずに、相手の方へ跳ぶ（跳び越える）。空中では、回避しない |
| 反応の遅れ | 相手の攻撃の始まりも、反応時間（§6）の分だけ遅れて見える。そのため、攻撃の出が速い相手には、間に合わないことがある（人と同じ） |

## 5. ステージの形への対応

### 5.1 足場の読み取り

- 試合の最初に、ステージの形から、列ごとのブロックの位置と、足場（立てるセルのまとまり。[stage-format.md](../04-stage/stage-format.md)）の一覧を作る。試合の間は、表を引くだけ（§7.2）。
- **安全な位置:** その x の列で、足元より下にブロックがある（落ちても、ステージの上に着く）。下に何もない列は、落ちたら場外。

### 5.2 戻る（復帰）

空中で、真下に足場がないとき（場外に出た、穴の上にいる、吹き飛ばされた）。

| 手順 | 内容 |
|---|---|
| 戻る先 | 足場のうち、残りの空中ジャンプで届く高さにあり、勢い（0.3 秒後の位置）から横に近いもの。届かない足場は、最後の候補 |
| 足場より低いとき | 足場の外側の縁（端から 0.45 セル外）の下へ回り込み、上向きの勢いが弱まったら（上向きの速さ 2 セル/秒未満）、空中ジャンプ。縁の外で上面の近くまで上がったら、内側へ |
| 足場より高いとき | 足場の内側（端から 0.8 セル内）へ向かう。落ち始めて（下向き 1 セル/秒より速い）、まだ横に届かず、上面との差が 1 セル未満なら、空中ジャンプで高さを保つ |
| 頭の上 | 頭の上 0.6 セル以内にブロックがあるとき（足場の下）は、跳ばない（空中ジャンプをむだにしない） |
| ジャンプの押し方 | ジャンプは、押した瞬間の入力。押してから **8 ステップ**は押し直さない（押しっぱなしで、空中ジャンプを一度に使い切らない） |

- 復帰の補助（ふち掴み、無敵）はない。プレイヤーと同じく、空中ジャンプ（2回）と空中の横の動きだけで戻る（[recovery.md](./recovery.md) §3.3）。遠くへ吹き飛ばされたときは、戻れずに撃墜される。

### 5.3 落ちない・上がる

| 場面 | 規則 |
|---|---|
| 地上で、進む先（0.6 セル先）に足場がない | 向こう側（1〜3 セル先）に、跳べる高さの足場があれば、**跳び越える**（穴のあるステージ）。なければ、**止まる** |
| 低い足場へ降りる | 下に足場がある列なら、そのまま歩いて降りる |
| 高い足場に相手がいる（`climb`） | その足場の外側の縁の下へ行き、跳ぶ。上向きの勢いが弱まったら空中ジャンプ。**回り込む縁の下に足場がない（その縁から跳ぶと、落ちてしまう）ときは、その縁を使わない**。使える縁がなければ、上がらずに近づく |
| 回避・距離を取る・位置の取り直しの途中 | 進む先に足場がなくなったら、やめる |

## 6. 強さ

### 6.1 設定値

強さは、次の数値だけで変える（行動の種類・物理・能力値は変えない）。`src/cpu/level.ts` にまとめる。

| 設定値 | 意味 | よわい | **ふつう（標準）** | つよい | 調整の範囲 |
|---|---|---|---|---|---|
| `reactionSteps` | 相手の動きに反応するまでの遅れ（ステップ。1/60 秒） | 14（約 0.23 秒） | **8（約 0.13 秒）** | 4（約 0.07 秒） | 4〜30 |
| `thinkSteps` | 判断（攻撃・ミスの抽選）の間隔（ステップ） | 8 | **4** | 3 | 2〜15 |
| `attackChance` | 届くときに攻撃する確率（判断ごと） | 0.35 | **0.6** | 0.8 | 0〜1 |
| `evadeChance` | 回避する確率（§4.3） | 0.15 | **0.35** | 0.6 | 0〜1 |
| `retreatChance` | 攻撃のあと、距離を取る確率 | 0.2 | **0.3** | 0.4 | 0〜1 |
| `missChance` | 届かない距離で攻撃してしまう確率（判断ごと） | 0.3 | **0.15** | 0.05 | 0〜0.5 |

- 範囲の外の値は、範囲に収める（`clampCpuLevel`）。反応時間の下限 4 ステップ（約 0.07 秒）は、人が反応できる速さの目安より速くしないため。
- 標準は「ふつう」。スマホは「ふつう」で固定、PC は「よわい」「ふつう」「つよい」から選ぶ（§9）。

### 6.2 強さの確認（シミュレーション）

[balance.md](./balance.md) の基準のボット（反応の遅れがなく、近ければ 4 ステップごとに 70 % で攻撃する）を相手に、標準の能力値どうし、プリセット 4 つ × シード 8 つ × 左右 1 通り（計 32 戦）で確かめた（2026-10-10）。

| CPU の強さ | CPU の勝ち | 負け | 引き分け |
|---|---|---|---|
| よわい | 2 | 30 | 0 |
| ふつう | 4 | 27 | 1 |
| つよい | 14 | 16 | 2 |

- 「つよい」は、基準のボットと、ほぼ互角。「ふつう」は、正確に攻撃し続ける相手には負けるが、動かない相手は約 15〜32 秒で 3 回撃墜する（§7.1）。
- 強さに最も効くのは、反応時間（`reactionSteps`）。「つよい」に近い設定で、反応時間だけを 2 にすると、基準のボットに 27 勝 4 敗だった（強くしすぎないため、下限を 4 にした）。
- 子どもが遊んで、強すぎる・弱すぎるときは、§6.1 の数値だけを変える。

## 7. 1試合が成立すること

### 7.1 確認する内容（テスト）

全プリセット（ひょうじゅん・ひろば・たかいとう・しま）× 全強さで、次を確かめる（`src/cpu/cpu.test.ts`）。

| 確認 | 基準 |
|---|---|
| 最後まで進む | CPU どうしで、試合が END まで進む（勝敗が決まる） |
| 対戦になる | CPU どうしで、ヒットが 20 回より多い |
| 落ち続けない | **自分から落ちた回数が 0**（撃墜の前の 5 秒間に、ヒットを受けていない撃墜を「自分から落ちた」とする） |
| 固まらない | 操作できる（やられ中・攻撃中でない）のに何も押さない時間が、**2 秒未満**（相手の撃墜中に待つ 1.5 秒を含む） |
| 同じ動きを繰り返し続けない | 4 種類以上の行動を取り、1 つの行動の割合が 6 割未満 |
| 攻撃が当たる | 動かない相手を、時間内に 3 回撃墜して勝つ |
| 能力値が低くても | 能力値 8/8/2/2（ジャンプ・速さが低い）の CPU が、自分から落ちない |
| 戻れる | 穴のあるステージで、右の場外へ吹き飛ばされた状態から、足場に戻る |

### 7.2 60 FPS を妨げない

- 1 ステップの判断は、表を引く・数回の比較だけ（足場の数に比例。最大でも数十）。テストで、1 回の判断の平均が 0.05 ms 未満であることを確かめる（1 ステップの予算 16.7 ms に対して、十分に小さい）。
- ステージの形の読み取り（§5.1）は、試合の最初に 1 回だけ。

## 8. テストできる形（決定性）

- 乱数は、**シードつきの疑似乱数**（`src/battle/random.ts` の `rng`。mulberry32）だけを使う。`Math.random` は使わない（frontend.md §4.3 D6。ESLint で検査）。
- **同じシード・同じ盤面の列から、同じ入力の列**を返す。テストで、同じシードの2回の試合の、入力・イベント・最終状態が一致することを確かめる。
- 画面では、試合ごとに新しいシードを決めて渡す（毎回、ちがう動きにする）。シードを記録すれば、その試合を再現できる。
- 判断は `createCpu(setup, level, seed)` が返す関数（ビューを渡すと、入力と行動の名前を返す）。テストでは、ビューを作って直接渡せる。試合全体は `simulateCpuMatch`（`src/cpu/sim.ts`）で進める。

## 9. 画面

| 端末 | 入口 | 1P | 2P（CPU） | ルール |
|---|---|---|---|---|
| PC | 持ち帰りの入口の「**CPUと あそぶ**」 | キーボード（1P の配置） | 強さを選ぶ（標準は「ふつう」）。能力値は標準で始まり、変えられる | 会場の対戦と同じ（`DEFAULT_MATCH_RULES`） |
| スマホ | 持ち帰りの入口の「スマホで あそぶ」 | 仮想コントローラー | 「ふつう」・標準の能力値 | 同上 |

- PC の画面（`CpuPlayScreen`）: 準備（キー・強さ・CPU の能力値）→ 対戦（残り時間・ストック・ダメージ）→ 結果（「きみの かち！」などと理由）→「もういちど」「つよさを かえる」。「もどる」で、持ち帰りの入口へ。
- スマホの画面（[mobile-ui.md](../06-ui/mobile-ui.md) §4.2、§5.3）: 右上に、残り時間と、両者のダメージ・ストック。勝敗が決まったら、結果と「もういちど」を出す。
- CPU との対戦は、Battle Report・比較の対象にしない（記録を保存しない。家庭では、Battle Report の履歴を引き継がない。take-home-share.md §12）。
- 会場の体験（S06〜S10）の 2P は、従来どおり人（保護者・ヘルパー）。会場で CPU を相手にする画面は、本書では作らない。

## 10. 例外・制約

| 場面 | 扱い |
|---|---|
| CPU がやられ中 | 何も押さない（押しても、対戦の側が捨てる） |
| 相手が無敵（リスポーン後） | 攻撃しない。近づいて待つ |
| 相手が場外 | 追って落ちない。端で待つ（§4.1） |
| 遠くへ吹き飛ばされた | 戻ろうとするが、戻れなければ撃墜される（特別な補助はない） |
| 足場の下に相手がいる・上に相手がいる | 縁へ回り込んで上がる。上がれない形のときは、近づける所まで近づく。動けなくなったら、位置を取り直す（§4.1 の 6） |
| ステージの形が変わる | 試合の間は変わらない（対戦の開始時に固定。character-config.md §5） |
| 盤面が渡されない | 何も押さない（`CpuSource` は `observation` がないとき、入力なし） |

## 11. Acceptance Criteria

- [x] CPU が行う行動が定義されている（接近、攻撃、距離を取る、ジャンプでの回避、場外に出そうなときの復帰）（§4、§5.2）
- [x] 「防御」はガード操作を追加せず、回避行動で代える。回避の発動条件が定義されている（§4.3、§5）
- [x] CPU は、プレイヤーと同じ入力・同じ物理・能力値のルールで動き、特別な能力を持たない（§3）
- [x] 強さが設定値（反応時間、攻撃の頻度、ミスの確率など）で調整できる。標準の強さと、調整の範囲が決まっている（§6）
- [x] CPU の能力値は標準設定（5/5/5/5）で始まり、変更できるかが決まっている（§3.3）
